# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-05-25
**Phases:** 1-2
**Total Plans:** 3

## Overview

Initial MVP of Vendeo V3. User can register store identity, input campaign product/offer details with BRL price and image upload, and see a success state — the complete first half of the campaign generation flow.

## Phases

### Phase 1: Foundation & Store Identity

**Goal**: Capture minimum store identity required to generate the first campaign
**Depends on**: Nothing (first phase)
**Plans**: N/A (built before GSD workflow)

**Details:**
- Store CRUD API (POST, GET, PATCH) with Supabase persistence
- Store identity form with name, segment, brand color, city, state
- Design system (MASTER.md, CAMPAIGN_VISUAL_SYSTEM.md)
- Tailwind CSS + dark theme configuration
- Browser-based session persistence via localStorage

### Phase 2: Campaign Input

**Goal**: User can input all campaign details (product, offer, image) for generation
**Depends on**: Phase 1
**Plans**: 3 plans

Plans:
- [x] 02-01: Foundation & Store Route — BADGE_OPTIONS, BRL formatters, /store route, StoreIdentityBlock
- [x] 02-02: Campaign Form System — useCampaignForm hook, image upload, form composition
- [x] 02-03: Campaign Page Integration & Verification — CampaignPageClient with all states, route split

**Details:**
- BADGE_OPTIONS constant (5 values) with derived BadgeOption type
- formatCurrencyBRL / parseCurrencyBRL helpers with Intl.NumberFormat
- /store route with StoreIdentityForm + "Voltar" navigation to /
- StoreIdentityBlock read-only card with resolveStoreIdentity fallback
- useCampaignForm hook with 6-field state, 5 validators, BRL mask, image lifecycle
- CampaignImageUpload dropzone with format/size validation and object URL preview
- CampaignInputForm composing all fields with success banner
- CampaignPageClient with 4 states: loading, blocked, error, ready

## Milestone Summary

**Key Decisions:**
- Route split: `/` for campaign, `/store` for store identity (Rationale: Clean separation, native App Router)
- BRL currency via Intl.NumberFormat with cents-internal state (Rationale: Precise comparison, reusable)
- Image upload local-only via object URL (Rationale: Zero-dependency, deferred storage)
- Component decomposition: hook + form + preview pattern from Phase 1 (Rationale: Single responsibility, testable)
- Badge as predefined dropdown in constants (Rationale: Consistent with VALID_SEGMENTS pattern)

**Issues Resolved:**
- Price mask bug: Fixed BRL input to use raw-digit extraction instead of parseCurrencyBRL
- .next cache stale issue: Required clean rebuild after /store route creation

**Issues Deferred:**
- Logo upload UI — intentionally deferred per Phase 1 spec
- Image upload to Supabase Storage — deferred to later phase
- Campaign data persistence — deferred (local success state only)
- AI generation, rendering, export — deferred to Phases 3-5

**Technical Debt Incurred:**
- parseCurrencyBRL exported but unused (replaced by raw-digit extraction in the hook)
- STATE.md needs updating after milestone close

# Milestone v1.2: Contas e Propriedade

**Status:** ✅ SHIPPED 2026-07-08
**Phases:** 7–11
**Total Plans:** 22 plans across 5 phases

## Overview

Estabelecer a camada fundacional de contas e propriedade para que as milestones seguintes construam sobre ela. Autenticação (Supabase Auth, email+senha), sessão SSR via `@supabase/ssr`, vínculo user→store (1:1, `stores.user_id`), RLS em 5 tabelas, ownership validado em todas as operações, rotas protegidas (middleware + server component), páginas de signup/login/onboarding, e verificação formal do perímetro multi-tenant.

## Milestone Summary

**Key Achievements:**
- Sistema completo de autenticação: signup → confirmação → login → sessão SSR → logout
- Vínculo user→store com ownership verificado em todas as operações
- RLS em 5 tabelas + Storage com isolamento multi-tenant
- 20+ route handlers protegidos com CSRF + Auth + Ownership
- 3 Server Actions convertidas para serviços internos, 4 com guards
- 465 testes automatizados, 51 files, zero erros de tipo/lint/build
- Catálogo D8 com 21 cenários de segurança validados manualmente

**Key Decisions (D1–D11):**
- D1: `stores.user_id` como fonte canônica de ownership
- D2: Supabase Auth, email+senha, sessão SSR via `@supabase/ssr`
- D3: Loja não criada automaticamente no signup — onboarding separado
- D4: `claims.sub` como fonte autoritativa, não localStorage
- D5: Cliente sessão + RLS como padrão; service role excepcional
- D6: RLS com políticas FOR SELECT específicas (sem `FOR ALL`)
- D7: Middleware (auth) + server component (store) + handler (ownership) + serviço (contexto)
- D8: Cenários binários de segurança como critério de aceite
- D9: CSRF same-origin para mutações em Route Handlers
- D10: Fluxo mínimo de recuperação de senha incluso
- D11: 3 Server Actions viram serviços internos, 4 ganham guards

**Technical Debt:**
- Bucket `store-logos`: 0 objetos, nenhum fluxo ativo — pendente de remoção (migration cleanup)
- E2E automatizado com cookies reais não implementado (verificação manual substituiu)
- Testes RLS contra banco real substituídos por verificação SQL + policies check

**Issues Resolved:**
- `csrf.ts` try-catch bug (try envolvia função inteira, engolia ForbiddenError)
- 11 test files precisaram de ajustes de mock para compatibilidade com auth guards
- `apiHandler` wrapper criado para garantir precedência CSRF > Auth > Ownership
- Build fix: re-exports de `"use server"` precisavam ser async
- Middleware CSRF precedence: mutações API sem sessão passam para route handler (CSRF > Auth)

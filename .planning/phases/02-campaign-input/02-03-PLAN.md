    1. Read `localStorage.getItem("store_id")`

       - `.then(data => { if (data) { setStore(data); setPageState("ready"); } })`
       - `.catch(() => { setErrorMessage("Não foi possível carregar os dados da loja. Tente novamente."); setPageState("error"); })`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client→localStorage | Reads store_id to identify which store to fetch |
| Client→GET /api/store/{id} | Fetch store data from API (read-only, existing Phase 1 endpoint) |
| Client (DOM) | Campaign form renders user-provided text + image via object URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Denial of Service | GET /api/store/{id} fetch loop | mitigate | Error state includes a manual "Tentar Novamente" button — no automatic retry with exponential backoff (no risk of request storm). User-initiated only. |
| T-02-09 | Spoofing | localStorage store_id tampering | accept | store_id is a UUID generated by Phase 1 API. If tampered, the GET returns 404 → clears localStorage → shows blocking state. No security impact — user only loses their own data view. |
| T-02-10 | Information Disclosure | Store data via fetch response | accept | Store data displayed was already provided by the user. No cross-user data access (no auth, single local store). |
| T-02-11 | Elevation of Privilege | Campaign form submit | accept | Submit is purely local state — no API call, no database write. No privilege boundary crossed. |
| T-02-12 | Tampering | Image file via object URL | accept | Object URL is isolated to the browser tab. File is not uploaded to any server in this phase. URL.revokeObjectURL called on cleanup. |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new package installs in this plan. Existing dependencies only. |
</threat_model>

# Phase 3.2: Real AI Provider Integration — Context

**Gathered:** 2026-05-26
**Status:** Ready for planning
**Source:** OpenSpec change `phase-3-2-ai-provider-integration` (proposal, design, specs, tasks)

<domain>
## Phase Boundary

Implement the real OpenAI provider for the campaign intelligence infrastructure, preserving the existing multi-format architecture but focusing refinement, testing, and acceptance criteria on the Product + Offer format.

Product + Offer is the golden path for validation, prompt refinement, manual testing, and acceptance criteria in Phase 3.2. Other campaign formats may remain structurally supported but are not considered refined or production-validated in this phase.

</domain>

<decisions>
## Implementation Decisions

### Architecture & Provider
- Implement `OpenAIProvider` class at `src/lib/campaign-intelligence/providers/openai.ts` implementing `AIProvider` interface
- Use dynamic `import("openai")` inside the provider (not static module-level import) to avoid loading the SDK on every cold start when MockProvider is active
- The factory and service layer stay provider-agnostic

### Structured Outputs
- Use OpenAI Structured Outputs (`response_format: { type: "json_schema" }`) via `zodResponseFormat` helper from `openai/helpers/zod`
- Fallback to `json_object` mode only for explicit `response_format`/model capability errors — do NOT fallback on auth, rate limit, network, quota, or validation errors
- Zod validation runs after all responses as a second layer of defense

### Provider Selection
- Development/test (`NODE_ENV !== "production"`):
  - `OPENAI_API_KEY` set → `OpenAIProvider`
  - `OPENAI_API_KEY` missing → `MockProvider` (silent fallback)
- Production (`NODE_ENV === "production"`):
  - `OPENAI_API_KEY` set → `OpenAIProvider`
  - `OPENAI_API_KEY` missing → throw explicit configuration error, fail fast

### Environment Variables
- `OPENAI_API_KEY` — required for real provider
- `OPENAI_MODEL` — configurable model name, defaults to `"gpt-4o-mini"` if unset

### Prompt
- System prompt written in Brazilian Portuguese
- Targets Product + Offer format exclusively
- Must reference store name in commercial_copy or generation context (not necessarily in title)
- Output must match CampaignSpecSchema structure

### visualIntent
- Deferred to Phase 4 — current `visual_parameters` block already covers layout, composition, hierarchy, palette, badge style, and background style

### Non-Goals
- No API route or CampaignIntelligenceService changes unless required by provider integration
- No visual rendering (Phase 4)
- No support for other campaign formats (combos, services, reels, etc.)
- No streaming support
- No rate limiting or token budgeting
- No Anthropic provider — only OpenAI in this phase
</decisions>

<specifics>
## Specific Implementation Details

### OpenAIProvider class
- File: `src/lib/campaign-intelligence/providers/openai.ts`
- Implements AIProvider interface
- Constructor accepts optional model parameter (defaults to `OPENAI_MODEL` env var or `"gpt-4o-mini"`)
- Dynamic `import("openai")` inside provider, not at module level
- Uses `zodResponseFormat` from `openai/helpers/zod` to derive JSON Schema from CampaignSpecSchema
- Falls back to `json_object` mode only for schema capability errors
- Returns `ProviderRawResponse` with `raw` being JSON string of generated campaign spec

### createDefaultProvider() update
- File: `src/lib/campaign-intelligence/service.ts`
- Check `OPENAI_API_KEY` environment variable
- If set → dynamically import and return `OpenAIProvider`
- If not set AND `NODE_ENV === "production"` → throw configuration error
- If not set AND dev/test → return `MockProvider`

### Environment setup
- Install `openai` npm package as runtime dependency
- Create `.env.example` with `OPENAI_API_KEY` and `OPENAI_MODEL`

### Spec updates
- `openspec/specs/ai-campaign-intelligence/spec.md`: Update provider selection scenarios with dev/prod-aware fallback; add CampaignIntelligenceService integration requirement
- `openspec/specs/openai-provider/spec.md`: New spec (already created in the change)
</specifics>

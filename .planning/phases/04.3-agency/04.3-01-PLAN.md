    2. Private `cache: Map<string, string>` for in-memory caching
    3. `load(name: string, variables?: Record<string, string>): string` method:
       a. Check cache first; if found, use cached content

       e. If any {{variable}} has no matching value in variables, leave it as-is (no error)

    4. `clearCache(): void` method for testing/reloading

    Use dynamic `import("fs")` or `fs.readFileSync` with proper path resolution. Since this runs server-side only in Next.js App Router, `fs` is available at runtime.

    ```typescript
      productName: z.string().min(1),

      storeTone: z.string().optional(),
      brandColor: z.string().regex(/^#[0-9a-fA-F]{6}$/),
      originalPriceCents: z.number().int().positive(),
      discountedPriceCents: z.number().int().positive(),
      badgeText: z.string().optional(),
      hook: z.string().optional(),
      cta: z.string().optional(),
      description: z.string().optional(),
      objective: z.string().optional(),
      campaignDetails: z.string().optional(),
      additionalDetails: z.string().optional(),
      targetChannel: z.string().optional(),
      format: z.string().optional(),
      validity: z.string().optional(),
      availabilityNotes: z.string().optional(),
      sensitiveConstraints: z.string().optional(),
      storeLogoUrl: z.string().optional(),
      productImageDataUrl: z.string().min(1, "Imagem do produto é obrigatória"),
      inputValidationOverride: z.object({
        productImageCheck: z.literal("user_confirmed_continue").optional()
      }).optional(),
    })
    ```

    2. `GenerateImageSuccessResponseSchema`:
    ```typescript
    z.object({
      imageDataUrl: z.string(),
      inputCorrections: z.object({
        productName: z.object({
          from: z.string(),
          to: z.string(),
          reason: z.string(),
        }),
      }).optional(),
    })
    ```

    3. `GenerateImageNeedsUserActionResponseSchema`:
    ```typescript
    z.object({
      status: z.literal("needs_user_action"),
      reason: z.union([z.literal("product_image_conflict"), z.literal("product_image_low_confidence")]),
      message: z.string(),
      suggestedProductName: z.string().optional(),
    })
    ```

    **TypeScript Types (not Zod):**

    4. `InputValidationResult`:
    ```typescript
    export type InputValidationResult =
      | { classification: "match"; confidence: number }
      | { classification: "auto-fix"; confidence: number; correctedProductName: string; reason: string }
      | { classification: "conflict"; confidence: number; suggestedProductName?: string; reason: string }
      | { classification: "low-confidence"; confidence: number; reason: string }
    ```

    5. `ImageReviewResult`:
    ```typescript
    export interface ImageReviewResult {
      passed: boolean;
      issues: ReviewIssue[];
    }

    export interface ReviewIssue {
      type: string;
      severity: "critical" | "minor";
      description: string;
    }
    ```

    **Error Response Types:**
    ```typescript
    export type ImageGenerationErrorCode = "payload_too_large" | "provider_failure" | "invalid_output" | "review_failed";

    export interface ImageGenerationError {
      code: ImageGenerationErrorCode;
      message: string;
      details?: string;
    }
    ```

    Export all schemas with `Type` suffix for inferred types (e.g., `GenerateImageRequest` inferred from `GenerateImageRequestSchema`).

    Note: `GenerateImageRequestSchema` includes `productImageDataUrl` as required because Phase 4.3 product+offer flow requires it. The Zod schema enforces this at the endpoint validation layer.

# Phase 4.3 Plan 2: Provider & Services — ImageProvider Interface, OpenAIImageProvider, InputValidationService, ImageReviewService

**ImageProvider interface and input/output types, OpenAIImageProvider with Responses API primary path and Image API fallback, InputValidationService for pre-generation conflict detection, and ImageReviewService for post-generation quality review — all loading prompts via PromptLoader**

## Accomplishments

- `ImageProvider` abstraction defined in `providers/types.ts` with `ImageProviderInput` (prompt, optional product image data, size, quality), `ImageProviderOutput` (imageBase64, mimeType, model), and `ImageProvider` interface (readonly name + generateImage method)
- `OpenAIImageProvider` implemented using OpenAI Responses API with `image_generation` tool as the primary path; falls back to Image API edits when Responses API is unavailable for the specific use case; product image passed as `input_image` content part
- `InputValidationService` loads `campaign-input-visual-check.md` via PromptLoader, sends prompt + product image to a vision-capable model, and parses the structured JSON response into the `InputValidationResult` discriminated union (match, auto-fix, conflict, low-confidence); supports `user_confirmed_continue` override
- `ImageReviewService` loads `campaign-image-reviewer.md` via PromptLoader with campaign data interpolation, sends generated image + review prompt to a vision-capable model with `response_format: json_object`, and parses into `ImageReviewResult` with `passed` boolean and `issues[]` array
- `npm run typecheck` and `npm run lint` pass with zero errors

## Files Created

- `src/lib/image-generation/providers/types.ts` — `ImageProviderInput` (prompt, productImageDataUrl, size, quality), `ImageProviderOutput` (imageBase64, mimeType, model), `ImageProvider` interface (readonly name + generateImage method); pure abstraction contract with no implementation
- `src/lib/image-generation/providers/openai.ts` — `OpenAIImageProvider` class implementing `ImageProvider`; uses `openai.responses.create()` with `image_generation` tool as primary path; falls back to `openai.images.edit()` for product-image edits when Responses API unavailable; dynamic import of `openai` package; `isResponsesApiError()` detection and single-attempt fallback; config defaults from `config.ts` (model, size, quality)
- `src/lib/image-generation/services/input-validation-service.ts` — `InputValidationService` class; `validate(typedProductName, productImageDataUrl, override?)` method; loads `campaign-input-visual-check.md` via PromptLoader with `typedProductName` interpolation; calls vision model with text + image content; `parseResult()` handles markdown code fence cleanup and discriminated union parsing; override check for `user_confirmed_continue`
- `src/lib/image-generation/services/image-review-service.ts` — `ImageReviewService` class + `ImageReviewInput` interface; `review(generatedImageDataUrl, input)` method; loads `campaign-image-reviewer.md` via PromptLoader with campaign data (productName, storeName, prices); calls vision model with `response_format: json_object`; `parseResult()` handles code fence cleanup and maps to `ImageReviewResult` with `passed` boolean + typed `issues[]`

## Decisions Made

- Separate `ImageProvider` interface (not extending `AIProvider` from campaign-intelligence) — image generation and campaign text generation have fundamentally different input/output shapes, provider capabilities, and fallback strategies
- `OpenAIImageProvider` uses Responses API `image_generation` tool as primary path (conversational/editable image flows) with Image API edit fallback (when product-image editing is needed but Responses API unavailable for the model)
- Both validation services use the same `VISION_REVIEW_MODEL` from config (`gpt-4o` by default) — a single vision-capable text model handles both pre-generation input validation and post-generation quality review
- `InputValidationService` override requires exact string literal `"user_confirmed_continue"` — prevents accidental bypass via falsy/null values (threat T-4.3-02-01 mitigation)
- Single-attempt fallback in `OpenAIImageProvider` (threat T-4.3-02-04 DoS mitigation) — no infinite retry loops

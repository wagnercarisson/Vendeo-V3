# Phase 4.3 Plan 3: Orchestrator & Endpoint Summary

**ImageGenerationService with correction state machine (INITIAL → REVIEW → CORRECT → REGENERATE → COMPLETE/ERROR) and POST /api/campaign/generate-image endpoint with controlled error mappings**

## Performance

- **Completed:** 2026-05-28T18:00:00Z

## Accomplishments

- **ImageGenerationService orchestrator** — full correction state machine that coordinates PromptLoader, ImageProvider, InputValidationService, and ImageReviewService into one lifecycle
- **Correction lifecycle** — max 3 image-generation calls (1 initial + 1 correction + 1 regeneration) with controlled error when exhausted
- **Pre-generation validation** — InputValidationService runs first; blocks on conflict/low-confidence, auto-fixes name mismatches with metadata
- **Correction/regeneration prompts** — correction preserves composition while fixing specific issues; regeneration starts fresh with all known issues
- **POST /api/campaign/generate-image endpoint** — returns appropriate HTTP status codes for all scenarios (200 success, 400 invalid/missing, 409 conflict, 413 oversized payload, 502 provider failure, 500 review failed)
- **Existing endpoint verified** — POST /api/campaign/generate confirmed untouched via git diff

- **Controlled error surface** — all error responses are user-facing messages in PT-BR; raw provider errors only exposed in development mode via NODE_ENV check
- **Existing endpoint preserved** — no changes to the original campaign intelligence endpoint; the new `/api/campaign/generate-image` is an independent route

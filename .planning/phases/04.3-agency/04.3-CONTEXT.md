# Phase 4.3 Context: AI-Native Agency Campaign Generation

## Goal
Create an AI-native image generation pipeline that produces flat, professional 1:1 square campaign images ready for Instagram preview — closing the gap between "functional CSS renderer" and "agency-grade publishable art."

## Key Decisions
1. **ImageProvider interface** — new parallel interface (not extending AIProvider) in `src/lib/image-generation/providers/types.ts`; `OpenAIImageProvider` uses GPT Image via Responses API
2. **Product image transport** — base64 data URL in request body, no Supabase storage
3. **Two-stage validation** — `InputValidationService` (pre-generation) + `ImageReviewService` (post-generation), both use configured vision-capable text model
4. **Correction state machine** — INITIAL → REVIEW → CORRECT → REGENERATE → COMPLETE/ERROR; max 3 image-generation calls per request
5. **Prompt files** — root `prompts/` directory, plain Markdown with `{{variable}}` interpolation, loaded via `PromptLoader` with in-memory cache
6. **Preview adaptation** — `generatedImageDataUrl` in PreviewPayload; CSS renderer as legacy fallback toggle
7. **No persistence** — images exist only in request/session/client state

## Constraints
- No database changes, migrations, or persistent storage
- No new external AI provider unless OpenAI spike fails
- No separate demo-only flow — reuse existing store and campaign forms
- Max 3 image-generation calls per request (1 initial + 1 correction + 1 regeneration)
- Product image required for Phase 4.3 product+offer flow (return 400 if absent)
- Target format: 1:1 square, provider native size (1024×1024 or 2048×2048)
- Response language: Brazilian Portuguese (PT-BR)

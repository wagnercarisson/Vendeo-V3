# Phase 04.6.1: Text Only State & Visual Direction Inference — Context

**Gathered:** 2026-06-12
**Status:** Ready for planning
**Source:** OpenSpec design artifacts, codebase mapping

## Domain

### Phase Boundary

Deliver complete text_only state coverage: when a lojista has no logo and no visual signature, infer a full brand identity (palette, style, tone, personality, guidelines) from store registration data alone. Three entry points are equivalent: clicking "Continuar sem logo", choosing colors and saving without logo, or saving without logo or colors.

### Problem

Currently Step 2 (Logo e Cores) has three user paths:
1. Upload logo → `logo_analysis` brand profile
2. Generate AI visual signature → approval → `without_logo` brand profile
3. "Continuar sem logo" → only `logo_status = explicit_none`, NO brand profile

Path 3 leaves the store with no identity — `safe_color_tokens`, `visual_style`, `visual_tone` and intelligence fields are empty, resulting in generic segment-fallback campaigns.

### Solution

Create a new `text_only` source in `store_brand_profiles` with a dedicated inference pipeline (prompt + service + route) that generates a complete brand identity from store data alone. Introduce `identity_state` on `stores` as the primary identity state source, with dual-population to `logo_status` for backward compatibility.

## Implementation Decisions

### D1: Dedicated inference route
- `POST /api/store/[id]/brand-profile/infer` as standalone route
- Separate from PATCH store — inference is a heavy operation (5-15s OpenAI call) needing dedicated timeout (30s), concurrency lock, error handling
- Follows existing `generate-without-logo/route.ts` pattern

### D2: Dual-population strategy
- When entering text_only, set both `identity_state = 'text_only'` AND `logo_status = 'explicit_none'` in the same handler
- UI migrates to read `identity_state` as primary source; existing code continues reading `logo_status`
- Mitigation: both written together in the same controlled operation

### D3: New dedicated prompt
- `prompts/store-brand-inference.md` — specific for inference without images
- Not reusing `store-brand-profiler.md` (designed for visual signature image analysis)
- Input variables: store name, segment, subsegment, tone_of_voice, positioning, short_description, slogan, city, state
- Optional: userPrimaryColor, userAccentColor as preference signals (not rules)

### D4: Service/Route responsibility split
- `BrandTextOnlyInferenceService`: loads prompt → fills template → calls OpenAI → validates output → returns `TextOnlyInferenceResult`
- Route handler: orchestrates persistence, store state updates, error handling
- Service follows pattern of `BrandDirectorService` and `BrandProfilerWithoutLogoService`

### D5: User colors as signal, not constraint
- `userChosenColors` passed in prompt as preference signal
- AI MAY adopt, adjust, or discard them
- Final palette recorded in `safe_color_tokens` regardless
- `brand_colors_chosen` preserves user's input for UI feedback

### D6: Color resolution priority in campaigns
- `safe_color_tokens.primary > inferred_primary_color > store.brand_color > SEGMENT_COLOR_FALLBACK[segment]`
- `brand_colors_chosen` excluded from rendering hierarchy (UI/input only)
- New block for `source = 'text_only'` in `resolveStoreIdentity`

### D7: Non-blocking error handling
- AI failure does NOT block the user's flow
- Profile persisted with `status = 'failed'`, `source = 'text_only'`
- `identity_state` and `logo_status` still set normally
- Campaign generation uses `store.brand_color > SEGMENT_COLOR_FALLBACK[segment]`
- UI shows warning + retry button

### D8: Concurrency lock
- In-memory `Map<string, boolean>` per store_id
- Returns 429 on duplicate inference request
- Same pattern as `generate-without-logo/route.ts`

### D9: Inference timeout
- 30 seconds (half of visual signature's 60s)
- Configurable via environment variable

### D10: previous_identity_snapshot
- Column created in migration but NOT populated in this phase
- Future subphase will populate when state transitions are implemented

### D11: PATCH color changes
- `PATCH /api/store/[id]/brand-profile` updates `brand_colors_chosen` + `manual_color_override`
- Does NOT change `safe_color_tokens`
- Does NOT sync `stores.brand_color` (sync only happens from `safe_color_tokens.primary` in inference service)

## Specific Ideas

### Migration SQL
```sql
-- stores
ALTER TABLE public.stores ADD COLUMN IF NOT EXISTS identity_state TEXT NOT NULL DEFAULT 'text_only';
ALTER TABLE public.stores ADD COLUMN IF NOT EXISTS text_only_origin TEXT NOT NULL DEFAULT 'implicit';
ALTER TABLE public.stores ADD COLUMN IF NOT EXISTS manual_color_override BOOLEAN NOT NULL DEFAULT false;
ALTER TABLE public.stores ADD COLUMN IF NOT EXISTS previous_identity_snapshot JSONB;
ALTER TABLE public.stores ADD CONSTRAINT chk_stores_identity_state CHECK (identity_state IN ('text_only', 'logo', 'visual_signature'));
ALTER TABLE public.stores ADD CONSTRAINT chk_stores_text_only_origin CHECK (text_only_origin IN ('implicit', 'explicit'));

-- store_brand_profiles
ALTER TABLE public.store_brand_profiles ADD COLUMN IF NOT EXISTS manual_color_override JSONB NOT NULL DEFAULT '{"enabled": false}';
ALTER TABLE public.store_brand_profiles DROP CONSTRAINT IF EXISTS chk_store_brand_profiles_source;
ALTER TABLE public.store_brand_profiles ADD CONSTRAINT chk_store_brand_profiles_source CHECK (source IN ('logo_analysis', 'without_logo', 'text_only'));
```

### Color resolution code block
```typescript
// NOVO BLOCO 4.6.1: source = 'text_only'
if (profile?.source === 'text_only' && profile?.status === 'synced') {
  if (profile.safe_color_tokens?.primary && /^#[0-9A-Fa-f]{6}$/.test(profile.safe_color_tokens.primary)) {
    brandColor = profile.safe_color_tokens.primary;
  } else if (profile.inferred_primary_color && /^#[0-9A-Fa-f]{6}$/.test(profile.inferred_primary_color)) {
    brandColor = profile.inferred_primary_color;
  }
}
```

### Text-only UI states
- `identity_state = 'text_only'` + synced profile → chip "✓ Direção visual definida pelo Vendeo", color pickers pre-filled, expanded preview
- `identity_state = 'text_only'` + failed profile → warning message, "Gerar direção visual agora" button
- `identity_state = null` → current behavior unchanged

    Refactor the POST handler in `src/app/api/store/[id]/logo/route.ts` following the new flow:

    **Phase 1 — Pre-analysis (unchanged except input_snapshot capture):**
    1. Upload file, validate, generate variants, store to Supabase storage
    2. Archive previous active assets — set status='archived' on all current active assets for this store
    3. Capture `input_snapshot` from current store data: { segment, subsegment, tone_of_voice, name, brand_color, accent_color }
       - Use the accent_color resolution chain: `brand_colors_chosen[1]` → `safe_color_tokens.accent` → `inferred_accent_color` → null
       - Get brand_colors_chosen from the current synced profile if it exists

    **Phase 2 — BrandDirector (MOVED: before profile mutation):**
    4. Execute brandDirector.analyze({ logoBuffer, logoMimeType, storeData }) — carregar buffer e MIME do asset recém-uploaded, montar storeData (storeName, segment, subsegment, tone_of_voice, etc.) da store atual
       - If BrandDirector throws/returns error → go to Failure Path

    **Phase 3 — Post-analysis:**
    
    **Success path (BrandDirector succeeded):**
    5. Implement compensated transition block:
       a. Read the current synced profile ID (if exists)
       b. If previous synced profile exists: update its status to 'outdated'
       c. Insert new brand profile with:
          - status: 'synced'
          - source: 'logo_analysis'
          - active_logo_asset_id: the original uploaded asset ID
           - visual_style, safe_color_tokens, inferred_accent_color, inferred_primary_color: from BrandDirector result
           - brand_colors_chosen: [] (não populado por análise — D09: isolamento de cores manuais)
           - metadata: { input_snapshot: captured_input_snapshot }
       d. If insert fails: restore previous synced profile status back to 'synced' (compensation)
       e. Update stores row: identity_state = 'logo', logo_status = IDENTITY_TO_LOGO_STATUS['logo']
    
    **Failure path (BrandDirector failed/errored):**
    5. Do NOT mutate the previous synced profile (it stays synced as fallback)
    6. Set identity_state = 'logo' (upload succeeded even if analysis didn't)
    7. Set logo_status = 'uploaded' (sync)
    8. Insert new brand profile with:
       - status: 'failed'
       - source: 'logo_analysis'
       - active_logo_asset_id: the original uploaded asset ID
       - metadata: { 
           error: error message/details,
           attempt_snapshot: captured_input_snapshot  // snapshot for audit, NOT input_snapshot
         }
       - Do NOT include input_snapshot in failed profiles (reserved for synced profiles only)

    Remove any existing code that sets `brand_colors_chosen: analysis.logo_colors_detected`. The `brand_colors_chosen` field must NOT receive detected colors from logo analysis.

  <action>
    Create `src/app/api/store/[id]/logo/restore/route.ts`:

    1. Export a `POST` async handler that receives `{ params }: { params: { id: string } }`
    2. Parse body as `LogoRestoreRequest`: `{ asset_id: string }`. Return 400 if missing/invalid.
    3. Validate the asset:
       - Query `store_brand_assets` where `id = asset_id` AND `store_id = params.id` AND `status = 'archived'`
       - If not found, return 404 with `{ error: "Archived asset not found for this store" }`
    4. Archive current active assets (prevent unique index violation on restore):
       - Update `store_brand_assets` SET `status = 'archived'` WHERE `store_id = params.id` AND `status = 'active'`
    5. Load the associated profile:
       - Query `store_brand_profiles` where `active_logo_asset_id = asset_id`
       - Extract `metadata.input_snapshot` if it exists
    6. Compute drift:
       - Fetch current store data (6 fields)
       - If input_snapshot exists: compare each of the 6 fields using normalizeSnapshotValue logic
       - If any field differs → drift = true
       - If no input_snapshot → drift = true (missing snapshot = drift)

    **No-drift path (profile may be synced or outdated):**
    7a. If the chosen profile is already status='synced':
        - Do NOT mark any profile outdated
        - Just re-activate assets: UPDATE store_brand_assets SET status='active' WHERE id = asset_id
    7b. If the chosen profile is status='outdated' (shouldn't happen normally, but handle):
        - Mark current synced profile (if any) as 'outdated'
        - Reactivate chosen profile to 'synced'
        - Re-activate assets: UPDATE store_brand_assets SET status='active' WHERE id IN (asset_id, any variants associated)
    8. Update stores: `identity_state = 'logo'`, `logo_status = IDENTITY_TO_LOGO_STATUS['logo']`
    9. Return 200: `{ success: true, profile_id: profile.id, drift_detected: false, realigned: false }`

    **Drift path:**
    7a. Execute BrandDirectorService.analyze(params.id, restoredLogoUrl) where restoredLogoUrl is the storage URL of the restored asset
    7b. On BrandDirector success:
        - Mark current synced profile as 'outdated'
        - Insert NEW profile as 'synced' with:
          - active_logo_asset_id: the restored asset_id (not the new asset — provenance preserved)
           - source: 'logo_analysis'
           - input_snapshot: current store data (6 fields)
           - safe_color_tokens, visual_style: from BrandDirector result
           - brand_colors_chosen: [] (não populado por análise — D09)
        - Do NOT re-activate the historical profile (it stays with its current status)
    7c. On BrandDirector failure:
        - Current synced profile stays synced (fallback preserved)
        - Insert new profile as 'failed' with:
          - active_logo_asset_id: restored asset_id
           - source: 'logo_analysis'
          - metadata.attempt_snapshot: current store data (6 fields)
          - metadata.error: failure details
        - Assets are STILL reactivated (logo is visible even if direction analysis failed)
     7d. Re-activate assets: UPDATE store_brand_assets SET status='active' WHERE id = asset_id OR parent_asset_id = asset_id (inclui variantes)
    8. Update stores: `identity_state = 'logo'`, `logo_status = IDENTITY_TO_LOGO_STATUS['logo']`
    9. Return 200:
       - Drift + BrandDirector success: `{ success: true, profile_id: newProfile.id, drift_detected: true, realigned: true }`
       - Drift + BrandDirector failure: `{ success: true, profile_id: failedProfile.id, drift_detected: true, realigned: false }`
  </action>

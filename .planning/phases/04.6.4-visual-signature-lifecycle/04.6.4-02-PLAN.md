<action>
Evolve GET handler to serve as history/list endpoint:

1. Structure response as `{ signatures: [{ id, status, assetUrl, type, attempt, created_at, approved_at, art_direction, restore_eligibility }] }`
2. `approved_at`: use `updated_at` of currently active signature (null for archived/never-active)
3. `art_direction`: extract from `metadata.artDirectorOutput`, or null if unavailable
4. `restore_eligibility`: compute server-side:
   - If no `metadata.input_snapshot` → `{ can_restore: false, reason: 'missing_metadata', requires_regeneration: true, drift_fields: [] }`
   - If drift detected (compare input_snapshot vs current store using content_used) → `{ can_restore: false, reason: 'critical_drift', requires_regeneration: true, drift_fields: [...] }`
   - If no drift → `{ can_restore: true, reason: 'ok', requires_regeneration: false, drift_fields: [] }`
</action>
<acceptance_criteria>
- GET returns `approved_at` as timestamp for active signature, null for archived
- GET returns `art_direction` object from metadata, null for pre-feature signatures
- GET returns `restore_eligibility` computed with drift detection rules
- Drift comparison uses same rules as restore: name/segment always critical, city/state/slogan conditional on content_used
- Missing metadata results in `reason: 'missing_metadata'`
- `npm run typecheck` passes with no errors
</acceptance_criteria>

<action>
Update the approve route handler to:

1. **Extract intendedPalette:**
   - After loading the signature (and before calling profiler), read `signature.metadata.artDirectorOutput?.intended_palette`
   - Re-apply `normalizeIntendedPalette()` on the extracted value (idempotent safety)
   - If `intended_palette` is missing or normalization returns null → `intendedPalette = null`

2. **Load previousBrandColors:**
   - Query the last synced brand profile for this store (most recent `synced` profile)
   - Check `manual_color_override.enabled` on that profile
   - If `true`: extract `brand_colors_chosen` → `previousBrandColors`
   - If `false` or no profile exists → `previousBrandColors = []`

3. **Pass to profiler:**
   - Add `intendedPalette` and `previousBrandColors` to the `BrandProfilerInput` passed to `brandProfiler.generate()`

4. **Handle profiler failure:**
   - Wrap profiler call in try-catch
   - If profiler returns `status = 'failed'` or throws:
     - Log the error (server-side)
     - Do NOT roll back signature approval (signature remains `active`)
     - Do NOT update stores.brand_color or stores.accent_color
     - Keep previous synced profile (if any) unchanged
     - Continue response with success (signature approved)

5. **Ensure identity_state is always set:**
   - `stores.identity_state = 'visual_signature'` is set regardless of profiler outcome
</action>

# Phase 4.6.5: VS Color Drift & Brand Profile Alignment — Context

**Gathered:** 2026-06-22
**Status:** Ready for planning
**Source:** OpenSpec — `openspec/changes/fase-4-6-5-vs-color-drift-brand-profile/`

<domain>
## Phase Boundary

Eliminar o drift entre o `intended_palette` (com papéis semânticos — primary, accent, support, background) que a IA já retorna na geração da Visual Signature e as cores efetivamente usadas nas campanhas. O `BrandProfilerWithoutLogoService` atualmente usa heurística cega (`extractColorsFromBuffer` + `pickPrimaryFromPalette`) que produz papéis trocados.

**O que esta fase entrega:**
1. **ColorProbe reutilizável**: Extrair `probeColors()` + utilitários de cor de `brand-director.ts` para módulo compartilhado `src/lib/brand-assets/color-probe.ts`
2. **IntendedPalette**: Criar tipo separado + normalizador idempotente para o JSON de retorno da IA
3. **BrandProfilerInput**: Adicionar `intendedPalette: IntendedPalette | null` e `previousBrandColors?: string[]`
4. **Presença física**: Substituir heurística por validação via ColorProbe com 3 zonas de ∆E (≤18 confirmado, 18-25 ambíguo, >25 ausente)
5. **Visão como árbitro**: Quando cor ambígua/ausente, visão arbitra entre `observed_colors`. HEX livre revalidado contra probe.
6. **ResolvedPalette**: `safe_color_tokens` com `secondary` derivado de `support[0] ?? primary`
7. **Profile failed**: Se visão falhar, profile `status: 'failed'` com auditoria em `metadata.color_validation`
8. **Fallbacks**: Probe indisponível → confia na intenção; intendedPalette nulo (retry/legado) → heurística
9. **Sincronização**: `stores.accent_color` sincronizado com `safe_color_tokens.accent`
10. **brand_colors_chosen**: Preservado apenas com `manual_color_override.enabled === true`

**Não escopo:**
- Integração da direção visual ao gerador de campanhas (fase futura)
- Revisão do prompt simplificado de retry ou provider diversity
- Backfill de profiles existentes
- Alteração no fluxo de logo (`curateLogoColors`, `applyGuardrail`)
- Migrações de banco (todas as colunas já existem)

</domain>

<decisions>
## Implementation Decisions

### D1: ColorProbe como módulo compartilhado

Extrair `probeColors()`, `ColorProbeResult`, `ColorCluster`, utilitários (`deltaE`, `hexToLab`, `rgbToHex`, `isNeutral`) e `findClosestProbeCluster` de `brand-director.ts` para `src/lib/brand-assets/color-probe.ts`.

- `edgeRatio: number` adicionado ao `ColorCluster` (expõe dado já calculado sem alterar lógica de classificação)
- `brand-director.ts` passa a importar de `color-probe.ts`
- `curateLogoColors` e `applyGuardrail` não são alterados

### D2: Presença física com 3 zonas de ∆E

| Faixa | Presença | Ação |
|---|---|---|
| ∆E ≤ 18 | `confirmed` | Aceita, mantém intended |
| 18 < ∆E ≤ 25 | `ambiguous` | Visão arbitra |
| ∆E > 25 | `not_confirmed` | Visão arbitra |

Thresholds CIE76 (implementação atual). Calibração com imagens VS reais antes do ship.

### D3: Visão arbitra apenas papéis contestados + observed_colors

Prompt condicional:
- **Happy path** (todas cores confirmadas): análise semântica apenas — sem extração/sugestão de cores
- **Divergência** (alguma cor ambígua/ausente): prompt de arbitragem com `observed_colors`

`observed_colors` selecionados por:
1. Cluster mais próximo de cada cor contestada
2. Melhor cluster de cada classificação relevante
3. Completar por frequência até 12 clusters
4. Deduplicar por ∆E ≤ 6 sem remover candidatos obrigatórios

**Contrato RawVisionAdjudication:**
- Todas as chaves obrigatórias (`primary`, `accent`, `background`, `support`)
- Papéis não contestados retornam `null` (visão não opinou)
- Papel contestado com `null` → `no_choice` → `vision_failed`
- `support` é `SupportCorrection[]` — cada item `{ index, color }`
- HEX livre revalidado contra probe — aceito se ∆E ≤ 18, rejeitado se > 18
- Índices inválidos filtrados; índices duplicados → `invalid_json`

### D4: Suportes corrigidos por índice

`RawVisionCorrections.support` é `SupportCorrection[]` onde cada item tem `{ index, color }`. Índices inválidos (< 0 ou >= intended.support.length) são filtrados. Após filtro, cobertura total exigida.

### D5: brand_colors_chosen preservado com prova de origem

Apenas profiles anteriores com `manual_color_override.enabled === true` preservam `brand_colors_chosen`. Perfis legados recebem `[]`.

### D6: ColorValidation como união discriminada

```typescript
// Estados com paleta resolvida
interface ColorValidationResolved {
  global_status: 'all_confirmed' | 'vision_adjudicated' | 'probe_unavailable' | 'fallback_heuristic';
  primary: ColorValidationEntry;
  accent: ColorValidationEntry;
  secondary: ColorValidationEntry;
  background: ColorValidationEntry;
  support_colors: string[];
  support_details?: ColorValidationEntry[];
  vision_adjudication?: VisionAdjudicationAudit;
}

// Estado de falha
interface ColorValidationFailed {
  global_status: 'vision_failed';
  vision_adjudication: VisionAdjudicationAudit;
}
```

Cada `ColorValidationEntry` tem: `intended | null`, `resolved`, `presence`, `delta_e | null`, `role_source`, `resolution`, `resolved_from_cluster?`, `note?`.

### D7: Matriz de fallbacks

| intendedPalette | Probe | global_status | safe_color_tokens |
|---|---|---|---|
| Válido | OK + todas ≤ 18 | `all_confirmed` | `intendedToResolved(intended, intended.support)` |
| Válido | OK + alguma > 18 | `vision_adjudicated` ou `vision_failed` | Resolvido pela visão ou `{}` |
| Válido | Vazio/exceção | `probe_unavailable` | `intendedToResolved(intended, intended.support)` |
| Nulo (retry/legado) | OK | `fallback_heuristic` | Probe-based heuristic |
| Nulo (retry/legado) | Vazio | `fallback_heuristic` | `{ primary: brandColor ?? SEGMENT_FALLBACK, ... }` |

Retry e legados nunca chamam visão para arbitragem de cores — apenas análise semântica.

### D8: Fluxo de dados end-to-end

1. Geração → `normalizeIntendedPalette()` → persiste em `metadata.artDirectorOutput.intended_palette`
2. Aprovação → lê intended_palette + previousBrandColors → passa para profiler
3. Profiler → ColorProbe + presença → visão (se divergência) → `safe_color_tokens` + `color_validation`
4. Se `vision_failed`: profile `failed`, signature permanece ativa, sem sync de stores
5. Sucesso: sync `stores.brand_color` + `stores.accent_color`

### D9: ResolvedPalette e sincronização de stores

```typescript
interface ResolvedPalette {
  primary: string;
  secondary: string;      // supportResolved[0] ?? primary
  accent: string;
  background: string;
}
```

Sincronização pós-profile:
- `stores.brand_color = safe_color_tokens.primary`
- `stores.accent_color = safe_color_tokens.accent`
- `inferred_primary_color = safe_color_tokens.primary`
- `inferred_accent_color = safe_color_tokens.accent`

### D10: intended_palette + color_usage no Art Director Output

`metadata.artDirectorOutput` ganha dois novos campos:
1. `intended_palette: IntendedPalette` — paleta estruturada com papéis semânticos. Omitido se normalização falhar (geração não bloqueada)
2. `color_usage: ColorUsage` — descrição em linguagem natural de como cada papel é usado

### D11: Prompt condicional do profiler

- **Happy path** (sem divergência): prompt `analyze_only` — análise semântica apenas, sem instruções de cor
- **Divergência**: prompt com `observed_colors`, papéis contestados com valores intended e ∆E, instrução para escolher apenas de `observed_colors`
- **Retry/legado**: prompt `analyze_only` — sem arbitragem de cores

</decisions>

**Wave 5 — Tests & Verification** *(depende de todos)*

### Fluxo de Presença (end-to-end)
1. Profiler recebe intendedPalette (ou null)
2. Se null → fallback heurístico (sem visão para cores)
3. Se válido → probeColors(buffer) → findClosestProbeCluster para cada papel
4. Classificar presença por ∆E
5. Se todas ≤ 18 → happy path (analyze_only)
6. Se alguma > 18 → divergência → observed_colors → visão com prompt condicional
7. Visão retorna RawVisionAdjudication → normalizeAdjudication → aplicar correções
8. Compor safe_color_tokens + color_validation
9. Se visão falhou → profile failed, signature ativa, sem sync

### Regras de observed_colors
- Cluster mais próximo de cada cor contestada (garante representação)
- Melhor cluster de cada classificação (dominant, dark_ink, neutral, background, structural)
- Preencher por frequência até 12
- Deduplicar ∆E ≤ 6 (sem remover mandatórios)

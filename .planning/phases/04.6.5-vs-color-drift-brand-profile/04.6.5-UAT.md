## Instruções

1. Tenha o `next dev` rodando com OpenAI key + Supabase configurados
2. Acesse o Step 2 do formulário de uma loja
3. Para inspecionar o banco: use o Supabase Studio ou `psql` na tabela `brand_profiles` (coluna `metadata` → `color_validation`)
4. Marque cada teste como `pass` / `fail` + observações

---

## Cenários

### 1. Fluxo feliz — cores confirmadas (all_confirmed)

**Setup:** Loja com VS ativa onde as cores do intended_palette têm boa correspondência com a imagem VS (∆E ≤ 18).

**Passos:**
1. Abra Step 2 de uma loja
2. Clique "Gerenciar assinatura visual" → "Criar nova assinatura" (ou gere uma VS nova)
3. Selecione uma imagem de logo/VS que contenha as cores que você escolheu no seletor de cores
4. Complete a geração → revise → aprove a VS

**Esperado:**
- `brand_profiles.metadata.color_validation.global_status` = `'all_confirmed'`
- Cada role (primary, accent, background) tem `presence: 'confirmed'` e `delta_e ≤ 18`
- `safe_color_tokens` corresponde exatamente ao intended_palette
- `stores.brand_color` = `safe_color_tokens.primary`
- `stores.accent_color` = `safe_color_tokens.accent`

**Resultado:** `___` (pass/fail)

---

### 2. Visão arbitra cor divergente (vision_adjudicated)

**Setup:** Loja onde a cor primária do intended_palette NÃO está presente na imagem VS (ex: escolha #FF0000 como primary mas a imagem VS é azul).

**Passos:**
1. No seletor de cores, escolha uma cor que NÃO existe na imagem VS (ex: vermelho puro #FF0000 para uma imagem azul)
2. Gere a VS → aprove
3. Inspecione o `color_validation` no banco

**Esperado:**
- `global_status` = `'vision_adjudicated'`
- A role `primary` tem `presence: 'not_confirmed'` (∆E > 25) ou `'ambiguous'` (18-25)
- `role_source: 'vision_adjudication'`
- `resolution: 'corrected_by_vision'`
- O prompt de divergência foi enviado para a IA com as `observed_colors`
- A visão escolheu uma cor DAS observed_colors (não a original #FF0000)
- `safe_color_tokens.primary` ≠ intended_palette.primary

**Resultado:** `___` (pass/fail)

---

### 3. Visão falha → profile failed (vision_failed)

**Setup:** Cenário onde a visão não consegue arbitrar (simular resposta JSON inválida ou sem correções).

**Passos:**
1. Crie uma VS com cores divergentes (como no cenário 2)
2. Se possível, force um erro na resposta da IA (ou apenas observe se a IA retorna algo inválido)
3. Aprove a VS

**Esperado:**
- Brand profile criado com `status = 'failed'`
- `color_validation.global_status` = `'vision_failed'`
- `safe_color_tokens = {}` (objeto vazio)
- `stores.brand_color` NÃO foi alterado (permanece com valor anterior)
- `stores.accent_color` NÃO foi alterado
- A assinatura visual continua `active` (o profile failure não rollback a aprovação)
- Profile anterior (se existia) permanece `synced` como fallback

**Resultado:** `___` (pass/fail)

---

### 4. Fallback heurístico — sem intended_palette (fallback_heuristic)

**Setup:** Simular uma geração de VS onde o Art Director não produziu intended_palette (ex: retry path, prompt mal formatado).

**Passos:**
1. Acesse uma loja que não tem VS ativa
2. No seletor de cores, deixe as cores padrão (sem personalizar)
3. Gere a VS → aprove
4. Inspecione o `color_validation` no banco

**Esperado:**
- `global_status` = `'fallback_heuristic'` (caso intendedPalette seja null)
- Cores derivadas heuristicamente da imagem VS (probe)
- `safe_color_tokens` populado com as cores heurísticas
- `stores.brand_color` e `stores.accent_color` sincronizados

**Resultado:** `___` (pass/fail)

---

### 5. brand_colors_chosen preservado com manual_color_override

**Setup:** Loja que já tem um brand profile synced com `manual_color_override.enabled = true`.

**Passos:**
1. Verifique no banco: `brand_profiles` da loja tem `manual_color_override.enabled = true` e `brand_colors_chosen` populado
2. Gere uma nova VS → aprove
3. Inspecione o NOVO brand profile

**Esperado:**
- `brand_colors_chosen` no novo profile contém os mesmos valores do profile anterior
- `inferred_primary_color` = `safe_color_tokens.primary`
- `inferred_accent_color` = `safe_color_tokens.accent`

**Resultado:** `___` (pass/fail)

---

### 6. Probe unavailable → probe_unavailable

**Setup:** Simular uma imagem VS corrompida ou que o sharp não consegue processar.

**Passos:**
1. Faça upload de uma imagem inválida como VS (ou corrompa o buffer)
2. Gere a VS → aprove
3. Inspecione o `color_validation`

**Esperado:**
- `global_status` = `'probe_unavailable'`
- `presence` = `'unchecked'` para todas as roles
- `role_source` = `'art_director'` (intended palette mantida)
- A assinatura visual ainda é aprovada com sucesso

**Resultado:** `___` (pass/fail)

---

### 7. Regressão: VS sem intended_palette + sem profile anterior → fallback completo

**Setup:** Loja NOVA (sem brandColor, sem brand profile anterior, sem intended_palette).

**Passos:**
1. Crie uma loja nova (ou use uma sem cor configurada nem VS ativa)
2. Gere a primeira VS → aprove
3. Inspecione o `color_validation`

**Esperado:**
- `global_status` = `'fallback_heuristic'`
- `primary` derivado do probe (dominant non-neutral) ou `SEGMENT_FALLBACK` se probe vazio
- `background` = `'#FFFFFF'` se probe vazio
- Profile salvo com status `'synced'`

**Resultado:** `___` (pass/fail)

---

### 8. Regressão: ciclo gerar → rejeitar → gerar nova → aprovar

**Setup:** Fluxo completo de rejeição.

**Passos:**
1. Gere uma VS → clique "Não gostei" / rejeite com feedback
2. Preencha o feedback
3. Gere nova versão
4. Aprove

**Esperado:**
- A segunda VS é independente da primeira
- O intended_palette da segunda VS é o que o Art Director gerou para a nova versão
- `color_validation` reflete a segunda VS, não a primeira
- Tudo funciona como antes (regressão zero)

**Resultado:** `___` (pass/fail)

### 9. Verificação visual: cores fazem sentido?

**Passos:**

**Esperado:**
- As cores parecem extraídas corretamente da imagem
- Nenhuma cor gritante ou fora de contexto
- A experiência visual é boa

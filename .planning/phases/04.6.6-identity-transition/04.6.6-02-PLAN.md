<action>
Update `src/app/api/store/[id]/logo/route.ts`:

**POST handler:**
1. Call `assertCanTransition(storeId, 'text_only_to_logo')` BEFORE any expensive processing (upload, BrandDirector)
2. If blocked (not text_only), return 409 with appropriate error and `current_identity_state`
3. Proceed with upload + BrandDirector (existing logic, unchanged)
4. Call orchestrator `transition(storeId, 'text_only_to_logo', { onCriticalPersistence, onCompensate })` to finalize state change
5. `onCriticalPersistence`: mark the uploaded asset as active (moved from inline logic)
6. `onCompensate`: archive the newly-activated asset if store update fails
7. Handle error return (orchestrator never declares success on failure)

**DELETE handler:**
1. Read `stores.identity_state` — reject 404 if not `'logo'`
2. Call orchestrator `transition(storeId, 'logo_to_text_only', { onCriticalPersistence, onCompensate })`
3. `onCriticalPersistence`: archive the active logo assets
4. `onCompensate`: re-activate logo if store update fails
5. The orchestrator validates `identity_state` first, THEN calls `onCriticalPersistence`
6. Only after persistence succeeds, orchestrator updates `identity_state` + `logo_status`
7. Brand profile remains synced (do NOT mark outdated)
8. Return success
</action>
<acceptance_criteria>
- `POST /api/store/{id}/logo` returns 409 when `identity_state` is `logo` or `visual_signature`
- `POST /api/store/{id}/logo` proceeds normally when `identity_state` is `text_only`
- `DELETE /api/store/{id}/logo` archives assets and transitions state to `text_only`
- Brand profile remains `synced` after removal (not marked outdated)
- `npm run typecheck` passes with no errors
</acceptance_criteria>
</task>

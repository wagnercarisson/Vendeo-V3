<action>
Update `src/app/api/store/[id]/logo/route.ts`:

**POST handler:**
1. Read `stores.identity_state` at the start of the handler (BEFORE any processing)
2. Validate via orchestrator: block if `identity_state = 'logo'` — return HTTP 409 with `{ error: "Remova o logotipo ativo antes de enviar outro.", requires_logo_removal: true, current_identity_state: "logo" }`
3. Block if `identity_state = 'visual_signature'` — return HTTP 409 with `{ error: "Remova a assinatura visual ativa antes de enviar um logotipo.", requires_identity_removal: true, current_identity_state: "visual_signature" }`
4. Permit only from `identity_state = 'text_only'`
5. After upload and BrandDirector complete (existing logic), call orchestrator `transition(storeId, 'text_only_to_logo')` to finalize state change
6. Pass `onActivate` callback that marks the uploaded asset as active (moved from inline logic)
7. Handle compensation if orchestrator fails after activation

**DELETE handler:**
1. Read `stores.identity_state` — reject 404 if not `'logo'`
2. Archive the active logo assets (existing logic)
3. Call orchestrator `transition(storeId, 'logo_to_text_only')` with `onArchive` callback
4. The orchestrator updates identity_state + logo_status
5. Brand profile remains synced (do NOT mark outdated)
6. Return success
</action>
<acceptance_criteria>
- `POST /api/store/{id}/logo` returns 409 when `identity_state` is `logo` or `visual_signature`
- `POST /api/store/{id}/logo` proceeds normally when `identity_state` is `text_only`
- `DELETE /api/store/{id}/logo` archives assets and transitions state to `text_only`
- Brand profile remains `synced` after removal (not marked outdated)
- `npm run typecheck` passes with no errors
</acceptance_criteria>
</task>

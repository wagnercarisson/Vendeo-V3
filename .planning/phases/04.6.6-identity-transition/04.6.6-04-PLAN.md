<action>
Create `src/lib/__tests__/identity-transitions.test.ts` with orchestrator unit tests:

**4 permitted transitions:**
- `text_only → logo` — succeeds when current state is text_only
- `logo → text_only` — succeeds when current state is logo
- `text_only → visual_signature` — succeeds when current state is text_only
- `visual_signature → text_only` — succeeds when current state is visual_signature

**Blocked transitions (all rejected):**
- `logo → visual_signature` — blocked
- `visual_signature → logo` — blocked
- `logo → logo` (text_only_to_logo called from logo) — blocked
- `visual_signature → visual_signature` (text_only_to_visual_signature called from VS) — blocked
- `text_only → text_only` (no such transition type) — type error

**Edge cases:**
- Transition with invalid store_id returns error
- Dual-population: after `text_only` transition, `logo_status` is `explicit_none`
- Dual-population: after `logo` transition, `logo_status` is `uploaded`
- Dual-population: after `visual_signature` transition, `logo_status` is `generated`
- Compensation called when DB update fails after persistence
- Error returned (never success) when compensation also fails
- Repeated invalid transition returns deterministic 409 without changing persisted state
</action>

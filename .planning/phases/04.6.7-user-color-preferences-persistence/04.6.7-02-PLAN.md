Update `src/app/api/store/[id]/brand-profile/route.ts` — PATCH handler:

1. **Body validation**: Change the `colors` field validation to accept `Array<string | null>` where each element is either a valid 7-character hex (`#RRGGBB`) or `null`:
   - Reject arrays with a single element (positions would be ambiguous) — HTTP 400
   - Valid arrays: `[]`, `[hex, null]`, `[null, hex]`, `[hex, hex]`
   - `#RRGGBB` placeholder SHALL be treated as `null` when received

2. **Remove manual_color_override writes**:
   - Do NOT set `manual_color_override = { enabled: true }` on the brand profile
   - Do NOT update `stores.manual_color_override = true`

3. **Reset scenario**: When `{ colors: [] }` is received, persist empty array (clears manual choice)

4. **Preserve constraints**:
   - Require an existing synced profile (return 404 if none exists)
   - Do NOT update `stores.brand_color`
   - Do NOT modify `safe_color_tokens`

5. **Persistence logic**:
   ```typescript
   // After validation
   const normalizedColors = normalizeBrandColorsChosen(colors);
   await db.from('store_brand_profiles')
      .update({ brand_colors_chosen: normalizedColors })
     .eq('store_id', storeId)
     .eq('status', 'synced');
   // Do NOT update manual_color_override on stores or store_brand_profiles
   ```
</action>

- `PATCH { colors: ["#FF0000"] }` returns 400 (single element)
- `PATCH { colors: ["#GGGGGG", null] }` returns 400 (invalid hex)

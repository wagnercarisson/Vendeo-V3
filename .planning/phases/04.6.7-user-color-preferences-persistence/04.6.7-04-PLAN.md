<action>
Manual verification scenarios — test each scenario in the browser/dev environment:

**Scenario 1: Null partial choice**
1. Open store identity form for a store with no brand profile
2. Select only primary color (`#FF6600`)
3. Save → Trigger inference
4. Verify `brand_colors_chosen = ["#FF6600", null]` in DB
5. Refresh → Verify primary picker shows `#FF6600`, accent picker is empty

**Scenario 2: Full pair choice**
1. Select both primary (`#FF6600`) and accent (`#E8A040`)
2. Save
3. Verify `brand_colors_chosen = ["#FF6600", "#E8A040"]`

**Scenario 3: Reset to suggested**
1. With an existing chosen color, click "Voltar para cores sugeridas"
2. Verify `brand_colors_chosen = []` in DB
3. Verify pickers show `safe_color_tokens`

**Scenario 4: Logo upload preserves choice**
1. With `brand_colors_chosen = ["#FF6600", null]`, upload a logo
2. After upload completes, verify new profile has `brand_colors_chosen = ["#FF6600", null]`

**Scenario 5: Logo removal does not clear choice**
1. Remove active logo
2. Verify `brand_colors_chosen` unchanged (still contains `["#FF6600", null]`)

**Scenario 6: PATCH single-element rejection**
1. Send `PATCH { colors: ["#FF0000"] }`
2. Verify HTTP 400 response

**Scenario 7: PATCH with null**
1. Send `PATCH { colors: [null, "#00FF00"] }`
2. Verify `brand_colors_chosen = [null, "#00FF00"]`

**Scenario 8: PATCH reset**
1. Send `PATCH { colors: [] }`
2. Verify `brand_colors_chosen = []`

**Scenario 9: manual_color_override not written**
1. Perform any PATCH
2. Verify `store_brand_profiles.manual_color_override` was NOT modified
3. Verify `stores.manual_color_override` was NOT modified

**Scenario 10: Placeholder #RRGGBB not persisted**
1. Open form, type `#RRGGBB` in color field
2. Verify value is treated as null, not persisted as choice

**Scenario 11: Re-inference preserves choice**
1. Trigger text-only inference for a store with existing `brand_colors_chosen = ["#FF6600", null]`
2. Verify new profile preserves `["#FF6600", null]`
</action>

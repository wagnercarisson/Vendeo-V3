<action>
Reescrever `resolveStoreIdentity(storeId)` como pipeline declarativo em `src/lib/actions/store.ts`:

1. Ler `identity_state` da store (1 query via Supabase)
2. Buscar brand profile `synced` (1 query, constraint garante único)
3. Se `identity_state === 'logo'`: buscar active store_brand_assets
4. Se `identity_state === 'visual_signature'`: buscar active visual signature
5. Se `identity_state === 'text_only'`: `signature.url = null`, pular asset lookup
6. Se asset esperado mas não encontrado: `signature.url = null`, console.log diagnóstico, não alterar estado persistido
7. Se `profile.source` incompatível com `identity_state`: console.log diagnóstico, não bloquear
8. Prioridade de variante de logo: `normalized` → `original` → `on_dark`
9. Retornar `StoreIdentitySnapshot` com `identityState`, `signature`, `brandProfile`

`resolveStoreIdentity` NÃO deve derivar directive — essa responsabilidade é do `buildCampaignBrief`.
</action>

- `resolveStoreIdentity` aceita `storeId: string` e retorna `Promise<StoreIdentitySnapshot>`

- `text_only` não busca assets
- `logo` busca store_brand_assets com prioridade de variante
- `visual_signature` busca visual signature ativa
- Asset ausente resulta em `signature.url = null`, estado não alterado
- Profile incompatível resulta em diagnóstico, mas é incluído
- Função NÃO deriva directive
- NÃO deve ser `async`? Deve ser `async` — constraint anterior de sync foi removida

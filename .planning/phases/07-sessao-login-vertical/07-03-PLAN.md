# Plan 07-03: Auth Middleware

Wave 3 — depends on Waves 1+2 (middleware helper + sanitizeRedirectPath available)

## Objective

Criar `src/middleware.ts` com matcher positivo que protege páginas e rotas de API, usando `updateSession()` para renovação de sessão e decisão de rota.

---

## Must Haves

- `src/middleware.ts` com matcher positivo: `"/"`, `"/login"`, `"/store/:path*"`, `"/campaign/:path*"`, `"/api/:path*"`
- Páginas protegidas sem sessão → redirect `/login?redirect=<path>`
- `/api/*` sem sessão → `401 { error: "Unauthorized" }`
- `/login` com sessão → redirect `/`
- Toda resposta preserva cookies de `updateSession()`
- Middleware não consulta banco de dados

## Tasks

### Task 01: Create `src/middleware.ts`

<action>
Criar `src/middleware.ts` no diretório raiz do Next.js com:
1. Matcher exportado positivo: `["/", "/login", "/store/:path*", "/campaign/:path*", "/api/:path*"]`
2. `export async function middleware(request: NextRequest)` que:
   - Chama `updateSession(request)` de `@/lib/supabase/middleware`
   - Extrai `claims` e `response` do resultado
    - Constrói redirect path com query string preservada e valida com `sanitizeRedirectPath()`:
      ```ts
      const redirectPath = request.nextUrl.pathname + request.nextUrl.search
      const safeRedirect = sanitizeRedirectPath(redirectPath)
      const loginUrl = new URL("/login", request.url)
      loginUrl.searchParams.set("redirect", safeRedirect)
      ```
   - Se `!claims?.sub`:
      - Páginas protegidas (não `/login`, não `/api/*`): criar `NextResponse.redirect(loginUrl, { status: 302 })` e **copiar cookies e headers seletivamente** da `response` de `updateSession()`. `NextResponse.redirect()` cria nova resposta — "usar como base" é insuficiente. Copiar apenas os cookies mais os headers relevantes para impedir cache compartilhado de tokens:
        ```ts
        const redirectResponse = NextResponse.redirect(loginUrl, { status: 302 })
        // Copiar cookies
        response.cookies.getAll().forEach((cookie) => {
          redirectResponse.cookies.set(cookie.name, cookie.value, cookie)
        })
        // Copiar headers de cache (impede cache compartilhado de tokens)
        const CACHE_HEADERS = ["cache-control", "expires", "pragma"] as const
        for (const key of CACHE_HEADERS) {
          const value = response.headers.get(key)
          if (value) redirectResponse.headers.set(key, value)
        }
        return redirectResponse
        ```
      - `/api/*`: criar `NextResponse.json({ error: "Unauthorized" }, { status: 401 })` (possui `.cookies` para receber cookies copiados) e copiar cookies/headers da response base
      - `/login`: `return response` (pass-through)
    - Se `claims.sub`:
      - `/login` → `NextResponse.redirect(new URL("/", request.url), { status: 302 })` com cookies copiados
      - Demais → `return response` (pass-through)
3. `export const config = { matcher: [...] }`

**Cookie/header propagation:** Toda resposta criada (redirect, 401) deve copiar explicitamente set-cookie e headers de cache da resposta de `updateSession()`. Isso impede cache compartilhado de tokens.
</action>

# Plan 07-03: Auth Middleware

Wave 2 — depends on Wave 1 (middleware.ts helper available)

## Objective

Criar `src/middleware.ts` com matcher positivo que protege páginas e rotas de API, usando `updateSession()` para renovação de sessão e decisão de rota.

---

## Must Haves

- `src/middleware.ts` com matcher positivo: `"/"`, `"/login"`, `"/store/:path*"`, `"/campaign/:path*"`, `"/api/:path*"`
- Páginas protegidas sem sessão → redirect `/login?redirect=<path>`
- `/api/*` sem sessão → `401 { error: "Unauthorized" }`
- `/login` com sessão → redirect `/`
- Toda resposta preserva cookies de `updateSession()`
- Middleware não consulta banco de dados

---

## Tasks

### Task 01: Create `src/middleware.ts`

<action>
Criar `src/middleware.ts` no diretório raiz do Next.js com:
1. Matcher exportado positivo: `["/", "/login", "/store/:path*", "/campaign/:path*", "/api/:path*"]`
2. `export async function middleware(request: NextRequest)` que:
   - Chama `updateSession(request)` de `@/lib/supabase/middleware`
   - Extrai `claims` e `response` do resultado
   - Constrói redirect param preservando query string:
     ```
     const redirectPath = request.nextUrl.pathname + request.nextUrl.search
     ```
   - Usa `URLSearchParams` para construir o parâmetro `?redirect=` corretamente
   - Se `!claims?.sub`:
     - Páginas protegidas (não `/login`, não `/api/*`): criar `NextResponse.redirect(...)` e **copiar explicitamente cookies e headers** da `response` de `updateSession()`. `NextResponse.redirect()` cria nova resposta — "usar como base" é insuficiente. Copiar via `new Response(headers, init)` ou iterar `response.headers`:
       ```ts
       const redirectResponse = NextResponse.redirect(loginUrl)
       response.headers.forEach((value, key) => {
         redirectResponse.headers.set(key, value)
       })
       return redirectResponse
       ```
     - `/api/*`: criar `Response.json({ error: "Unauthorized" }, { status: 401 })` e copiar cookies/headers da response base
     - `/login`: `return response` (pass-through)
   - Se `claims.sub`:
     - `/login` → redirect `/` com cookies copiados
     - Demais → `return response` (pass-through)
3. `export const config = { matcher: [...] }`

**Cookie/header propagation:** Toda resposta criada (redirect, 401) deve copiar explicitamente set-cookie e headers de cache da resposta de `updateSession()`. Isso impede cache compartilhado de tokens.
</action>

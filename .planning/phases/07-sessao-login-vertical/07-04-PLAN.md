### Task 02: Create `src/app/(auth)/login/page.tsx`

<action>
Criar server component (Next.js 15 — `searchParams` é `Promise`):
```ts
export default async function LoginPage({
  searchParams,
}: {
  searchParams: Promise<{ redirect?: string | string[] }>
}) {
  const params = await searchParams
  const redirectParam = typeof params.redirect === "string" ? params.redirect : ""
  const safeRedirect = sanitizeRedirectPath(redirectParam)
  return <LoginForm redirect={safeRedirect} />
}
```
- Lê `searchParams.redirect` com `await` (Next.js 15)
- Valida com `sanitizeRedirectPath()` de `@/lib/auth/redirect`
- Renderiza `<LoginForm redirect={sanitizedRedirect} />`
- Não chama `requirePageUser()` — middleware já trata auth check
</action>

### Task 04: Create logout route handler `src/app/auth/signout/route.ts`

<action>
Criar Route Handler `POST /auth/signout` que:
- Cria server client via `createServerClient()`
- Chama `supabase.auth.signOut()`
- Chama `revalidatePath("/", "layout")` (escopo layout para cobrir toda a árvore)
- Retorna redirect explícito:
  ```ts
  return NextResponse.redirect(new URL("/login", request.url), { status: 302 })
  ```
  `redirect()` do Next.js em Route Handler retorna 307 por padrão (preserva método POST após redirect). Usar `NextResponse.redirect` com `status: 302` para garantir GET no redirect pós-logout.
- É POST-only (outros métodos retornam 405)
</action>

   - `clearStorage`:
     ```ts

     sessionStorage.removeItem("campaign_draft_image")
     sessionStorage.removeItem("campaign_preview")
     localStorage.removeItem("store_id")
     ```
   - Botão "Sair" com loading state no submit

2. **`src/components/auth/auth-header.tsx`** — Server component que:
   - Chama `requireUser()` com try/catch:
     ```ts
     try {
       await requireUser()
       return <LogoutButton />
     } catch (error) {
       if (error instanceof UnauthorizedError) return null
       throw error
     }
     ```
   - Renderiza `LogoutButton` apenas se autenticado
   - Se não autenticado, retorna null — o route group `(auth)` tem layout próprio, mas o **root layout ainda envolve** páginas `(auth)`. O botão não aparece porque `AuthHeader` retorna null, não porque o layout raiz deixou de ser renderizado.

3. **`src/app/layout.tsx`** — Renderizar `<AuthHeader />` no header da aplicação

Arquitetura: `AuthHeader` (server) → `LogoutButton` (client). O route group `(auth)` não substitui o root layout — ele fica aninhado nele.
</action>

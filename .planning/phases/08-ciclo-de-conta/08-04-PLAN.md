# Plan 08-04: UAT — Local & Online

Wave 4 — User Acceptance Testing (depends on all code + tests passing)

## Objective

Validar o ciclo completo de credenciais usando o Supabase remoto + SMTP Hostinger para ambos os ambientes (localhost e Vercel Preview). Cada ambiente passa sua própria URL via `emailRedirectTo`/`redirectTo`, populando `{{ .RedirectTo }}` no template. Docker/Mailpit não são necessários.

---

## Must Haves

- `npx tsc --noEmit`, `npm run lint`, `npx next build` — zero erros
- Supabase remoto configurado: SMTP Hostinger + templates de email com TokenHash
- Vercel project vinculado, Preview com Standard Protection e NEXT_PUBLIC_SITE_URL
- `http://localhost:3000/auth/confirm` registrado nas Redirect URLs do Supabase Dashboard
- UAT local: signup com confirmação real → confirma → login (email via Hostinger)
- UAT local: forgot-password → recovery → update-password → login
- UAT online: signup e recovery entregam email real via Preview Vercel
- UAT online: callback retorna à mesma Preview (localhost e Preview)
- UAT online: Gmail e Outlook não classificam como spam
- Evidências documentadas em `docs/UAT-phase-08.md`

### Task 04: UAT online — configurar templates de email no Dashboard remoto

<action>
No Supabase Dashboard do projeto de UAT, navegar para Authentication → Email Templates e configurar:

- **Confirmation**: `{{ .RedirectTo }}?token_hash={{ .TokenHash }}&type=signup`
- **Reset Password**: `{{ .RedirectTo }}?token_hash={{ .TokenHash }}&type=recovery&next=/update-password`

Sem esta configuração, os links de confirmação podem não conter `token_hash`, quebrando o fluxo do `/auth/confirm`.
</action>

- docs/alinhamento-fase-8-ciclo-de-conta.md (seção D3 — templates)

<acceptance_criteria>
- Template Confirmation contém `{{ .RedirectTo }}`, `{{ .TokenHash }}` e `type=signup`
- Template Reset Password contém `{{ .RedirectTo }}`, `{{ .TokenHash }}`, `type=recovery` e `next=/update-password`
</acceptance_criteria>

### Task 05: UAT online — configurar SMTP Hostinger

<action>
1. No Supabase Dashboard do projeto de UAT, navegar para Authentication → Settings → SMTP Settings
2. Configurar:
   - Host: `smtp.hostinger.com`
   - Port: `465` (SSL/TLS)
   - Username: email completo do remetente
   - Password: senha da conta de email
3. Verificar SPF, DKIM e DMARC no DNS do domínio remetente
4. Verificar limite do plano Hostinger Business (1.000 ou 3.000 mensagens/dia)
</action>

### Task 06: UAT online — configurar Vercel Preview e NEXT_PUBLIC_SITE_URL

<action>
A ordem é crítica porque `NEXT_PUBLIC_SITE_URL` é validada em build/load time — sem ela, o build falha.

1. Criar/vincular projeto na Vercel com a branch estável (ex: `fase-8`)
2. Definir alias estável da Preview (ex: `fase-8.vercel.app`)
3. **Antes do primeiro deployment**, configurar `NEXT_PUBLIC_SITE_URL` no ambiente Preview da Vercel = URL do alias
4. Registrar URL da Preview (`https://fase-8.vercel.app`) no Supabase Dashboard:
   - Authentication → URL Configuration → Site URL
   - Redirect URLs: adicionar `https://fase-8.vercel.app/auth/confirm`
5. Fazer o deployment inicial
   - **Nota:** Se a URL ainda não existir no momento do deployment, o primeiro build pode falhar. Isso é esperado — faça um redeploy após a variável estar configurada
6. Habilitar Standard Protection (Vercel Deployment Protection) para acesso restrito a testadores
7. Habilitar "Enable email confirmation" no projeto Supabase de UAT (Authentication → Settings → General)
8. Confirmar que `npx next build` passa com a `NEXT_PUBLIC_SITE_URL` da Preview
</action>

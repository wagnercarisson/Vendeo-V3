# Plan 08-04: UAT — Local & Online

Wave 4 — User Acceptance Testing (depends on all code + tests passing)

## Objective

Validar o ciclo completo de credenciais em dois ambientes: local (Supabase + Mailpit) e online (Vercel Preview + SMTP Hostinger). Garantir que signup, confirmação, recuperação e deliverability funcionam conforme especificado.

---

## Must Haves

- UAT local: signup com confirmação via Mailpit → confirma → login
- UAT local: forgot-password → recovery → update-password → login
- UAT online: SMTP Hostinger configurado e funcional
- UAT online: Vercel Preview protegida acessível
- UAT online: signup e recovery entregam email real
- UAT online: callback retorna à mesma Preview
- UAT online: Gmail e Outlook não classificam como spam
- `npx tsc --noEmit` zero erros
- `npm run lint` zero erros
- `npx next build` bem-sucedido

---

## Tasks

### Task 01: UAT local — ciclo de signup com Mailpit

<action>
1. Alterar `enable_confirmations = true` em `supabase/config.toml` (`[auth.email]`)
2. Reiniciar stack: `npx supabase stop && npx supabase start`
3. Verificar Mailpit em `http://localhost:54325`
4. Navegar para `http://localhost:3000/signup`
5. Criar conta com email e senha válidos
6. Verificar que é redirecionado para `/check-email?type=signup`
7. Abrir Mailpit, localizar o email de confirmação
8. Clicar no link de confirmação
9. Verificar que é redirecionado para `/` (login automático pós-confirmação)
</action>

<read_first>
- supabase/config.toml
</read_first>

<acceptance_criteria>
- Signup bem-sucedido com confirmação real via Mailpit
- Email de confirmação contém link com `token_hash` e `type=signup`
- Link de confirmação redireciona para `/` (login automático)
</acceptance_criteria>

### Task 02: UAT local — ciclo de recovery

<action>
1. Acessar `http://localhost:3000/forgot-password`
2. Inserir email da conta criada na Task 01
3. Verificar redirect para `/check-email?type=recovery`
4. Abrir Mailpit, localizar o email de recovery
5. Clicar no link (deve conter `type=recovery&next=/update-password`)
6. Verificar que é redirecionado para `/update-password`
7. Definir nova senha e confirmar
8. Verificar redirect para `/`
9. Fazer logout e login com a nova senha
</action>

<acceptance_criteria>

- Link de recovery redireciona para `/update-password`
- Nova senha funciona para login subsequente
- Sessão mantida após alteração de senha
</acceptance_criteria>

### Task 04: UAT online — configurar SMTP Hostinger

<action>
1. No Supabase Dashboard do projeto de UAT, navegar para Authentication → Settings → SMTP Settings
2. Configurar:
   - Host: `smtp.hostinger.com`
   - Port: `465` (SSL/TLS)
   - Username: email completo do remetente
   - Password: senha da conta de email
3. Verificar SPF, DKIM e DMARC no DNS do domínio remetente
4. Verificar limite do plano Hostinger Business (1.000 ou 3.000 mensagens/dia)
</action>

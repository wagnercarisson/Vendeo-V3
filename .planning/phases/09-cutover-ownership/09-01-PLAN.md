### Task 01: Migration SQL — add_user_id_to_stores

<action>
Criar migration `supabase/migrations/<timestamp>_add_user_id_to_stores.sql` com timestamp de hoje (20260706):

1. DELETE FROM generation_events
2. DELETE FROM store_brand_profiles         (antes de brand_assets e visual_signatures — FK references ambos)
3. DELETE FROM store_brand_assets
4. DELETE FROM store_visual_signatures
5. DELETE FROM stores
6. ALTER TABLE stores ADD COLUMN user_id UUID NOT NULL UNIQUE REFERENCES auth.users(id)
7. ALTER TABLE stores ENABLE ROW LEVEL SECURITY
8. CREATE POLICY "users_select_own_store" FOR SELECT TO authenticated USING (user_id = (SELECT auth.uid()))
9. GRANT SELECT ON TABLE public.stores TO authenticated
10. Include `-- REVERT:` block com ALTER TABLE ... DROP COLUMN e GRANT/REVOKE reverso

**Nota:** O GRANT SELECT é necessário porque as migrations existentes revogaram `authenticated`. Sem ele, `createServerClient()` não consegue acessar `stores` mesmo com RLS policy.

**⚠ A migration é destrutiva (DELETE em tabelas filhas + stores). Confirmar que está em ambiente local/dev antes de aplicar. Nunca rodar contra produção.**

Rodar `npx supabase migration up` para aplicar localmente e verificar:
- `\d stores` — coluna user_id UUID NOT NULL UNIQUE REFERENCES auth.users(id)
- `\d stores` — RLS enabled
- `\dp stores` — authenticated tem SELECT
- `\c stores` — "users_select_own_store" policy existe
</action>

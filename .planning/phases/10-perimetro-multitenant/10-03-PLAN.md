# Plan 10-03: Server Actions — Extracao de Servico + Guards

Wave 2 — Extracao de servico interno e guards nas Server Actions (depends on 10-01, parallel to 10-02)

## Objective

Extrair 3 funcoes de `src/lib/actions/store.ts` para `src/lib/store-identity-service.ts` como servico interno (sem `"use server"`). Adicionar `requireUser()` + `requireOwnership(storeId)` nas 4 Server Actions de `src/lib/visual-signature/server-actions.ts`.

---

## Must Haves

- `src/lib/store-identity-service.ts` com `resolveStoreIdentity(store)`, `validateIdentityReference(snapshot)`, `buildCampaignBrief(snapshot, input)`
- Nenhuma das 3 funcoes tem `"use server"` — sao funcoes puras ou de servico
- `resolveStoreIdentity` recebe store ja autorizada, nunca aceita storeId cru do cliente
- `src/lib/actions/store.ts` atualizado: funcoes extraidas removidas, importa de `store-identity-service.ts`
- `generateVariations(storeId)`: requireUser() + requireOwnership(storeId)
- `generateAutomatic(storeId)`: requireUser() + requireOwnership(storeId)
- `activateSignature(storeId, signatureId)`: requireUser() + requireOwnership(storeId)
- `listSignatures(storeId)`: requireUser() + requireOwnership(storeId) + supabaseAdmin query filtrada
- Testes para cada entrypoint com auth mockado

### Task 03: Adicionar requireUser + requireOwnership em generateVariations

<action>

```typescript
import { requireUser } from "@/lib/auth/require-user";
import { requireOwnership } from "@/lib/auth/store-ownership";

  const user = await requireUser();
  await requireOwnership(storeId, user.userId);
  // ... codigo existente usando supabaseAdmin
}
```

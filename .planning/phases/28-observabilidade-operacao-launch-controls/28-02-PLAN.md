# 28-02: Migrations + Pipeline Integration + Rate Limit

## Objective

Expandir a tabela `generation_events` para suportar telemetria de IA, criar a função de cleanup 90d, e instrumentar o pipeline de geração com launch config checks, logging estruturado e telemetria persistida (best-effort). Modificar rate-limit para respeitar `rateLimitEnabled` flag.

## Must Haves

- [ ] Migration 1: DROP CHECK + ADD CHECK (novos tipos) + ADD COLUMNS em `generation_events`
- [ ] Migration 2: CREATE FUNCTION `cleanup_generation_events_90d()` — sem DELETE durante a migration
- [ ] Launch config checks no pipeline (generationPaused → 503, v15Enabled → v1.4, etc.)
- [ ] traceId gerado via randomUUID() no início de cada request
- [ ] `logPipelineEvent()` em 11 etapas do pré-stream, paralelo e pós-paralelo
- [ ] Telemetria INSERT em generation_events após Copy Director, Image Director e pipeline completo
- [ ] `rateLimitEnabled=false` → `checkRateLimit()` retorna `{ allowed: true }` sem consultar banco
- [ ] Tentativas continuam registradas em `generation_rate_events` mesmo com flag desligada
- [ ] INSERT de telemetria é best-effort (try/catch) — nunca bloqueia o pipeline
- [ ] `npm run typecheck` — zero erros
- [ ] `npm run lint` — zero erros
- [ ] `npm run build` — bem-sucedido

## Dependencies

28-01 (launch-config, pipeline-logger), 25-02 (pipeline 3 zonas), 24-01 (CreditService).

- Migration 1 aplicada: colunas novas existem (campaign_id, user_id, prompt_tokens, completion_tokens, total_tokens, trace_id, phase)

- logPipelineEvent() emitido em cada etapa com traceId único por request

</read_first>

<action>
Create migration with:
```sql
CREATE OR REPLACE FUNCTION public.cleanup_generation_events_90d()
RETURNS bigint
LANGUAGE plpgsql
SECURITY DEFINER SET search_path = public
AS $$
DECLARE
  deleted_count bigint;
BEGIN
  DELETE FROM public.generation_events
  WHERE created_at < NOW() - INTERVAL '90 days';
  GET DIAGNOSTICS deleted_count = ROW_COUNT;
  RETURN deleted_count;
END;
$$;
```
Include REVERT section with DROP FUNCTION.

<acceptance_criteria>
- Migration defines function but does NOT execute it
- Function returns number of deleted rows
- Function is SECURITY DEFINER with explicit search_path
</acceptance_criteria>

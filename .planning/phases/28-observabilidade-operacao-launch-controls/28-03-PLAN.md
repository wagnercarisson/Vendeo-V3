### Task 2: Pipeline Metrics — Query Functions

**File:** `src/lib/metrics/pipeline-metrics.ts`

<read_first>
- `openspec/changes/fase-28-observabilidade-operacao-launch-controls/specs/pipeline-metrics/spec.md` — 7 functions, hours parameter, scenarios
- `src/lib/supabase/admin.ts` — supabaseAdmin client

</read_first>

<action>
Create `src/lib/metrics/pipeline-metrics.ts` with 7 functions, each accepting `hours: number` (1, 24, 168):

1. `getSuccessRate(hours)` — percentage of `status=success` in `generation_events`
2. `getErrorRate(hours)` — percentage of `status=failed` in `generation_events`
3. `getAvgCost(hours)` — average of `estimated_cost_usd` in `generation_events` (null if no records with cost)
4. `getAvgDuration(hours)` — average of `duration_ms` in `generation_events`
5. `getCreditsGranted(hours)` — count of `type=grant` in `credit_transactions`
6. `getRefundRate(hours)` — percentage of refunds over non-grant transactions in `credit_transactions`
7. `getActiveUsers(hours)` — distinct `user_id` count in `generation_events`

All queries via `supabaseAdmin`, direct SQL (no cache, no pre-aggregation).

<acceptance_criteria>
- `getSuccessRate(24)` with 80 success + 20 failed returns 80
- `getErrorRate(24)` with 10 failed in 100 returns 10
- `getErrorRate(24)` with zero records returns 0
- `getAvgCost(24)` with costs 0.01, 0.02, 0.03 returns 0.02
- `getAvgCost(24)` with no cost records returns null
- `getAvgDuration(24)` with durations 10, 20, 30 returns 20
- `getCreditsGranted(24)` with 15 grants returns 15
- `getRefundRate(24)` with 2 refunds in 10 non-grant returns 20
- `getActiveUsers(24)` with 3 distinct user_ids returns 3
</acceptance_criteria>

#### Task 1.4: generate-without-logo — Integração de crédito

<read_first>

- openspec/changes/fase-29-1-1-creditos-assinatura-visual/tasks.md
</read_first>

<action>

1. Add imports: `getLaunchConfig` from `@/lib/launch-config/config`, `CreditService` from `@/lib/credit/credit-service`
2. After store load and before substitution guards, add guard:
   - `getLaunchConfig().generationPaused` → return 503 "Geração temporariamente indisponível."
3. After substitution mode guards (or after store load in standard mode), check:
   - If `getLaunchConfig().v15Enabled === false`: skip ALL credit logic (no balance check, no reserve, no refund, no credit_tx_id)
   - If `getLaunchConfig().creditsChargingEnabled === false`: skip balance check and reserve/refund, but keep rest of flow normal
4. If creditsChargingEnabled, add balance check BEFORE IA call:
   - `new CreditService().getBalance(id)` — if balance < 1, return 402 `{ error: "Créditos insuficientes", code: "insufficient_credits" }`
5. If creditsChargingEnabled, add `reserveCredit` BEFORE IA call:
   - `const creditTxId = await new CreditService().reserveCredit(id, 1, { campaignId: null, idempotencyKey: \`vs_reserve_${id}_${operationId}\`, metadata: { feature: "visual_signature", mode, operationId } })`
6. REMOVE totalCount >= 3 exhausted guard and its response block
7. REMOVE `store.update({ visual_signature_attempts: ... })` — both the increment in success path and the `logo_status: 'failed'` in failure path
8. In success path (after persistSignature), ADD update to write `credit_tx_id` into the signature's metadata:
   ```
   await supabase.from('store_visual_signatures').update({
     metadata: { ...existingMetadata, credit_tx_id: creditTxId }
   }).eq('id', signature.id)
   ```
9. Wrap the IA + persist block in try/catch: on catch (technical failure — timeout, IA error, storage error), call `refundCredit(creditTxId, reason)` before returning error
10. Wrap `generationLocks.set/get/delete` + timeout in `try/finally` to guarantee lock cleanup
11. Ensure response does NOT include `maxAttempts: 3` or `attempt: attemptNumber` fields related to quota
</action>

<acceptance_criteria>
- `generationPaused=true` returns 503 before any operation
- `v15Enabled=false` skips all credit logic (no balance check, no reserve)
- `creditsChargingEnabled=false` skips balance check and reserve but generation proceeds
- With sufficient balance: reserves credit, generates VS, persists with `credit_tx_id` in metadata
- With zero balance: returns 402 `{ code: "insufficient_credits" }`
- On IA failure after reserve: calls `refundCredit`, returns error (not 402)
- On storage failure after reserve: calls `refundCredit`, returns 503
- No limit of 3 — user can generate unlimited VS (subject to credit balance)
- `visual_signature_attempts` NOT incremented anywhere
- Lock always released in `finally` (including on crash/timeout)
- Timeout always cleared in `finally`
</acceptance_criteria>

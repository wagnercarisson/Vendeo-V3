# 29-01: Componentes Base + Loading States + Error Boundaries

## Objective

Eliminar telas em branco durante carregamento (12 rotas) e exposição de stack trace em erros (2 grupos), criando a fundação de componentes reutilizáveis de loading e error.

## Tasks

### Task 29-01-01: Estender Skeleton com prop variant

Extends `src/components/ui/skeleton.tsx` with a `variant` prop.

<read_first>
- src/components/ui/skeleton.tsx
</read_first>

<action>
Add `variant` prop of type `"card" | "table" | "form" | "preview" | "stats"` to the existing `Skeleton` component.

Each variant renders stable dimensions:
- `card`: `h-64 w-full` with `aspect-square` + 2 skeleton lines (`h-4 w-3/4`, `h-4 w-1/2`)
- `table`: `space-y-3` with configurable `rows` prop (default 5), each row `h-10 w-full` with `rounded`
- `form`: `space-y-4` with label+input pairs (3 pairs): label `h-4 w-1/4`, input `h-10 w-full`
- `preview`: `aspect-square w-full` block
- `stats`: CSS grid `grid-cols-2 lg:grid-cols-4 gap-4` with `count` prop (default 4), each card `h-24 w-full`

Default when no `variant` is passed: preserve existing `width`, `height`, `rounded` props exactly as they work today. No breaking change in existing usage.
</action>

<acceptance_criteria>
- `Skeleton` component accepts `variant` prop with all 5 types
- `Skeleton` with `variant="card"` renders aspect-square + 2 text lines
- `Skeleton` with `variant="table" rows={5}` renders 5 rows with h-10
- `Skeleton` with `variant="form"` renders 3 label+input pairs
- `Skeleton` with `variant="preview"` renders aspect-square block
- `Skeleton` with `variant="stats" count={4}` renders 4 cards in grid
- No variant prop preserves existing width/height/rounded behavior (zero breaking changes)
- All existing Skeleton usages render identically to pre-F29
- TypeScript compile passes
- npx vitest run passes
</acceptance_criteria>

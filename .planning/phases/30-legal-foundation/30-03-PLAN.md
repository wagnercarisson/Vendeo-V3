### Task 3: API Route — POST /api/legal/acknowledge-privacy

<read_first>
- openspec/changes/fase-30-legal-foundation/specs/signup-page/spec.md
- src/lib/legal/privacy.ts
- src/lib/legal/consent.ts
- src/lib/legal/document-versions.ts
- src/app/api/ (existing API route patterns)
</read_first>

<action>
Create `src/app/api/legal/acknowledge-privacy/route.ts`:

- POST handler
- Requires authentication (requireUser)
- Receives `{ communicationsOptIn: boolean }` from client body
- Resolves current privacy_policy version server-side via `getCurrentVersion("privacy_policy")` — does NOT accept version from client (no version spoofing)
- Resolves IP and UA from the incoming request
- Calls `registerPrivacyAcknowledgement()` with the resolved version, IP, UA
- If `communicationsOptIn` is true, calls `recordConsentEvent()` with action "granted"
- Returns 200 on success
- If the legal call fails, logs error server-side but still returns 200 (anti-enumeration — the auth user was already created by Supabase Auth)
</action>

<acceptance_criteria>
- `POST /api/legal/acknowledge-privacy` with valid params returns 200
- Version is resolved server-side, never from client body
- If communicationsOptIn is true, consent event is recorded
- On failure, returns 200 but logs error (anti-enumeration preserved)
- TypeScript compiles
</acceptance_criteria>

# Plan 30-04: Pipeline Guards + Re-aceite Flow

## Objective

Adicionar o guardião `requireLegalClearance` no pipeline de geração e no fluxo de assinatura visual, e implementar o fluxo de re-aceite contratual.

## Tasks

### Task 1: Pipeline Guard — requireLegalClearance no generate-image

<read_first>
- .planning/phases/30-legal-foundation/30-CONTEXT.md (D2, D7)
- openspec/changes/fase-30-legal-foundation/specs/transactional-pipeline/spec.md
- src/app/api/campaign/generate-image/route.ts (existing route)
- src/lib/legal/clearance.ts
</read_first>

<action>
Modify `src/app/api/campaign/generate-image/route.ts`:

- In the pré-stream zone (before ReadableStream), add legal clearance check:
  - Call requireLegalClearance({ storeId, userId, capability: "content_generation" })
  - Execute BEFORE rate limit and balance check (first check in pré-stream after auth/ownership)
  - If clearance returns `{ ok: false }`:
    - Return HTTP 403 with JSON:
      ```json
      {
        "error": {
          "message": "Ação bloqueada por pendência legal.",
          "reason": "<reason from clearance>",
          "requiredDocuments": ["<pending docs>"]
        }
      }
      ```
    - Include `acceptUrl: "/legal/reaccept"` in the response body
  - If clearance returns `{ ok: true }`:
    - Continue normal flow (rate limit → balance check → etc.)
</action>

<acceptance_criteria>
- `requireLegalClearance` is called before rate limit and balance check
- Clearance failure returns 403 before any IA call
- 403 response includes message, reason, requiredDocuments, acceptUrl
- Clearance success continues to rate limit and normal pipeline flow
- TypeScript compiles, lint passes
</acceptance_criteria>

- All existing behavior (standard/substitution modes, approval, re-generation, historical versions, credit handling) remains unchanged when clearance passes
</action>

### Task 3: Re-aceite Page — /legal/reaccept

<read_first>
- openspec/changes/fase-30-legal-foundation/specs/re-aceite-flow/spec.md
- src/lib/legal/acceptance-service.ts

<action>
Create the re-acceptance flow:

1. **Server component** `src/app/(app)/legal/reaccept/page.tsx`:
   - Requires auth (middleware allows through, page checks auth)
   - Detects which documents have pending acceptance for the user's store
   - For each pending document:
     - Displays message: "Os Termos de Uso foram atualizados" (or "A Política de Uso Aceitável foi atualizada")
     - Shows summary of changes from the new version (`summary` field from legal_document_versions)
     - Provides link to the full document
   - Shows button "Aceitar nova versão"
   - Shows button "Revisar documento" (opens the full document in new tab)
   - If no pending documents: show "Tudo em dia" message

2. **Client component** `src/app/(app)/legal/reaccept/reaccept-form.tsx`:
   - "Aceitar nova versão" button calls POST /api/legal/accept with source='login_reacceptance'
   - On success: redirects to previous page or dashboard
   - Shows loading state during submission
</action>

<acceptance_criteria>
- `/legal/reaccept` shows pending documents with change summary and version info
- "Aceitar nova versão" button calls POST /api/legal/accept
- After re-acceptance, requireLegalClearance returns { ok: true }
- If no pending documents, shows "Tudo em dia" message
- TypeScript compiles, lint passes
</acceptance_criteria>

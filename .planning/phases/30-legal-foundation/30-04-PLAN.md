# Plan 30-04: Pipeline Guards + Re-aceite Flow

## Objective

Adicionar o guardião `requireLegalClearance` no pipeline de geração e no fluxo de assinatura visual, e implementar o fluxo de re-aceite contratual.

### Task 1: Pipeline Guard — requireLegalClearance no generate-image

<action>
Modify `src/app/api/campaign/generate-image/route.ts`:

- In the pré-stream zone (before ReadableStream), add legal clearance check:
  - Call requireLegalClearance({ storeId, userId, capability: "content_generation" })
  - Execute BEFORE rate limit and balance check (first check in pré-stream after auth/ownership)
  - If clearance returns `{ ok: false }`:
    - Return HTTP 403 with JSON:
      ```json
      {
        "error": {
          "message": "Ação bloqueada por pendência legal.",
          "reason": "<reason from clearance>",
          "requiredDocuments": ["<pending docs>"]
        }
      }
      ```
    - Include `acceptUrl: "/legal/reaccept"` in the response body
  - If clearance returns `{ ok: true }`:
    - Continue normal flow (rate limit → balance check → etc.)
</action>

<acceptance_criteria>
- `requireLegalClearance` is called before rate limit and balance check
- Clearance failure returns 403 before any IA call
- 403 response includes message, reason, requiredDocuments, acceptUrl
- Clearance success continues to rate limit and normal pipeline flow
- TypeScript compiles, lint passes
</acceptance_criteria>

### Task 2: Visual Signature Guard — requireLegalClearance no VS

<read_first>
- openspec/changes/fase-30-legal-foundation/specs/visual-signature-approval/spec.md
- src/components/flow/visual-signature-approval-modal.tsx (existing modal, `"use client"`)

- src/lib/legal/clearance.ts
- src/app/api/legal/status/route.ts (from Plan 30-03, returns privacy, consent, acceptance status)
</read_first>

<action>

**Context: `visual-signature-approval-modal.tsx` é `"use client"` — não pode chamar `requireLegalClearance` diretamente (usa supabaseAdmin/service role).**

Em vez disso, o guard é aplicado em duas camadas:

**Camada 1 — API Route (server-side, autoritativo):**
A API `src/app/api/store/[id]/visual-signature/generate-without-logo/route.ts` verifica `requireLegalClearance({ storeId, userId, capability: "content_generation" })` ANTES de qualquer operação de geração. Se o clearance falhar, retorna HTTP 403 com JSON padronizado (message, reason, requiredDocuments, acceptUrl).

**Camada 2 — Client-side (UX):**
O modal `visual-signature-approval-modal.tsx` faz uma chamada a `GET /api/legal/status` (ou endpoint similar) ANTES de iniciar o fluxo de geração:

- Se o status retornar `acceptanceStatus !== "current"`:
  - Exibir estado de bloqueio com mensagem: "Ação bloqueada por pendência legal. Aceite a nova versão dos documentos para continuar."
  - Mostrar link para `/legal/reaccept`
  - Não prosseguir com geração
- Se o status retornar `acceptanceStatus === "current"`:
  - Prosseguir com fluxo normal de geração VS (inalterado)
- Todo comportamento existente (standard/substitution modes, approval, re-generation, historical versions, credit handling) permanece inalterado quando clearance está ok

**Nota:** A camada 1 (API) é a guarda autoritativa — mesmo que o client pule a verificação, o servidor bloqueia. A camada 2 é UX para feedback imediato sem chamar a API de geração.
</action>

<acceptance_criteria>
- API route que gera VS verifica requireLegalClearance antes de operar (camada autoritativa)
- Modal consulta GET /api/legal/status antes de iniciar geração (camada UX)
- Legal blocking state mostra mensagem e link para /legal/reaccept
- Geração não prossegue quando clearance falha (em ambas as camadas)
- Fluxo normal inalterado quando clearance está ok
- TypeScript compila, lint passa
</acceptance_criteria>

<action>
Create the re-acceptance flow:

1. **Server component** `src/app/(app)/legal/reaccept/page.tsx`:
   - Requires auth (middleware allows through, page checks auth)
   - Detects which documents have pending acceptance for the user's store
   - For each pending document:
     - Displays message: "Os Termos de Uso foram atualizados" (or "A Política de Uso Aceitável foi atualizada")
     - Shows summary of changes from the new version (`summary` field from legal_document_versions)
     - Provides link to the full document
   - Shows button "Aceitar nova versão"
   - Shows button "Revisar documento" (opens the full document in new tab)
   - If no pending documents: show "Tudo em dia" message

2. **Client component** `src/app/(app)/legal/reaccept/reaccept-form.tsx`:
   - "Aceitar nova versão" button calls POST /api/legal/accept with source='login_reacceptance'
   - On success: redirects to previous page or dashboard
   - Shows loading state during submission
</action>

<acceptance_criteria>

- If no pending documents, shows "Tudo em dia" message
- TypeScript compiles, lint passes
</acceptance_criteria>

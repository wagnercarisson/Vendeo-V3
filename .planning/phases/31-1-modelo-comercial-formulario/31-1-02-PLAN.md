### Task 2: inferIntent function + integração no hook

<read_first>
- src/components/flow/use-campaign-form.ts (Current hook structure, setField, handlers)
- openspec/changes/fase-31-1-modelo-comercial-formulario/specs/campaign-form-intent/spec.md (Inferência)
</read_first>

<action>
1. Implementar função `inferIntent` no escopo do módulo (fora do hook) e **exportá-la como named export** (`export function inferIntent`):
   ```typescript
   function inferIntent(
     originalPriceCents: number,
     discountedPriceCents: number | undefined | null
   ): CampaignIntent {
     const hasOriginal = originalPriceCents > 0;
     const hasDiscounted = (discountedPriceCents ?? 0) > 0;

     if (hasOriginal && hasDiscounted) return "offer";
     if (hasDiscounted) return "spotlight";
     return "exclusive";
   }
   ```
   Valores `undefined`/`null` são normalizados para `0` via nullish coalescing.

2. Integrar no `useCampaignForm`:
   - Criar `useEffect` que observa `fields.originalPriceCents` e `fields.discountedPriceCents`
   - Quando qualquer um muda, chamar `inferIntent` e atualizar `campaignIntent` via `setFields`
   - **Não** sobrescrever se o usuário já selecionou manualmente uma intent diferente da inferida — usar flag `userChangedIntent` (booleano `useRef`).
   - **Integração com setField:** Modificar `setField` para que, quando `field === "campaignIntent"`, ele automaticamente marque `userChangedIntent.current = true`. Isso centraliza a lógica e evita que o Plan 4 precise chamar `userChangedIntent.current` manualmente.
   - Quando os preços mudarem e `userChangedIntent` for false, atualizar automaticamente via `setFields`.
   - Se `userChangedIntent` for true, não atualizar automaticamente ao mudar preços
   - **Normalizar intent manual inválida:** Quando os preços mudarem (mesmo com `userChangedIntent = true`), verificar se `fields.campaignIntent` ainda existe nas opções disponíveis para os novos preços. Se não existir (ex: usuário escolheu spotlight, depois preenche DE+POR → opções são só [offer]), forçar `campaignIntent` para a intent inferida e resetar `userChangedIntent.current = false`. Isso evita formulário bloqueado/incoerente.

3. Garantir que o `useEffect` de inferência só rode quando o componente está montado (sem memory leaks)
</action>

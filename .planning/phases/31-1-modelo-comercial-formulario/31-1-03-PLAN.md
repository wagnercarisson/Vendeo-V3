# Plan 31-1-03: Pipeline — Guard + InputSnapshot

## Objective

Adicionar o guard de segurança no pipeline que rejeita intents não-offer (`spotlight`/`exclusive`) antes de qualquer operação paga (criação de campanha, reserva de crédito, chamada de IA). Também transportar `campaignIntent` e `preserveImageContext` no `inputSnapshot` com a normalização adequada.

## Tasks

### Task 1: Pipeline guard — rejeitar intents não-offer no pré-stream

<read_first>
- src/app/api/campaign/generate-image/route.ts (Todo o handler, especialmente a zona pré-stream)
- src/app/api/campaign/generate-image/route.ts (linhas 98-116, schema parse existente)
- openspec/changes/fase-31-1-modelo-comercial-formulario/specs/transactional-pipeline/spec.md
</read_first>

<action>
Adicionar o guard no pré-stream, **após auth/ownership/legal clearance**, mas **antes de rate limit, saldo check, criação de campanha e reserva de crédito**. O guard deve ser posicionado entre o bloco de legal clearance e a seção de rate limit.

Inserir após o bloco `requireLegalClearance` (que termina ~linha 156) e antes de `// ── Rate Limit` (~linha 158):

```typescript
// ── Pre-stream: Campaign intent guard ──────────────────────────────
if (parsed.data.campaignIntent !== "offer") {
  return Response.json(
    { error: { message: "Intenção comercial indisponível. Apenas ofertas podem ser geradas no momento." } },
    { status: 400 }
  );
}
```

**Regras:**
- O guard usa `parsed.data.campaignIntent` que já tem default "offer" do schema
- Se `campaignIntent` for `undefined` no body, o schema default faz ser `"offer"` → guard não bloqueia
- A mensagem de erro deve ser exatamente: "Intenção comercial indisponível. Apenas ofertas podem ser geradas no momento."
- HTTP status code: 400
- O guard é uma camada de segurança (D-07), o bloqueio principal é no client-side

**Posicionamento crítico:** Após `requireApiUser`, `requireOwnership` e `requireLegalClearance` (para respeitar a ordem de validação do pipeline: parse → auth → ownership → legal clearance → campaignIntent guard), mas antes de rate limit, saldo check, criação de campanha e reserva de crédito. Isso garante que o guard só executa após as validações de segurança e legais, e que nenhuma operação paga ou de IA seja executada depois.
</action>

<acceptance_criteria>
- Request com `campaignIntent: "spotlight"` → HTTP 400 body `{ error: { message: "Intenção comercial indisponível. Apenas ofertas podem ser geradas no momento." } }`
- Request com `campaignIntent: "exclusive"` → HTTP 400 mensagem igual
- Request sem `campaignIntent` → pipeline prossegue (default offer, guard não bloqueia)
- Request com `campaignIntent: "offer"` → pipeline prossegue normalmente
- Guard está posicionado após auth/ownership/legal clearance e antes de rate-limit/saldo/IA/criação de campanha
- `npm run typecheck` passa
</acceptance_criteria>

### Task 2: InputSnapshot com campaignIntent + preserveImageContext + normalização

<read_first>
- src/app/api/campaign/generate-image/route.ts (linhas 268-287, inputSnapshot atual)
</read_first>

<action>
Modificar o `inputSnapshot` na seção de criação de campanha (linhas 268-287) para incluir os novos campos:

Adicionar no objeto `inputSnapshot` (após `mandatoryArtworkText`, antes de `productImage`):

```typescript
campaignIntent: campaignInput.campaignIntent,
preserveImageContext: campaignInput.campaignIntent === "offer"
  ? false
  : (campaignInput.preserveImageContext ?? false),
```

**Regra de normalização (per D-5):**
- Se `campaignIntent === "offer"`, `preserveImageContext` é SEMPRE `false` independente do valor enviado
- Se `campaignIntent === "spotlight"` ou `"exclusive"`, `preserveImageContext` mantém o valor enviado (ou `false` se omitido)

**Nota:** O guard do Task 1 já garante que apenas `offer` chega aqui (nesta fase). A normalização para `false` em `offer` mantém os registros existentes compatíveis (per D-6) e prepara o campo para F31.2 quando `spotlight`/`exclusive` forem ativados.
</action>

<acceptance_criteria>
- `inputSnapshot` contém `campaignIntent: "offer"` quando body tem `campaignIntent: "offer"`
- `inputSnapshot` contém `preserveImageContext: false` quando body tem `campaignIntent: "offer"` e `preserveImageContext: true`
- `inputSnapshot` contém `preserveImageContext: false` quando body tem `campaignIntent: "offer"` e `preserveImageContext: false`
- `inputSnapshot` contém `preserveImageContext: false` quando body tem `campaignIntent: "offer"` e `preserveImageContext` omitido
- Normalização não afeta registros existentes sem `campaignIntent` (default continua sendo offer)
- `npm run typecheck` passa
</acceptance_criteria>

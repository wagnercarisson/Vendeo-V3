# Plan 31-1-04: UI — IntentSelector + Badge + Checkbox + Submit

## Objective

Modificar o formulário de campanha (`campaign-input-form.tsx`) para incluir o seletor de intenção comercial (radio group), badge condicional por intent, checkbox preserveImageContext (invisível em offer), e bloqueio de submissão para intents não-offer. Este plan depende dos contratos e lógica estabelecidos nos Plans 1 e 2.

## Tasks

### Task 1: IntentSelector component + integração no formulário

<read_first>
- src/components/flow/campaign-input-form.tsx (Full file — especialmente FormContent, linhas 194-459)
- src/components/flow/use-campaign-form.ts (CampaignFormFields, setField, handleBlur, fieldErrors, touched)
- openspec/changes/fase-31-1-modelo-comercial-formulario/specs/campaign-form-intent/spec.md (Intent selector)
- openspec/changes/fase-31-1-modelo-comercial-formulario/specs/campaign-input-ui/spec.md (Form fields)
</read_first>

<action>
1. Criar o componente `IntentSelector` **dentro do mesmo arquivo** `campaign-input-form.tsx` (não criar arquivo separado — consistente com o padrão do arquivo que já tem `FormContent` no mesmo arquivo):

   `IntentSelector` é um radio group vertical com as seguintes características:
   - **Props:** `value: CampaignIntent`, `onChange: (intent: CampaignIntent) => void`, `availableOptions: CampaignIntent[]`, `disabled: boolean`
   - **Renderização:** Um radio button para cada intent em `availableOptions`
   - **Termos PT-BR:** `offer` → "Oferta", `spotlight` → "Destaque", `exclusive` → "Exclusivo"
   - **Indicador "Em breve":** Para `spotlight` e `exclusive`, exibir badge "Em breve" ao lado do label (estilo: `text-[10px] bg-amber-900/40 text-amber-300 px-1.5 py-0.5 rounded-full font-medium ml-2`)
   - **Estilo visual:** Radio group vertical com `space-y-2`, cada opção é um `label` estilizado como card clicável (borda, padding, cursor pointer)
   - **Desabilitado:** Quando `disabled` é true, todos os inputs ficam disabled (durante submissão)

2. Adicionar `IntentSelector` no formulário:
   - **Posicionamento:** Entre o badge select e o `MandatoryArtworkField` (entre as seções de badge e mandatory artwork)
   - **Antes de MandatoryArtworkField**, depois do badge select
   - Passar `campaignIntent` e `setField("campaignIntent", ...)`

3. Calcular `availableOptions`:
   - No `FormContent`, usar `inferIntent` (importar de `use-campaign-form`) para determinar as opções disponíveis
   - `offer` → `["offer"]`
   - `spotlight` → `["offer", "spotlight"]`
   - `exclusive` → `["spotlight", "exclusive"]`
   - **Regra:** Se o usuário mudou manualmente (via `userChangedIntent`), as opções disponíveis continuam baseadas nos preços atuais, não na intent selecionada

4. Atualizar `FormContentProps` e `CampaignInputFormProps`:
   - Nenhuma prop adicional necessária — `campaignIntent` já está em `fields`, `setField` já está disponível
</action>

<acceptance_criteria>
- IntentSelector renderiza radio group com opções filtradas
- Quando DE+POR preenchidos → apenas "Oferta" disponível
- Quando só preço → "Oferta" e "Destaque" disponíveis
- Quando nenhum preço → "Destaque" e "Exclusivo" disponíveis
- "Destaque" e "Exclusivo" exibem badge "Em breve"
- Radio group aparece entre badge select e mandatory artwork field
- `npm run typecheck` passa
</acceptance_criteria>

<action>
1. **Badge select condicional (linhas 357-391):**
   - Modificar o `<select id="badge">` para usar `BADGE_OPTIONS_BY_INTENT[fields.campaignIntent]` em vez de `BADGE_OPTIONS`
   - Adicionar opção vazia `<option value="">Nenhum</option>` no select
   - Para `offer`: manter `<option value="" disabled>` (sem opção vazia — badge obrigatório)
   - Para `spotlight`/`exclusive`: usar `<option value="">Nenhum</option>` (badge opcional)
   - Mudar label de "Selo promocional *" para "Selo promocional" (sem asterisco) quando badge é opcional
   - Adicionar texto "(opcional)" ao lado quando `campaignIntent !== "offer"` (mesmo padrão de Preço Original)

2. **Badge cleanup ao trocar intent (efeito):**
   - Adicionar `useEffect` no `FormContent` (ou no `useCampaignForm`) que detecta mudança de `campaignIntent`
   - Comparar badge atual com `BADGE_OPTIONS_BY_INTENT[newIntent]`
   - Se badge não pertence à nova lista, resetar para vazio
   - **Regra de negócio (per CONTEXT.md linha 241):** "Quando o usuário troca de intent e o badge atual não pertence à lista da nova intent, o badge é resetado para vazio automaticamente. Isso evita inconsistência visual."

3. **Checkbox preserveImageContext:**
   - Adicionar após o IntentSelector (antes de MandatoryArtworkField):
     ```tsx
     {fields.campaignIntent !== "offer" && (
       <label className="flex items-start gap-3 cursor-pointer">
         <input
           type="checkbox"
           checked={fields.preserveImageContext}
           onChange={(e) => setField("preserveImageContext", e.target.checked)}
           disabled={isSubmitting}
           className="mt-0.5 h-4 w-4 rounded border-border-light bg-bg-surface text-accent-green focus:ring-accent-green/20"
         />
         <span className="text-text-primary text-sm font-body">
           Preservar imagem original
         </span>
       </label>
     )}
     ```
   - **Sempre invisível** quando `campaignIntent === "offer"`
   - **Visível e opcional** quando `spotlight` ou `exclusive`
   - **Reset para false** quando intent muda para offer — implementar no mesmo `useEffect` do badge cleanup

4. **Mudar label do badge select dinamicamente:**
   - Se `fields.campaignIntent === "offer"`: "Selo promocional *" (obrigatório)
   - Caso contrário: "Selo promocional (opcional)"
</action>

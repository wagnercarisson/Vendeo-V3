# Plan 31-3-01: Schema + Foundation

## Objective

Estender `ImageReviewInput` com `campaignIntent` e `preserveImageContext`; criar `ReviewIssueType` como union nomeada; migrar `failureType` de opcional para `string | null` explícito; adicionar `commercial_tone_mismatch`. Este plan não modifica comportamento de revisão — apenas contratos de tipo.

## Tasks

### Task 1: Estender ImageReviewInput

<read_first>
- src/lib/image-generation/services/image-review-service.ts (interface ImageReviewInput, linhas 11-18)
- openspec/changes/fase-31-3-quality-gate-por-intencao-comercial/specs/image-quality-review/spec.md
</read_first>

<action>
1. Em `src/lib/image-generation/services/image-review-service.ts`, alterar `ImageReviewInput`:
   ```
   De:
   export interface ImageReviewInput {
     productName: string;
     storeName: string;
     badgeText: string;
     originalPrice?: string;
     discountedPrice: string;
     validationContext?: ValidationContext;
   }

   Para:
   export interface ImageReviewInput {
     productName: string;
     storeName: string;
     campaignIntent?: CampaignIntent;
     preserveImageContext?: boolean;
     badgeText?: string;
     originalPrice?: string;
     discountedPrice?: string;
     validationContext?: ValidationContext;
   }
   ```
2. Adicionar `import type { CampaignIntent } from "@/lib/campaign/types";` no topo.
3. `campaignIntent` default conceitual é `"offer"` (default no schema, não no input).
4. `preserveImageContext` indica se o revisor deve permitir fundo contextual.
5. NÃO alterar `validationContext`.
</action>

<acceptance_criteria>
- `ImageReviewInput` pode ser construído sem `campaignIntent`, `preserveImageContext`, `badgeText`, `discountedPrice`
- `ImageReviewInput` com `campaignIntent: "exclusive"` é aceito
- `ImageReviewInput` com `campaignIntent: "spotlight"`, `badgeText: "Novidade"` é aceito
- `npm run typecheck` passa
</acceptance_criteria>

### Task 3: Migrar failureType para string | null

<read_first>
- src/lib/image-generation/schema.ts (linha 153, ImageReviewResult)
- src/lib/image-generation/services/image-review-service.ts (linhas 161-175, determineFailureType, linha 142-158, parseResult)
- openspec/changes/fase-31-3-quality-gate-por-intencao-comercial/specs/image-quality-review/spec.md
</read_first>

<action>
1. Em `src/lib/image-generation/schema.ts`, alterar `ImageReviewResult.failureType`:
   ```
   De: failureType?: "empty_review" | "insufficient_image" | "review_low_confidence" | "generated_product_mismatch";
   Para: failureType: "empty_review" | "insufficient_image" | "review_low_confidence" | "generated_product_mismatch" | null;
   ```
2. Em `src/lib/image-generation/services/image-review-service.ts`:
   a. Em `determineFailureType`: trocar todos os `return undefined` por `return null`.
   b. Em `parseResult`: trocar `failureType?:` por `failureType: ... | null`.
3. Atualizar consumidores em `image-generation-service.ts` que checam `failureType` — toda checagem `failureType` vs `undefined` deve tratar `null`:
   - `reviewResult.failureType ?? null` (já trata null)
   - `reviewResult.failureType === "generated_product_mismatch"` (funciona igual com null)
   - Verificar quaisquer `!== undefined` e trocar para `!== null`.
</action>

<acceptance_criteria>
- `ImageReviewResult.failureType` é `string | null` (nunca undefined)
- `determineFailureType` retorna `null` quando não há failureType aplicável
- `parseResult` retorna `failureType: null` quando `passed: true`
- Consumidores em `image-generation-service.ts` tratam `null` em vez de `undefined`
- `npm run typecheck` passa
</acceptance_criteria>

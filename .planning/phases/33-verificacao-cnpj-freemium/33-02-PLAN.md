  <action>
    Modificar POST /api/store:

    1. Após validação local de CNPJ (dígitos, F32) e normalização, adicionar step de verificação server-side:
       - Chamar CnpjVerificationService.resolve(cnpjNormalized)
    2. Se resolve retornar not_found → 400 com mensagem "CNPJ não encontrado na Receita Federal"
    3. Se resolve retornar unavailable → cria loja com verification_status = 'defer', sem grant, mensagem DEFER
    4. Se resolve retornar resolved:
       a. Resolver rootEligible: consultar freemium_entitlements WHERE root_hash = input.rootHash AND benefit_type = 'onboarding' — se exists, rootEligible = false
       b. Montar FreemiumEligibilityInput com rootEligible já resolvido
       c. Chamar evaluateFreemiumEligibility(input) (função pura síncrona do 33-01)
       d. Se decision = 'approve': verification_status='approved', grant concedido
       e. Se decision = 'review': verification_status='review', sem grant
       f. Se decision = 'reject': verification_status='rejected', sem grant
       g. Se decision = 'defer': verification_status='defer', sem grant
    5. Passar p_verification_status, p_verification_data, p_cnpj_official_data para RPC create_store_with_cnpj (já modificada na migration 33-01)
    6. Response inclui: onboardingGranted (boolean), verificationStatus (string), message (string por estado)
    7. Backend NÃO confia no estado do client — se client não enviar dados resolvidos, tenta resolve server-side
  </action>

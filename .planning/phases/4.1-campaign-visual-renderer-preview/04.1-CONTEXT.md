# Phase 4.1: Campaign Visual Renderer & Preview — Context

**Gathered:** 2026-05-26
**Status:** Ready for planning
**Source:** OpenSpec change `phase-4-1-campaign-visual-renderer-preview`

<domain>
## Phase Boundary

First visual rendering and preview flow for Vendeo V3. Transforms the `CampaignSpec` JSON (generated by Phase 3 API) into a visible 1080×1080 reference composition in the browser. Adds a preview page with quick local adjustments. Wires the existing form to navigate to preview on successful generation. No export, no persist, no approval, no database changes.

</domain>

<decisions>
## Implementation Decisions

### Rendering Approach
- CSS-based composition (Tailwind + aspect-ratio container) — not Canvas/SVG/HTML2Canvas
- Fixed 1080×1080 reference container scales responsively via `w-full max-w-[1080px] aspect-[1/1]`
- Zone positions use percentage-based sizing matching CAMPAIGN_VISUAL_SYSTEM.md zone distribution
- Phase 5 (export pipeline) will use a separate rendering engine

### Component Architecture
- `CampaignRenderer` — pure presentational component, no state or side effects
- `CampaignAdjustmentsPanel` — emits change events upward
- `PreviewPage` — owns adjusted state, orchestrates renderer + panel
- Separate from existing `components/flow/` — lives under `components/campaign/`

### Store Identity Flow
- `CampaignPageClient` resolves store identity once, passes `storeIdentity` prop through `CampaignInputForm` → `useCampaignForm`
- No extra fetch, no API change
- `StoreIdentitySnapshot`: `{ storeName, storeSegment, brandColor, logoUrl }`

### Preview Payload (sessionStorage)
```typescript
interface PreviewPayload {
  campaignSpec: CampaignSpec;
  storeIdentity: StoreIdentitySnapshot;
  productImageUrl: string | null;
  generatedAt: string;
}
```
- `productImageUrl` is existing client-side object URL from `URL.createObjectURL` — no file/blob/base64 stored
- Object URL NOT revoked on navigation to preview; revoked on new campaign/exit/tab close
- sessionStorage (not localStorage) — cleared on tab close

### Quick Adjustments (Local)
- Three override fields: title, discounted price display, badge text
- Pure client-side `useState` — no API calls
- Each field has undo button resetting to original spec value
- Price override is visual-only (`offer.discounted_price_display`), no recalculation

### Responsive Scaling
- Desktop: art left + panel right (≥768px)
- Mobile: art full-width, adjustments collapsed below (<768px)
- Font sizes use `clamp()` or relative units

### CampaignRenderer Zone Mapping
| Zone | Source |
|------|--------|
| Background | visual_parameters → segment palette (CAMPAIGN_VISUAL_SYSTEM.md §8) |
| Product image | `productImageUrl` from preview payload |
| Badge | `offer.badge_text` + `visual_parameters.badge_style` |
| Product name | `offer.product_name` |
| Price | `offer.original_price_display` + `offer.discounted_price_display` |
| Description | `commercial_copy.subtitle` |
| CTA | `commercial_copy.cta` |
| Store identity | `StoreIdentitySnapshot` |

### Empty/Error States
- No payload → "Nenhuma campanha encontrada" + CTA to campaign input
- Invalid/malformed payload → error state with retry/back
- Missing/invalid product image → explicit error state, no silent placeholder
- Unsupported `layout_preset` → fallback to Variation A (primary product-offer)

### Non-Goals (locked)
- No export/download of campaign image
- No persistence (database writes)
- No approval workflow or campaign history
- No multiple variation rendering (one layout per preview)
- No Canvas/SVG-based pixel-level rendering
- No API contract changes
- No new dependencies
</decisions>

<specifics>
## Specific Requirements

1. CampaignRenderer is a pure React component — no state, no side effects, no API calls
2. All visual zones follow CAMPAIGN_VISUAL_SYSTEM.md layout, typography, and color rules
3. Accent colors come from `visual_parameters`, segment palette, or brand color — never hardcoded except as fallback `#22C55E`
4. sessionStorage payload includes `campaignSpec`, `storeIdentity`, `productImageUrl`, `generatedAt`
5. During API generation: form fields and button disabled, payload frozen from submit-time state
6. Object URL lifecycle: revoked only on new campaign/preview exit, NOT on navigation to preview
7. No API changes — if data is missing client-side, stop and report the gap
</specifics>

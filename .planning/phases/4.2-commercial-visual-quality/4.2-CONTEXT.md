# Phase 4.2: Commercial Visual Quality — Context

**Gathered:** 2026-05-27
**Status:** Ready for planning
**Source:** OpenSpec change `phase-4-2-commercial-visual-quality`

<domain>
## Phase Boundary

Transform the current CampaignRenderer (Phase 4.1) — which uses a stacked/amateur CSS layout — into a professional, publishable commercial art engine for the `produto-oferta-comercial` template. The phase covers art direction, content/type expansion, renderer rewrite, and a validation gate. No export, no multiple templates, no visual editor, no database changes.

</domain>

<decisions>
## Implementation Decisions

### Art Direction First
- **4.2.0 Commercial Art Direction** is a **blocking prerequisite** for the renderer implementation. No CSS or component changes to CampaignRenderer shall begin before the visual contract is approved.
- The UI/UX Pro Max skill produces the contract: zone layout, hierarchy, image treatment, price block, CTA styling, store identity, and fallback rules.
- Contract output: `openspec/design-system/CAMPAIGN_ART_DIRECTION.md`

### Renderer Architecture
- Refactor in-place: rewrite `campaign-renderer.tsx` internals without changing the `CampaignRendererProps` interface (`spec`, `storeIdentity`, `productImageUrl`)
- Pure component: no side effects, no API calls, no state beyond logo `onError`
- Preserve responsive 1080×1080 container (`w-full max-w-[1080px] aspect-[1/1]`)
- Product image missing/null renders explicit error state (not a placeholder for publishable art)
- Unsupported `layout_preset` falls back to the default template

### Types & Adjustments
- `CampaignAdjustments` expanded: add `hook?: string` and `cta?: string`
- `mergedSpec` logic in PreviewPage expanded to merge hook and CTA adjustments
- CampaignAdjustmentsPanel gains: "Texto do Benefício" field (maxLength=120) and "Chamada para Ação" field (maxLength=60)
- All adjustments are local-only (no API calls), with undo buttons

### Mock Provider
- MockProvider already generates `commercial_copy.hook` and `commercial_copy.cta`, but values may be generic
- Improve hooks and CTAs per segment for better visual validation during development

### Image Treatment
- PreviewPage detects product image load failure (existing Phase 4.1 logic)
- When `productImageError === true`, PreviewPage passes `productImageUrl={null}` to renderer
- Renderer shows explicit error — no silent placeholder
- Campaign does NOT pass publishability gate without real product image

### the agent's Discretion
- Exact zone proportions, font sizes, spacing values (deferred to 4.2.0 contract)
- Color hierarchy: brandColor vs segment palette priority (deferred to 4.2.0 contract)
- Background visual treatment specifics (gradient, overlay, texture — deferred to 4.2.0 contract)
- Image treatment specifics (contain/crop ratio, shadow intensity — deferred to 4.2.0 contract)

</decisions>

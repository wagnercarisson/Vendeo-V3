<action>
Modify src/app/api/campaign/generate-image/route.ts:
1. Keep pre-stream validation: return 400 for missing fields, 409 for product_image_conflict/input_low_confidence, 413 for oversized payload — these do NOT open a stream
2. After validation passes, create a `ReadableStream` and return `new NextResponse(readableStream, { headers: { "Content-Type": "application/x-ndjson" } })`
3. Inside the stream, instantiate `ImageGenerationService` with `onPhaseChange` callback that writes NDJSON `{"type":"phase",...}` lines
4. Convert service success result to NDJSON `{"type":"result","success":true,"imageDataUrl":"...","inputCorrections":{...}}`
5. Convert service error result to NDJSON `{"type":"error","phase":"...","code":"...","message":"...","httpStatus":...}`
6. Write each event as a complete JSON line terminated by `\n`
7. Close the stream after the final event
8. Handle stream errors: write error event and close

Modify src/lib/image-generation/services/image-generation-service.ts:
9. Implement budget-aware retry: before each retry, compute `remainingTime = globalTimeout - elapsedTime`; skip retry if `estimatedRetryDuration > remainingTime`
10. Implement retry per spec policy:
    - `provider_error` (429/503/network): up to 2 retries, backoff 1s then 3s
    - `provider_timeout`: 1 retry, immediate, switch to fallback path
    - `no_image_in_response`: 1 retry, immediate, switch fallback model
    - `empty_review`: 1 retry, immediate, regenerate
    - `insufficient_image`: 2 retries, immediate, with correction instruction
    - `review_low_confidence`: 1 retry, immediate, with quality improvement instruction
11. Do NOT retry: `provider_auth_error`, `generated_product_mismatch`, `product_image_conflict`, `input_low_confidence`, `invalid_data`, `global_timeout`
12. Emit phase event with message "Tentando novamente..." during retry
13. Pass `attempt` counter to `ImageProviderInput` so provider can select primary vs fallback path
14. Pass global `AbortSignal` through to provider calls for cancellation support

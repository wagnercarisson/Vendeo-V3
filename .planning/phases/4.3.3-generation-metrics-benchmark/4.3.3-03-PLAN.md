### 3.3 Create benchmark CLI script

<read_first>

- src/lib/image-generation/providers/factory.ts

<action>
Create `scripts/benchmark.ts` with:

```typescript
import { BENCHMARK_SCENARIOS, BenchmarkScenario } from "./benchmark-scenarios";
import { createImageProvider } from "../src/lib/image-generation/providers/factory";
import { ImageGenerationService } from "../src/lib/image-generation/services/image-generation-service";
import { MetricsWriter } from "../src/lib/image-generation/metrics/writer";
import { IMAGE_GENERATION_RESPONSES_MODEL } from "../src/lib/image-generation/config";
```

CLI arguments (use `process.argv` or `yargs`-style parsing):
- `--provider <name>` — override IMAGE_PROVIDER (default from env)
- `--model <name>` — override model (default from env)
- `--delay <ms>` — delay between scenarios (default 2000)
- `--max-runs <number>` — max executions (default 25, protects cost)

Behavior:
- Invalid `--provider` → fail fast with error message and non-zero exit code
- Execute scenarios sequentially
- Each execution: construct `GenerateImageRequest` with fixture image (or placeholder base64), call `ImageGenerationService.generateImage()`, collect metrics
- Record each execution to `metrics/benchmark-{timestamp}.jsonl`
- After all scenarios: print formatted comparative summary table

Summary table columns:
| Scenario | Status | Time (s) | Cost ($) | Retries | Validation | Review |
</action>

<acceptance_criteria>
- `npx tsx scripts/benchmark.ts` runs all scenarios sequentially
- `--provider invalid` exits with error (no fallback)
- `--model gpt-5.5` overrides model
- Metrics written to `metrics/benchmark-{timestamp}.jsonl`
- Summary table printed to console
- `--max-runs` limit enforced
- `--delay` respected between scenarios
</acceptance_criteria>

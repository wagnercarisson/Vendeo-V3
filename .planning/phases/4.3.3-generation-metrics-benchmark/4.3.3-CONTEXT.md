# Phase 4.3.3: Generation Metrics, Provider Switch & Model Benchmark - Context

**Gathered:** 2026-05-30
**Status:** Ready for planning
**Source:** OpenSpec change `phase-433-generation-metrics-benchmark`

<domain>
## Phase Boundary

Refine the Phase 4.3.2 generation pipeline (mature, validated) with objective measurement infrastructure:

1. **Generation Metrics System** — automatic JSONL metrics recording per run (local/dev/benchmark only), best-effort, never blocks generation, sanitized data only
2. **Provider/Model Switch** — `IMAGE_PROVIDER` env var with factory pattern, image provider selectable via `.env.local`, validation/review models configurable via existing env vars
3. **Model Benchmark** — CLI script with 10 fixed scenarios, cross-model comparison, summary output
4. **Human-Friendly Progress UI** — separate technical metrics events from human messages, remove provider/model/runId/cost from UI, rotating professional messages
5. **Validation & Review Alignment** — preserve creative freedom when essential data is correct, never override price/product/store/legibility/conflict
</domain>

<decisions>
## Implementation Decisions

### Decision 1: JSONL metrics, local only, best-effort
- `GenerationMetrics` interface with optional fields per availability
- `MetricsWriter` with `fs.promises.appendFile`, try/catch, never blocks generation
- Code in `src/lib/image-generation/metrics/`, files in `/metrics/` root
- Production: disabled by default; if enabled, stdout only
- Sanitization: never log image base64, full prompt, API keys, payload, headers, provider response
- `runId` via `crypto.randomUUID()`, cost as `estimatedCostUsd` with `costEstimationSource`
- `/metrics/*.jsonl` added to `.gitignore`

### Decision 2: Provider switch via dedicated factory module
- `IMAGE_PROVIDER` env var in `config.ts` (values: `"openai"`, future `"gemini"`)
- `createImageProvider()` in `src/lib/image-generation/providers/factory.ts` — simple switch, no discovery pattern
- Route handler uses factory instead of hardcoded `OpenAIImageProvider`
- Invalid provider at runtime → warning + OpenAI fallback; invalid `--provider` in benchmark → fail fast
- Vision/review models remain as existing `VISION_REVIEW_MODEL` env var

### Decision 3: Two-layer progress architecture
- `onMetricsEvent` callback → technical data (runId, provider, model, elapsed, attempt, cost) — never exposed to UI
- `onPhaseChange` callback → human messages only (`GenerationPhaseEvent.message`)
- Rotating per-phase message set: professional, reassuring, non-technical
- Optional "Ver etapas da geração" panel (phase names + status only), collapsed by default

### Decision 4: Benchmark script
- `scripts/benchmark.ts` via `tsx` (verify or add as devDependency)
- 10 fixed scenarios in `scripts/benchmark-scenarios.ts`
- Accepts `--provider` and `--model`, sequential execution, configurable delay, max execution limit
- Output: `metrics/benchmark-{timestamp}.jsonl` + console summary table
- Fixtures in `scripts/benchmark-fixtures/` (gitignored if real test images)
- Gemini support documented as future capability (same scenarios, same metrics format)

### Decision 5: Creative freedom boundaries
- `applyValidationContextToReviewResult()` preserves creative freedom when price, product name, store name, legibility, and product×image match are correct
- Never overrides: `wrong_price`, `wrong_store_name`, `wrong_product_name`, `generated_product_mismatch`, `illegible_text`, strong product×image conflict
- Both `wrong_product_name` (non-terminal, triggers correction) and `generated_product_mismatch` (terminal) block
- Prompt changes only: `campaign-image-reviewer.md` (freedom boundaries), `campaign-image-director.md` (repertoire as inspiration)
- `creativeContextGuidance` variable considering segment + inferred category + conflict/alignment

### Decision 6: Non-goals (locked)
- No database tables for metrics
- No automatic provider fallback
- No metrics dashboard or analytics
- No export/download, captions, hashtags, supplementary text
- No art editor, no art variations
- No credit/plan system
- No legal terms implementation
- No Gemini implementation now
</decisions>

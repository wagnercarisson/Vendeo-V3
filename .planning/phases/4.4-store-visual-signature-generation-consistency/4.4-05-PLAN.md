<action>
Create `src/lib/visual-signature/server-actions.ts` with 4 exported async functions. All functions use `"use server";` directive (Next.js Server Actions).

**Helper: `getStore(storeId: string): Promise<Store>`** — fetches store from `supabaseAdmin.from('stores').select('*').eq('id', storeId).single()`. Throws if not found.

**1. `generateVariations(storeId: string): Promise<GenerateVariationsResult>`**:
- Validate storeId as UUID (regex check). Return error if invalid.
- Fetch store data via `getStore(storeId)` to get name, segment, brand_color.
- Initialize `AiImageGenerator` and `TypographicFallbackGenerator`.
- Define 3 tonalities for variation: `['profissional', 'moderno', 'elegante']`.
- For each tonality, attempt cascade:
  a. Try `AiImageGenerator.generate()` with `attempt: 0`, store data, that tone.
  b. If it fails, try once more with `attempt: 1` (retry with simplified prompt).
  c. If retry fails, generate `TypographicFallbackGenerator.generate()` to fill the slot.
- Collect results into an array of exactly 3 `CascadeResult` items.
- Per D-14 (3-card guarantee): if any position fails all cascade levels (including typographic — which should never fail since it's zero-dependency), return `{ success: false, error: "Não foi possível gerar 3 opções. Tente novamente." }`.
- Cards created by typographic fallback MUST show `tier: 'typographic'` in their metadata so the UI can show a "Simples" badge.
- Return `{ success: true, variations: CascadeResult[] }`.

**2. `generateAutomatic(storeId: string): Promise<{ success: true; signature: VisualSignatureRecord } | { success: false; error: string }>`**:
- Validate storeId. Fetch store data.
- Try `AiImageGenerator.generate()` with 30s timeout via `AbortSignal.timeout(30000)`.
- If that fails, retry once with `attempt: 1`.
- If retry fails, use `TypographicFallbackGenerator.generate()`.
- The result is persisted with `status: 'active'` (per D-11: automatic generation creates active directly) and `generation_mode: 'automatic'`.
- Return `{ success: true, signature: VisualSignatureRecord }` on success, or error.
- **Existing active handling**: Before generating, check if an active signature exists via `getActiveVisualSignature(storeId)`. If one exists, archive it first: `supabaseAdmin.from('store_visual_signatures').update({ status: 'archived', updated_at: new Date().toISOString() }).eq('store_id', storeId).eq('status', 'active')`. This prevents violating the partial unique index `WHERE status = 'active'`.

**3. `activateSignature(storeId: string, signatureId: string): Promise<{ success: true; signature: VisualSignatureRecord } | { success: false; error: string }>`**:
- Validate both UUIDs.
- Verify the signature exists and belongs to the given store (query `store_visual_signatures` with `.eq('id', signatureId).eq('store_id', storeId).single()`).
- If status is already `active`, return success (idempotent).
- **Atomic operation**: archive previous active, then activate the chosen one.
  a. Archive previous: `supabaseAdmin.from('store_visual_signatures').update({ status: 'archived', updated_at: new Date().toISOString() }).eq('store_id', storeId).eq('status', 'active')`
  b. Activate chosen: `supabaseAdmin.from('store_visual_signatures').update({ status: 'active', updated_at: new Date().toISOString() }).eq('id', signatureId)`
- Use `.select().single()` on the activate call and return the updated record.
- If archive step fails, throw/return error (rollback not supported via Supabase — caller can retry).
- Return `{ success: true, signature: VisualSignatureRecord }`.

**4. `listSignatures(storeId: string): Promise<VisualSignatureRecord[]>`**:
- Query `supabaseAdmin.from('store_visual_signatures').select('*').eq('store_id', storeId).order('created_at', { ascending: false })`.
- Return the array of records (may be empty).

Import all types from `./types`. Import generators from their modules. Import `supabaseAdmin as supabase` from `@/lib/supabase`. Import `Store` interface from `@/lib/store`.

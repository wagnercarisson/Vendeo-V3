# Phase 4.4: Plan 05 — Server Actions Summary

**Four server actions orchestrating the full visual signature lifecycle: 3-card guarantee variation generation, single automatic generation with cascade, atomic activation, and signature listing**

## Performance

- **Duration:** ~20 min
- **Started:** 2026-06-01T23:43:00Z
- **Completed:** 2026-06-01T23:47:00Z
- **Tasks:** 1
- **Files modified:** 1

## Accomplishments
- generateVariations(storeId): 3-card guarantee across 3 tonalities (profissional, moderno, elegante), each with AI → retry cascade, returns error if any slot fails
- generateAutomatic(storeId): single signature with AI → retry cascade, no typographic fallback, archives existing active before generation
- activateSignature(storeId, signatureId): atomic archive-previous → activate-new, idempotent if already active
- listSignatures(storeId): returns all signatures ordered by created_at desc
- Structured cascade error tracking with classifyError(), sanitizeErrorMessage(), CascadeAttempt metadata

## Decisions Made
- **generateAutomatic does NOT use TypographicFallbackGenerator** — per D-10 design decision, returns controlled error "Não conseguimos criar sua assinatura visual agora" on AI failure. This was a deliberate deviation from the original plan spec
- generateAutomatic returns `isFallback: boolean` field (not in original plan) — enables UI differentiation between AI-generated and simpler outcomes
- generateVariations timeout set to 120s per attempt (not 30s as in plan) — empirical observation that image generation can take 60s+
- Added `CascadeAttempt` tracking via `classifyError()` — classifies errors as `failed`, `rejected`, or `timeout` for structured metadata
- Error sanitization via `sanitizeErrorMessage()` masks API keys (sk-*), Bearer tokens, and URLs before logging
- generateAutomatic randomly selects one of 3 tonalities rather than generating for all 3
- generateVariations returns error state (not typographic fallback) when AI fails for a tonality — ensuring all 3 are AI-generated or none at all

## Deviations from Plan

**1. generateAutomatic does not use TypographicFallbackGenerator**
- **Issue:** Original plan specified cascade: AI → retry → typographic fallback. Design decision D-10 changed this: typographic fallback is NOT a success outcome for automatic generation
- **Fix:** generateAutomatic returns `{ success: false, error }` after both AI attempts fail, with descriptive PT-BR message
- **Files modified:** src/lib/visual-signature/server-actions.ts
- **Verification:** UAT test 8 documents this as intentional behavior

**2. Added isFallback field to generateAutomatic return type**
- **Issue:** Return type in plan didn't include isFallback; UI needed to distinguish fallback outcomes
- **Fix:** Extended return type to `{ success: true; signature: VisualSignatureRecord; isFallback: boolean } | { success: false; error: string }`
- **Files modified:** src/lib/visual-signature/server-actions.ts

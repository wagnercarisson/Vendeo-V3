# Phase 4.4: Store Visual Signature Generation & Consistency — Context

**Gathered:** 2026-06-01
**Status:** Ready for planning
**Source:** OpenSpec change artifacts + user context

<domain>
## Phase Boundary

Provide lojas sem logotipo com uma assinatura visual persistida e reutilizável, garantindo que campanhas futuras da mesma loja compartilhem identidade visual reconhecível, sem recriar marca por campanha.

Isso resolve o gap onde campanhas da mesma loja parecem vir de lojas diferentes por falta de identidade visual consolidada.

</domain>

<decisions>
## Implementation Decisions

### D-01: IA gera imagem diretamente (Abordagem B) como fluxo principal
- Prompt `visual-signature-generator.md` envia dados da loja (nome, segmento, cor principal, tom de voz) e pede imagem de assinatura visual (~1024×1024, fundo simples, sem produto/sem preço).
- O modelo de imagem (Responses API `image_generation` tool) gera o PNG diretamente.
- A imagem gerada passa por validação antes de persistir.
- Removido da V1: Abordagem A (IA descreve JSON → renderizador SVG monta) — falhou no quality gate por achatar expressão visual.

### D-02: Cascade de geração (2 níveis de fallback)
1. `AiImageGenerator.generate()` — IA gera imagem final diretamente
2. `AiImageGenerator.generate()` com prompt simplificado — retry único
3. `TypographicFallbackGenerator.generate()` — zero IA, iniciais + nome em SVG puro

### D-03: Fallback tipográfico em SVG puro, sem conversão PNG
- Fallback tipográfico é salvo como SVG direto no Storage (bucket `visual-signatures` já permite `image/svg+xml`).
- Sem conversão para PNG — zero dependências externas, confiabilidade máxima.
- PNG é para assinaturas geradas por IA; SVG para fallback tipográfico.

### D-04: generation_tier em metadata, não em coluna
- `metadata` (jsonb) inclui `generation_tier: "image_direct" | "image_retry" | "typographic"`
- `type` continua representando contexto geral (`ai_generated`, `automatic_generated`, `fallback_typographic`)

### D-05: Modal pós-save com 4 opções, sem close button
1. Gerar 3 opções para eu escolher — gera 3 variações, picker, persiste escolhida
2. Deixar o Vendeo escolher por mim — gera 1 automaticamente com cascade
3. Tenho logotipo, mas vou enviar depois — idêntico à opção 2
4. Tenho logotipo e quero enviar agora — redireciona para upload de logotipo

### D-06: Store visual signatures table
- Tabela `store_visual_signatures` (store_id FK, storage_path, asset_url, type, status, generation_mode, prompt, metadata, created_at, updated_at)
- Partial unique index `WHERE status = 'active'` — no máximo uma ativa por loja
- CHECK constraints para type, status, generation_mode
- `updated_at` trigger: `update_store_visual_signatures_updated_at()`

### D-07: Buckets Storage
- `visual-signatures` — assets de assinatura visual (PNG para IA, SVG para fallback). Já criado via migration `20260601000002`.
- `store-logos` — upload de logotipos. Migration `20260601000004` a ser criada (idempotente, public read, service_role policies).

### D-08: Prioridade na zona de identidade
1. `logo_url` — prioridade máxima
2. Active visual signature `asset_url` — usado quando não há logo
3. Fallback tipográfico — usado quando não há logo nem assinatura visual ativa

### D-09: Visual signature é render-time asset, não prompt injection
- Assinatura visual NÃO é injetada no prompt de geração de imagem do diretor de arte.
- É aplicada na renderização como asset fixo (pós-geração).
- Quando assinatura visual é usada, o nome da loja textual abaixo é omitido (asset já contém nome).

### D-10: Quality gate bloqueia integração com campanha
- 7.x tasks (campaign pipeline integration) tecnicamente implementadas mas marcadas como `[~]` (BLOCKED).
- Não são aceitas até quality gate visual passar (section 9 do tasks.md).
- CampaignRenderer renderiza apenas fallback padrão enquanto gate não passar.

### D-11: Ciclo de vida dos status
- `draft` → variações geradas para escolha
- `active` → a escolhida (ou fallback automático). No máximo 1 por loja.
- `archived` → desativada por substituição. Nunca reativada em V1.
- Fallback automático nasce como `active` direto.

### D-12: Troca de assinatura ativa com confirmação
- Na página da loja, seção "Identidade Visual" mostra assinatura atual.
- "Criar / Alterar Assinatura Visual" → abre modal.
- Ao escolher variação diferente → confirmação antes de trocar.
- Anterior vai para `archived`.

### D-13: Upload mínimo de logotipo
- Bucket `store-logos`, pasta `{store_id}/{uuid}.ext`
- Validação: tipo (PNG, JPEG, WebP), tamanho (máx 2MB)
- API route: `src/app/api/stores/[storeId]/logo/route.ts`
- Salva `logo_url` em `stores` (coluna já existe)
- Logo tem prioridade máxima sobre assinatura visual

### D-14: 3-card guarantee
- `generateVariations` MUST produzir exatamente 3 cards ou retornar erro
- Slots vazios preenchidos descendo na cascade
- Cards tipográficos mostram badge "Simples"

</decisions>

<specifics>
## Specific Requirements

1. **Database & Storage Setup** — migration for `store_visual_signatures` table already applied. Bucket `visual-signatures` exists. Need migration for `store-logos` bucket.
2. **Visual Signature Generator** — `AiImageGenerator` using Responses API `image_generation` tool. Prompt in `prompts/visual-signature-generator.md`. Validation before persist.
3. **Fallback Generators** — `TypographicFallbackGenerator` with SVG template (initials circle + name). Upload as SVG directly to Storage (no PNG conversion). `uploadToStorage()` and `persistSignature()` utilities.
4. **Server Actions** — `generateVariations(storeId)` (3-card guarantee), `generateAutomatic(storeId)`, `activateSignature(storeId, signatureId)`, `listSignatures(storeId)`. Atomic activate (archive → active).
5. **Store Identity Extension** — extend `resolveStoreIdentity()` for visual signature fallback. Extend `StoreIdentitySnapshot` type.
6. **UI** — 4-option modal (no close button), `VisualSignaturePicker` component, "Identidade Visual" section on store page, replace with confirmation.
7. **Logo Upload** — API route, bucket, validation, link to `stores.logo_url`.
8. **Campaign Pipeline Integration** — BLOCKED by quality gate. Extend `CampaignRenderParams`, load asset in render flow, update store identity priority.
9. **Quality Gate** — generate first visual signature and evaluate before accepting campaign integration.
10. **Validation** — manual visual tests for consistency, priority, cascade, replacement. typecheck, lint, build must pass.

</specifics>

**POST handler implementation:**

```typescript
export async function POST(request: NextRequest, { params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
```

Step-by-step within the handler function:

**1. Validate storeId as UUID**
- Regex `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i`
- Return 400: `{ error: "ID da loja inválido" }`

**2. Parse multipart form data**
- `const formData = await request.formData(); const file = formData.get('logo') as File | null;`
- Return 400 if no file: `{ error: "Nenhum arquivo enviado" }`

**3. Validate extension (client-visible error)**
- Check filename ends with .png, .jpg, .jpeg, or .webp (case insensitive)
- If extension is .svg (or not in allowed list), return 400: `{ error: "Formatos aceitos: PNG, JPG ou WEBP." }`

**4. Validate file size (5MB limit)**
- `file.size > 5 * 1024 * 1024` → return 400: `{ error: "Arquivo muito grande. Máximo 5MB." }`

**5. Convert to Buffer**
- `const buffer = Buffer.from(await file.arrayBuffer());`

**6. Server-side validation via sharp**
- Call `validateImage(buffer)` → if invalid, return 400 with appropriate error
- Call `getImageDimensions(buffer)` → get width/height
- Call `checkMinimumDimensions(width, height)` → if invalid, return 400: `{ error: "A imagem deve ter no mínimo 200x200 pixels." }`
- Call `computeChecksum(buffer)` → get SHA-256
- Extract extension from MIME: png → '.png', jpeg → '.jpg', webp → '.webp'
- Generate UUID for filenames: `const uuid = crypto.randomUUID();`
- Storage path: `{id}/original/{uuid}{ext}`

**7. Calculate next version**
- Query max version: `supabase.from('store_brand_assets').select('version').eq('store_id', id).order('version', { ascending: false }).limit(1).maybeSingle()`
- Next version: `(existing?.version ?? 0) + 1`

**8. ARCHIVE previous active assets (CRITICAL — must be BEFORE inserts per D-14)**
- `supabase.from('store_brand_assets').update({ status: 'archived', updated_at: new Date().toISOString() }).eq('store_id', id).eq('status', 'active')`
- `supabase.from('store_brand_profiles').update({ status: 'outdated', updated_at: new Date().toISOString() }).eq('store_id', id).eq('status', 'synced')`

**9. Upload original to storage**
- `const { error: uploadError } = await supabaseAdmin.storage.from('store-brand-assets').upload(storagePath, buffer, { contentType: file.type, upsert: false })`
- If upload fails: return 500 with error message

**10. Resolve public URL**
- `const { data: { publicUrl } } = supabaseAdmin.storage.from('store-brand-assets').getPublicUrl(storagePath);`

**11. Insert original asset record**
- `const { data: originalAsset, error: insertError } = await supabase.from('store_brand_assets').insert({ ...CreateBrandAssetInput }).select().single()`
- Return 500 on insert error
- CreateBrandAssetInput: store_id=id, asset_type='logo', variant_type='original', source='user_upload', parent_asset_id=null, storage_path=storagePath, mime_type=file.type, width, height, size_bytes=buffer.length, checksum, version=nextVersion, status='active'

**12. Generate all 5 technical variants**
- `const variantResults = await generateAllVariants(buffer);`
- Map results to insert promises (using Promise.allSettled for individual error handling):
  - For each successful variant: upload to storage `{id}/{variant_type}/{uuid}.png`, create asset record with source='system_generated', parent_asset_id=originalAsset.id, version=nextVersion, status='active'
  - For each failed variant: create asset record with status='failed', storage_path=null, metadata={ error: result.error }

**13. Execute Store Brand Director analysis inline (per D-07)**
- Fetch store data: `supabase.from('stores').select('*').eq('id', id).single()`
- Create BrandDirectorService, call analyze with original buffer + store data
- If analysis succeeds: create store_brand_profiles record with status='synced', active_logo_asset_id=originalAsset.id
- If analysis fails (BrandDirectorAnalysisError): create profile with status='failed', metadata containing error details

**14. Return 201 response**
```typescript
return NextResponse.json({
  originalAsset,
  variants: variantRecords,
  profile: createdProfile,
  version: nextVersion,
}, { status: 201 });
```

## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| Client → POST /logo | Untrusted file upload (multipart form-data) — validation chain entry |
| POST /logo → Supabase Storage | Uploaded files stored with service_role |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-4.4.1-04-01 | Spoofing | MIME type spoofing | mitigate | Dual validation: client extension check + server-side sharp MIME verification |
| T-4.4.1-04-02 | DoS | Oversized file | mitigate | 5MB check before sharp processing, reject early |
| T-4.4.1-04-03 | Tampering | Corrupted file | mitigate | sharp.metadata() check verifies file integrity |
| T-4.4.1-04-04 | Tampering | Variant generation partial failure | mitigate | Each variant handled independently with Promise.allSettled — one failure doesn't block others |
| T-4.4.1-04-05 | Tampering | Archive-then-insert race condition | mitigate | Archive operations complete BEFORE any insert (synchronous within same async handler) |
| T-4.4.1-04-06 | Tampering | Storage upload fails after DB insert | mitigate | DB insert happens after successful storage upload; if storage upload fails, no DB record created |
| T-4.4.1-04-07 | Tampering | Variant storage fails after DB insert for original | accept | Original already committed; variant failure is non-fatal per D-06 (variant recorded as failed) |
| T-4.4.1-04-08 | Information Disclosure | Logo image stored with public read | accept | Required for campaign rendering; logos are public brand assets |
| T-4.4.1-SC | Tampering | npm installs | mitigate | No new packages in this plan |
</threat_model>

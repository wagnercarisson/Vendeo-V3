<action>
Update resolveStoreIdentity to follow the 4-step resolution chain:

1. **Brand assets active (logo uploaded):** resolvedLogoUrl + brandProfile (source=logo_analysis) → return (existing behavior, unchanged)

2. **Active visual signature + brand profile (source=without_logo):** visualSignatureUrl + brandProfile → return BOTH in StoreIdentitySnapshot. The visualSignatureUrl fills the visualSignatureUrl field. The brandProfile provides campaign context. logoVariantUrl remains null.

3. **Brand profile (source=without_logo) without active signature:** store name text + brandProfile → return. The brand profile still provides campaign context (colors, style, tone) even without a visual asset. logoVariantUrl is null, visualSignatureUrl is null.

4. **Nothing:** store name + segment fallback → return (existing behavior)

Key additions to the current code:
- After checking for brand assets, also check for brand profiles with source='without_logo'
- If found: check for active visual signature
- If both exist: fill visualSignatureUrl + brandProfile
- If only brand profile: fill brandProfile (no visual asset)
- The brand profile must always be included when it exists (even when there's no visual asset), so the campaign director has brand context

Update the `StoreIdentitySnapshot` assembly to handle both paths without changes to the snapshot type itself — the fields already support this.
</action>

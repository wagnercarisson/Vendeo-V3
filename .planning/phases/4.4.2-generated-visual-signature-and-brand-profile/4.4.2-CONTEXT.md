# Phase 4.4.2: Generated Visual Signature & Brand Profile — Context

**Gathered:** 2026-06-03
**Status:** Ready for planning
**Source:** OpenSpec change artifacts (phase-4-4-2-generated-visual-signature-and-brand-profile)

<domain>
## Phase Boundary

Implementar o fluxo completo de identidade visual para lojas **sem logotipo**, incluindo:

1. Geração de assinatura visual profissional via IA (Store Identity Art Director) — prompt separado do diretor de campanhas
2. Modal de aprovação com até 3 tentativas sequenciais + feedback direcional
3. Inferência de brand profile a partir de dados cadastrais + outputs aprovados do diretor de identidade (Store Brand Profiler)
4. Persistência de status da escolha (uploaded / generated / explicit_none / failed / exhausted / null)
5. Métricas de geração (generation_events)
6. Fallback controlado: sem fallback tipográfico "bonitinho" — campo vazio = nome da loja em tipografia simples

</domain>

<decisions>
## Implementation Decisions

### D-01: Três papéis de IA distintos

| Papel | Prompt | Responsabilidade |
|-------|--------|------------------|
| Store Identity Art Director | `prompts/store-identity-art-director.md` | Criar assinatura visual + cartão de referência + metadados criativos. Recebe dados cadastrais + contexto de rejeição. |
| Store Brand Profiler | `prompts/store-brand-profiler.md` | Inferir brand profile a partir de dados cadastrais + outputs aprovados do identity art director. Executa após aprovação. |
| Campaign Image Director | `campaign-image-director.md` (inalterado) | Criar campanhas. **Nunca** cria identidade visual do zero. |

### D-02: Database — extensão de store_brand_profiles

CHECK constraint alterada para aceitar source `without_logo`:
```sql
CONSTRAINT chk_store_brand_profiles_source CHECK (source IN ('logo_analysis', 'without_logo'))
```

Novas colunas opcionais:
- `visual_signature_id` (uuid, FK → store_visual_signatures)
- `inferred_primary_color` (text)
- `inferred_accent_color` (text)
- `identity_art_director_output` (jsonb) — metadados criativos

### D-03: Database — novos campos em stores

- `logo_status` TEXT nullable (`'uploaded' | 'generated' | 'explicit_none' | 'failed' | 'exhausted' | null`)
- `visual_signature_attempts` INTEGER NOT NULL DEFAULT 0

### D-04: Database — tabela generation_events

Nova tabela para métricas de geração com CHECK constraints:
- generation_type: `visual_signature | brand_profile_without_logo | brand_profile_with_logo`
- status: `success | failed | rejected | timeout`

### D-05: UI — Step 2 "Logo e Cores" modificado

- Botão "Enviar logotipo" explícito
- Botão "Não tenho logo" (outline, ícone Sparkles) com tooltip explicativo
- Opção "Continuar sem logo" discreta (text-text-muted, sem destaque)

### D-06: Fluxo de geração — sequencial, 1 por vez

- "Não tenho logo" → gera 1 assinatura → modal de aprovação
- Aprovar → ativa assinatura + executa brand profiler + retorna ao form
- Rejeitar (attempts < 3) → feedback opcional → próxima geração com nova direção criativa
- Attempt 3/3 → botão "Não gostei" inativo + mostra 3 assinaturas para reavaliação
- "Continuar sem logo" → logo_status = explicit_none

### D-07: Ciclo de vida do asset

1. Gerar → salvar em store_visual_signatures com status `draft`
2. Aprovar → status `active`, anterior vira `archived`
3. Rejeitar → status `archived` com metadata rejected=true
4. Fechar modal sem decidir → permanece `draft`

### D-08: Persistência da assinatura aprovada

- Assinatura PNG em `visual-signatures/{store_id}/{uuid}.png`
- store_visual_signatures: type=ai_generated, status=active, generation_mode=user_choice
- stores.logo_status = generated
- stores.visual_signature_attempts = 0 (reset)

### D-09: Persistência do brand profile (sem logo)

- source = `without_logo`, active_logo_asset_id = null
- visual_signature_id = id da assinatura aprovada
- brand_colors_chosen preenchido com inferred colors
- status = synced
- Profile anterior synced → outdated (apenas se novo synced com sucesso)

### D-10: Erro controlado — sem fallback tipográfico

- Cenário A (erro técnico): logo_status = failed, "Tentar novamente" sem incrementar attempt
- Cenário B (limite esgotado): logo_status = exhausted, opções de reavaliação
- Nunca gerar fallback tipográfico artificial

### D-11: Resolução de identidade (resolveStoreIdentity)

1. store_brand_assets ativo (logo) → logoUrl, brandProfile (source=logo_analysis)
2. store_visual_signatures ativo + brandProfile (source=without_logo) → visualSignatureUrl, brandProfile
3. store_brand_profiles ativo (source=without_logo) sem assinatura → nome da loja, brandProfile
4. Nada → nome da loja, fallback por segmento

### D-12: Ordem de migrações

1. `20260603000001_alter_store_brand_profiles_source.sql` — altera CHECK, adiciona colunas
2. `20260603000002_add_store_logo_status.sql` — logo_status, visual_signature_attempts
3. `20260603000003_create_generation_events.sql` — tabela generation_events

### D-13: Métricas — best-effort

- generation_events insert nunca bloqueia geração
- Evento criado na geração, atualizado na aprovação/rejeição
- approved/rejected preenchidos apenas após decisão do lojista

</decisions>

## Specific Requirements

1. **Migrations (ordem rígida 3 arquivos):** alter store_brand_profiles CHECK → add columns → add logo_status/attempts → create generation_events
2. **Prompts:** store-identity-art-director.md + store-brand-profiler.md (ambos novos, PT-BR)
3. **Types Extensions:** logo_status type, signature input/output types, brand profiler types, generation event types, store extensions
4. **Store Identity Art Director Service:** cascade (tentativa → retry → erro), validar PNG, upload storage, persiste como draft
5. **Brand Profiler Service:** inline após aprovação da assinatura, persiste como synced/failed
6. **Generation Events Service:** best-effort insert, update on approve/reject
7. **API Endpoints:** generate-without-logo, reject, approve, brand-profile/generate-without-logo, logo-status, extend PATCH store
8. **UI:** botões no form, modal de aprovação sequencial, preview atualizado, cores preenchidas
9. **Identity Resolution:** 4-step chain com without_logo profile
10. **Error Handling:** failed vs exhausted, sem fallback tipográfico
11. **Verification:** typecheck, lint, build + 10 cenários de teste manual
</specifics>

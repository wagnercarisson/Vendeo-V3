# Phase 4.4.2: Generated Visual Signature & Brand Profile for Stores Without Logo — Research

**Researched:** 2026-06-03
**Domain:** Store identity resolution for stores without uploaded logo — AI-generated visual signature + brand profile
**Confidence:** HIGH (codebase patterns verified by reading actual files)

## Summary

Phase 4.4.2 extends the brand profile pipeline to support **stores without an uploaded logo**. Currently, `store_brand_profiles` has a `source CHECK (source IN ('logo_analysis'))` constraint — meaning only stores with uploaded logos can have brand profiles. 4.4.2 needs to:

1. Create a new prompt (`store-brand-director-without-logo.md`) that analyzes store data (name, segment, subsegment, direction fields) without a logo image and produces a brand profile.
2. Add a new `source` value (`store_analysis`) to the `store_brand_profiles` CHECK constraint.
3. Create or adapt the Brand Director AI service to work without a logo buffer.
4. Create a no-logo brand profile generation endpoint or server action.
5. Integrate visual signature generation (existing `AiImageGenerator` / `generateAutomatic`) as part of the no-logo brand profile creation flow.
6. Extend `resolveStoreIdentity` so stores without logos get their AI-generated visual signature and brand profile pre-resolved.

**Primary recommendation:** Follow 4.4.1 patterns exactly — replicate the architecture rather than invent new patterns. The source CHECK constraint change is the only migration needed; everything else is code.

## 8. Migration Pattern

### Existing migration structure:

```sql
-- Create the {table} table for {purpose}
-- Uses specific trigger function (NOT generic)

CREATE TABLE IF NOT EXISTS public.{table} (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  -- columns...
  CONSTRAINT chk_{table}_{field} CHECK (...)  -- inline CHECK constraints
);

-- Specific trigger function
CREATE OR REPLACE FUNCTION public.update_{table}_updated_at()
RETURNS TRIGGER AS $$ BEGIN NEW.updated_at = now(); RETURN NEW; END; $$ LANGUAGE plpgsql;

-- Trigger
CREATE TRIGGER trg_{table}_updated_at
BEFORE UPDATE ON public.{table}
FOR EACH ROW EXECUTE FUNCTION public.update_{table}_updated_at();

-- Partial unique index (most tables)
CREATE UNIQUE INDEX ON public.{table} (store_id) WHERE status = '{active_status}';

-- REVERT comments at bottom
```

**For 4.4.2 — Minimal migration:**
```sql
-- No new table needed. Just alter the CHECK constraint on store_brand_profiles.
ALTER TABLE public.store_brand_profiles
DROP CONSTRAINT IF EXISTS chk_store_brand_profiles_source,
ADD CONSTRAINT chk_store_brand_profiles_source CHECK (source IN ('logo_analysis', 'store_analysis'));
```

Alternatively, since the existing constraint uses `IN ('logo_analysis')`, the 4.4.1 migration already ran. We need a new migration to alter it.

**If storage is needed:** No new bucket required. `visual-signatures` bucket already exists for visual signature assets. `store-brand-assets` is only for uploaded logos.

### Pattern Decisions

**1. Brand Director for no-logo:**
- **Option A:** Add `analyzeWithoutLogo()` method to existing `BrandDirectorService`
- **Option B:** Create new `NoLogoBrandDirectorService` class
- **Recommendation:** **Option A** — simpler, single import, shared types. The analyze method signature differs (no buffer), so a separate method name is cleaner.

**2. No-logo generation flow:**
- Should generate BOTH brand profile AND visual signature in a single call
- Flow: analyze store data via LLM → get brand profile → pick tone → generate visual signature → persist both
- Return unified response: `{ brandProfile: BrandProfileRecord, signature: VisualSignatureRecord }`

**3. Migration minimalism:**
- Only 1 migration needed: alter the CHECK constraint on `store_brand_profiles.source`
- All other changes are code-only

**4. Visual identity priority for no-logo stores:**
```
AI-generated visual signature (active) + brand profile (synced) → 
typographic fallback (active) + brand profile (synced) →
text fallback (store name initials)
```

**5. resolveStoreIdentity changes:**
- When `resolvedLogoUrl` is null AND `brandProfile` exists with `source='store_analysis'`:
  - Return `brandProfile` (for campaign context) + `visualSignatureUrl` (active signature URL)
  - Both fields already exist in `StoreIdentitySnapshot`
- When no brand profile exists and no visual signature: trigger generation flow from UI

**6. Color source for no-logo:**
- `safe_color_tokens` comes from AI analysis (segment-based + store personality)
- `brand_colors_chosen[0]` → highest priority color
- Fallback chain: `brand_colors_chosen[0]` > `safe_color_tokens.primary` > segment fallback `SEGMENT_COLOR_FALLBACK`

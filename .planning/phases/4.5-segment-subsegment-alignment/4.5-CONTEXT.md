# Phase 4.5: Segment & Subsegment Alignment — Context

**Gathered:** 2026-06-11
**Status:** Ready for planning
**Source:** OpenSpec change artifacts (phase-4-5-segment-subsegment-alignment)

<domain>
## Phase Boundary

Realinhar o sistema de segmentos e subsegmentos da identidade da loja para refletir o perfil real do varejo brasileiro. O sistema atual (10 segmentos fixos + input text livre para subsegmento) gera dados inconsistentes que poluem os prompts de IA e dificultam agrupamentos futuros.

**O que esta fase entrega:**

1. Substituição de `VALID_SEGMENTS`/`SEGMENT_LABELS` (10 valores) por `STORE_SEGMENTS`/`STORE_SUBSEGMENTS` (13 segmentos com subsegmentos hierárquicos)
2. Dropdown condicional de subsegmento com 3 modos: dropdown rico (6 segmentos), dropdown travado (6 segmentos), campo aberto (segmento `outros`)
3. Comportamento "Outro" com validação client-side e server-side + sanitização
4. Atualização de fallbacks: `SEGMENT_COLOR_FALLBACK`, `SEGMENT_PALETTES`, `SEGMENT_HOOKS`, `SEGMENT_CTAS`
5. Migration SQL para atualizar CHECK constraint em `stores.segment`
6. Compatibilidade do `image-generation-service.ts` com a nova taxonomia
7. Atualização de API routes para validação com `STORE_SEGMENTS`
</domain>

<decisions>
## Implementation Decisions

### D-01: Estrutura unificada STORE_SEGMENTS + STORE_SUBSEGMENTS

Array `STORE_SEGMENTS` com `{ value, label }` + Record `STORE_SUBSEGMENTS` indexado por segment value. Tipo `StoreSegment` derivado. Único ponto de verdade.

### D-02: Três modos de UI para subsegmento

| Modo | Segmentos | Comportamento |
|------|-----------|---------------|
| Dropdown rico | `moda-calcados-acessorios`, `bebidas-adegas-conveniencia`, `padaria-confeitaria-doces`, `beleza-estetica`, `petshop`, `variedades-utilidades` | Dropdown com subsegmentos + "Outro" → texto livre obrigatório |
| Dropdown travado | `mercados-mercearias`, `restaurantes-lanchonetes`, `farmacia-saude`, `casa-decoracao`, `eletronicos-tecnologia`, `servicos-locais` | Dropdown desabilitado com única opção auto-selecionada |
| Campo aberto | `outros` | Input de texto obrigatório sem dropdown |

### D-03: Reset de subsegmento ao trocar de segmento

Ao mudar o segmento, `setField("subsegment", "")` e fechar campo "Outro".

### D-04: Validação do "Outro" — 2 camadas

**Client-side** (no blur e no submit): 3-30 chars, regex `/^[A-Za-zÀ-ü\s]+$/`, rejeitar genéricos (`outro`, `loja`, `comercio`, `comércio`, `varejo`).

**Server-side** (API routes): mesmas regras + sanitização: trim + reduzir espaços múltiplos + Capitalize.

O campo livre é obrigatório em dois cenários: (1) segmento rico + subsegmento `outro`, (2) segmento `outros`.

### D-05: Migration nomeada como `20260611000001_update_stores_segment_check.sql`

Dropar CHECK antiga, criar nova com os 13 valores. Base deve ser zerada antes (TRUNCATE).

### D-06: Placeholder sem exemplos

`"Digite o seu subsegmento"` — sem exemplos como "Ex: Artigos Esportivos" para evitar cópia literal.

### D-07: Fallback values de marketing

Todas as cores, hooks, CTAs e paletas são fallbacks — usados APENAS quando a IA não conseguir inferir valores próprios.

### D-08: Impacto na geração/IA — compatibilidade apenas

Esta fase não altera o contrato de dados do diretor de marketing (`segment`, `subsegment`). Apenas atualiza consumidores passivos: `image-generation-service.ts` (persona criativa, creative context guidance), prompts de IA, mappings auxiliares.
</decisions>

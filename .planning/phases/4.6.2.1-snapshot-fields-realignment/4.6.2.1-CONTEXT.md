<domain>
## Phase Boundary

**Propósito único:** Persistir os 7 campos textuais da loja nos snapshots de `store_brand_profiles.metadata` (`input_snapshot`, `drift_dismissed_snapshot`, `attempt_snapshot`) e estabelecer o helper único de construção de snapshot. A detecção de drift propriamente dita (usar esses snapshots para identificar desalinhamento) é fase 4.6.2.2 — **não está no escopo.**

**O que esta fase entrega:**

1. **`src/lib/snapshot.ts`** — `StoreProfileInputSnapshot` (7 campos), `SNAPSHOT_FIELDS` constante, `buildStoreProfileInputSnapshot(store)` helper
2. **`src/lib/drift.ts`** atualizado — `DriftSnapshot = StoreProfileInputSnapshot` (alias), `SNAPSHOT_FIELDS` importado, `DRIFT_FIELDS` provisório (4 campos, mecanismo transitório), `currentVisualState` simplificado (delega ao helper)
3. **6 endpoints** usando o helper em vez de construção inline
4. **Hook e formulário** atualizados para ler os 7 campos
5. **Testes mínimos** — helper, backward compat de leitura, novos campos inertes, ausência de falso drift por cor

**Não escopo:**
- Política de drift por `identity_state` (4.6.2.2)
- `CRITICAL_FIELDS` condicional (4.6.2.2)
- Testes de cenários de drift (4.6.2.2)
- Versionamento de snapshot
- Backfill de snapshots antigos
- `VisualSignatureMetadataInputSnapshot` (11 campos, sistema separado)
</domain>

<decisions>
## Implementation Decisions

### D1 — Helper único substitui construção inline

`buildStoreProfileInputSnapshot(store)` em `src/lib/snapshot.ts` centraliza a construção. Todos os endpoints usam o helper — sem mais `{ segment, subsegment, ..., brand_color, accent_color }` inline.

### D2 — `SNAPSHOT_FIELDS` ≠ `DRIFT_FIELDS` (transitório)

`SNAPSHOT_FIELDS` (7) define o que é capturado. `DRIFT_FIELDS` (4) é mecanismo transitório que mantém funções de drift existentes funcionando com o novo shape — não é política definitiva. A política de drift será definida na 4.6.2.2.

### D3 — `DriftSnapshot = StoreProfileInputSnapshot`

Alias type. Mesmo contrato. `brand_color` e `accent_color` deixam de fazer parte do snapshot.

### D4 — `currentVisualState` simplificado

Delega para `buildStoreProfileInputSnapshot(store)`. Sem parâmetro `profile` — cores eram dados derivados, não dados-fonte.

### D5 — VS snapshot preservado (11 campos)

`VisualSignatureMetadataInputSnapshot` em `visual-signature/types.ts` não é alterado. Sistemas separados.

</decisions>

  tone_of_voice: string | null;

  short_description: string | null;
  slogan: string | null;
}

export type StoredProfileSnapshot = Partial<StoreProfileInputSnapshot>;

export const SNAPSHOT_FIELDS = [
  'segment', 'subsegment', 'tone_of_voice', 'name',
  'positioning', 'short_description', 'slogan',
] as const;

export function buildStoreProfileInputSnapshot(store: Pick<...>): StoreProfileInputSnapshot

import { StoreProfileInputSnapshot, buildStoreProfileInputSnapshot, SNAPSHOT_FIELDS } from './snapshot';

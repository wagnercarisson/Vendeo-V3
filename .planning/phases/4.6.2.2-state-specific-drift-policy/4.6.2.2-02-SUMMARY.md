# Phase 4.6.2.2 Plan 02: Fundação do Diagnóstico — Onda 2 Summary

**One-liner:** Implemented state-specific drift policy foundation: replaced `DRIFT_FIELDS` with `getDriftPolicy(identityState, contentUsed?)` returning sensitive + critical field matrices for text_only, logo, and visual_signature states; added `evaluateCriticalDrift`, `evaluateSensitiveDrift`, updated `computeDriftStatus` with required `fields` param, created `drift-revalidator.ts`, expanded `drift-validator.ts` for absent properties, migrated all callers and tests.

## Objective

This wave delivers the full diagnostic logic that consumers (frontend, endpoints) will use. The drift detection system now operates on per-identity-state policies rather than a fixed 4-field constant.

## Changes by Task

### Tasks 1-4: Drift Policy Foundation in `src/lib/drift.ts` (commit `432764e`)

- **DriftCategory** type: `'critical' | 'sensitive' | 'none'`
- **DRIFT_POLICY** constant with 3 matrices:
  - `text_only`: 7 sensitive fields, 0 critical
  - `logo`: 6 sensitive fields (name excluded), 0 critical
  - `visual_signature`: 4 sensitive fields, `['name', 'segment']` + conditional fields based on `contentUsed`
- **getDriftPolicy(identityState, contentUsed?)**: returns `{ sensitive, critical }`. Falls back to text_only for unknown states. Conditionally adds slogan/city/state to critical for visual_signature.
- **evaluateCriticalDrift(vsSnapshot, contentUsed, store)**: compares VS input_snapshot (11 fields) against current store. Returns `{ hasDrift, fields }`. Skips absent snapshot properties. null snapshot → hasDrift: true.
- **evaluateSensitiveDrift(bpSnapshot, store, fields)**: compares BP input_snapshot (7 fields) using provided field list. Returns `{ hasDrift, fields }`. null snapshot → hasDrift: false.
- **computeDriftStatus** updated: now requires `fields: readonly string[]` parameter. No default — every caller must specify. Skips absent snapshot properties to avoid false drift from old snapshots.
- **DRIFT_FIELDS** removed — replaced by `getDriftPolicy().sensitive`.

### Task 5: Caller Migration (in commit `432764e`)

- **use-drift-detection.ts**: imports `getDriftPolicy` instead of `DRIFT_FIELDS`. Passes `getDriftPolicy(identityState).sensitive` as fields to `computeDriftStatus`. Hook signature extended with `identityState: string | null` parameter.
- **store-identity-form.tsx**: imports `getDriftPolicy`. Passes identity-state-derived fields to `computeDriftStatus` in `handleStep2Submit`.

### Task 6: Drift-Validator Expansion (commit `75dcca5`)

- `drift-validator.ts` types updated: `city`, `state`, `slogan` in `input_snapshot` marked as optional (`| undefined`) to reflect old snapshots without these fields.
- Comparison logic: each field checks for `undefined` before comparing. If property is absent, the field is skipped.
- If no properties were compared (`anyCompared = false`), returns `has_drift: false, reason: 'ok'`.
- 4 new test cases for absent property scenarios + 2 edge case tests.

### Task 7: Drift-Revalidator Creation (commit `ad047cd`)

- **drift-revalidator.ts**: NEW server-side function `revalidateCriticalDrift(input)` that wraps `evaluateCriticalDrift` and maps results to a typed `{ hasDrift, fields, reason }` format.
  - null/undefined snapshot → `reason: 'missing_metadata'`
  - Drift detected → `reason: 'critical_drift'`
  - No drift → `reason: 'ok'`
- **drift-revalidator.test.ts**: 6 tests covering all 3 result scenarios + content_used controls + absent property skipping.

### Task 8-9: Test Updates

  - 3 tests for `evaluateSensitiveDrift` (null snapshot + field list filtering + absent properties)
  - All existing `computeDriftStatus` tests migrated to pass explicit fields parameter

## Deviations

### [Rule 1 - Bug] computeDriftStatus did not skip absent properties

**Found during:** Task 10 verification gate (test failures in drift.test.ts)

**Issue:** The original `computeDriftStatus` treated `undefined` snapshot values as `null` (via `?? null`), converting them to empty string via `normalizeSnapshotValue`. This caused legacy snapshots without certain fields (like `positioning`, `short_description`, `slogan`) to falsely trigger drift detection when compared against current store values.

**Fix:** Added an explicit `undefined` check at the start of the field comparison loop in `computeDriftStatus` — if `inputSnapshot[f] === undefined`, the field is skipped entirely. This matches the behavior already present in `evaluateSensitiveDrift` and `evaluateCriticalDrift`.

**Files modified:** `src/lib/drift.ts`, `src/lib/__tests__/drift.test.ts`

**Commit:** `92bb09b`

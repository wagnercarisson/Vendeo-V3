<action>
Expandir GET /api/store/[id]/visual-signature (route.ts) para incluir `critical_drift` no response.

Para cada signature no array:
- Se for a assinatura ativa (status === 'active'), calcular critical_drift:
  - Ler `restore_eligibility.reason` (já computado)
  - reason === 'ok' → status: 'none'
  - reason === 'critical_drift' | 'missing_metadata':
    - Verificar se `visual_signature_drift_dismissed_snapshot` existe em `metadata`
    - Se existir e bater com store atual → status: 'dismissed'
    - Se não bater ou snapshot ausente → status: 'new'
  - Incluir `fields` do restore_eligibility.drift_fields e `reason`
- Para assinaturas não-ativas: critical_drift: null

Formato:
```typescript
critical_drift: {
  status: 'none' | 'new' | 'dismissed'
  fields: string[]
  reason: 'ok' | 'critical_drift' | 'missing_metadata'
} | null
```

O cálculo de dismiss usa normalizeSnapshotValue para comparação. O dismissed_snapshot pode ter menos campos que a store atual — campos ausentes no snapshot são skipados.
</action>

- Archived signature → critical_drift nulo
- Sem drift → status: 'none'
- Drift sem dismiss → status: 'new'
- Drift com dismiss matching → status: 'dismissed'
- Missing metadata → status: 'new', reason: 'missing_metadata'
- `npm run typecheck` passa

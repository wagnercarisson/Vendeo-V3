**Estratégia por identity_state (servidor decide exclusivamente):**

```typescript
const strategy = {
  text_only: () => BrandTextOnlyInferenceService.infer(store),
  logo: () => BrandDirectorService.analyze(store, logoAsset),
  visual_signature: () => BrandProfilerWithoutLogoService.generate({
    ...input,
    mode: 'regenerate',
    // content_used lido da VS metadata, NÃO do perfil anterior
  }),
}[identity_state]();
```

**Regra de compensação: o serviço de inferência é dono da persistência.**
O endpoint NÃO cria uma segunda inserção — ele apenas:
1. Determina a estratégia por identity_state
2. Prepara os inputs (content_used da VS, etc.)
3. Chama o serviço de inferência
4. Retorna o resultado

**Para text_only e logo:** os serviços existentes (BrandTextOnlyInferenceService, BrandDirectorService) já gerenciam sua própria persistência com compensação (implementada nas fases 4.6.1 e 4.6.3).

**Para VS (profiler):**
- O profiler (mode:'regenerate') assume a responsabilidade pela compensação:
  1. Inferir todos os campos brand (ignorando cache)
  2. Marcar perfil anterior synced como outdated
  3. Inserir/atualizar novo perfil com status 'synced'
  4. Se insert falhar: restaurar perfil anterior para 'synced'
  5. Atualizar input_snapshot com valores atuais da store
- O endpoint NÃO faz marcação/inserção separada — o profiler é o dono da escrita.

**VS path específico:**
- Localizar VS ativa (store_visual_signatures com status 'active')
- Ler `content_used` de `metadata.artDirectorOutput.content_used`
- Passar content_used para o profiler (mode 'regenerate')
- Preservar identity_state = 'visual_signature'
- Preservar visual_signature_id no BP
</action>

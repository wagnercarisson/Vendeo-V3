1. Aceitar `mode: 'standard' | 'substitution'` no body (opcional, default 'standard')
   Payload: `{ signatureId: string, mode?: 'substitution' }` (camelCase)

2. Implementar guardas para mode:'substitution':
   ```typescript
   if (mode === 'substitution') {
     // 1. signatureId corresponde a uma VS pendente para esta store
     // 2. identity_state === 'visual_signature'
     // 3. VS ativa existe (a que será arquivada)
     // 4. Drift crítico revalidado — contra a VS ATIVA, não contra signatureId
   }
   ```

3. Fluxo de aprovação substitution (dois tiers):

   **Tier 1 — Archive/Activate (compensação):**
   a. Revalidar drift crítico contra VS ativa
   b. Confirmar signatureId pendente
   c. Arquivar VS anterior: status 'active' → 'archived'
   d. Verificar resultado — se archive falhar, abortar
   e. Ativar nova VS: status 'draft' → 'active'
   f. Se ativação falhar: RESTAURAR VS anterior para 'active'
   g. Se restauração bem-sucedida: retornar erro (VS ativa, nova não ativa)
   h. Se restauração falhar: retornar erro crítico (intervenção manual necessária)

   **Tier 2 — BP Generation (fallback, não desfaz ativação):**
   i. Executar BrandProfilerWithoutLogoService.generate() (fluxo NORMAL, mode:'reuse')
   j. Se BP falhar: NOVA VS PERMANECE ativa. Perfil anterior permanece synced.
   k. Retornar HTTP 200 com warning. BP pode ser retentado.
   l. Se BP insert falhar: restaurar perfil anterior para 'synced'. Nova VS ativa.

   **Importante:** NÃO chamar identity-transitions. Estado permanece 'visual_signature'.

4. Mode 'standard': comportamento atual inalterado
</action>

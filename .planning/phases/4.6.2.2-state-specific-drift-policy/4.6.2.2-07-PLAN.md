11. Drift sensível (VS) → manter → dismiss salvo

13. Sem drift → salvar direto

Documentar cada cenário com PASS/FAIL.

</read_first>
<action>
UAT — Cenários de falha e borda:

**Compensação:**
14. Falha Tier 1 (archive → activate → restore): ativação falha → VS anterior restaurada
15. Falha Tier 2 (profiler fail + insert fail): nova VS ativa, BP anterior synced, bp_status:'failed'

**Retry BP (pós-Tier 2):**
16. Retry via POST /brand-profile/realign → Ramo C: INSERT novo BP, fallback anterior outdated
17. Retry com BP failed existente → Ramo B: fallback outdated, UPDATE target para synced
18. Falha no UPDATE/INSERT do retry → fallback restaurado para synced

**Limite:**
19. Limite de 3 gerações: substitution bloqueia em 3 signatures
20. Falhas não contam: 2 sucesso + 1 falha = permitido (2 < 3)

**Regressão:**
21. Aprovação standard inalterada: text_only → visual_signature
22. Fluxo normal de remoção VS → text_only

**Badge:**
23. Badge "Desalinhado" apenas quando effectiveStatus === 'new' (não dismissed)
24. Nenhum badge quando sem drift

**Backward compatibility:**
25. VS snapshot antigo (sem city/state) → não dispara falso drift
26. BP snapshot antigo (poucos campos) → não dispara falso drift

**Invariantes:**
27. identity-transitions NÃO chamado na substituição
28. Save nunca bloqueado (apenas orientado)
29. Drafts históricos NÃO bloqueiam substituição
30. NUNCA duas VS active simultaneamente
</action>

- Retry BP verificado nos Ramos B e C

## Deviations from Plan

### Typecheck/Build Gate Failures (Pre-existing)

The typecheck and build gates fail due to 8 pre-existing type errors from implementation waves. The UAT plan objective explicitly prohibits code modifications ("Nenhuma modificação de código — apenas teste e documentação"). These errors:

- Are **not caused by this plan's changes** (this plan makes zero code modifications)
- Are in files modified by Waves 4, 5, and 6
- Should be corrected in a follow-up fix plan targeting the 3 files: `realign/route.ts`, `approve/route.ts`, `store-preview.tsx`
- Do not affect runtime behavior: all 268 unit tests pass, confirming logical correctness

**Root cause analysis:**

1. **`realign/route.ts` (490-496)**: `vsRecord.metadata.artDirectorOutput` is typed as `VisualSignatureArtDirectorOutput | VisualSignatureMetadataArtDirectorOutput`. These interfaces only share `visual_direction`; `creative_description`, `suggested_colors`, and `elements_used` exist only on `VisualSignatureArtDirectorOutput`. Fix: cast or narrow the union before property access.

2. **`approve/route.ts` (206)**: `artDirectorOutput` variable typed as `{}` (empty object) from `pendingMetadata.artDirectorOutput ?? { ... }` where `pendingMetadata` is `Record<string, unknown>`. Fix: cast the fallback to `VisualSignatureArtDirectorOutput`.

3. **`approve/route.ts` (228)**: `buildStoreProfileInputSnapshot(store)` where `store` is `Record<string, any>`. Fix: cast `store` to `Pick<Store, ...>` or add type annotation.

4. **`store-preview.tsx` (125)**: After TypeScript narrows `criticalDrift?.status` via `=== 'new'` check on line 123, the `else` branch has type `'none' | 'dismissed' | undefined` which has no overlap with `'new'`. The condition is dead code (always true) but logically correct at runtime. Fix: remove redundant `criticalDrift?.status !== 'new'` check since it's always true after the `===` check fails.

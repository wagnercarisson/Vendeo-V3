<action>
Manual validation — Substitution flow (controlled backend failure):

1. Run the application
2. Navigate to a store with active VS (identity_state = 'visual_signature')
3. Ensure the store has critical drift (e.g., change store.name in DB or via UI)
4. Open Step 2 → click "Gerenciar assinatura visual"
5. DriftCriticalModal appears → click "Atualizar"
6. VisualSignatureApprovalModal opens in substitution mode
7. **Induce a controlled backend failure that traverses the normal error path** — the failure must happen DURING generation so the code reaches the error handler at line 394-408 (where the `logo_status` protection lives):
   - Set `OPENAI_API_KEY` to an invalid value (e.g., `sk-invalid`), restart the dev server, then trigger the substitution flow. The AI call will fail, the route will catch it at line 394-408, and the `logo_status` guard will execute with the real condition
   - This path uses OpenAI (not Anthropic) — only `OPENAI_API_KEY` is relevant
   
   **Do NOT** use an early `return 500` before the AI call — that would bypass the error handler and the `logo_status` guard, making the test pass even without the fix.
   **Do NOT** disconnect the network — the request must reach the server for the fix to be exercised.
8. Observe the error phase:
   - Secondary button says "Cancelar"
   - Primary button says "Tentar novamente" — because the error is from generation failure, NOT from drift detection. In substitution mode, `generate()` is called immediately (line 189-192); if it fails, `state.drift` is NOT set.
9. Click "Cancelar"
10. Verify:
    - Modal closes
    - No new request initiated by the click
    - Step 2 still shows the VS active and intact
    - Database: `logo_status` continues as `"generated"` (not overwritten to "failed")
    - Database: `identity_state` remains `"visual_signature"`
11. Remove the temporary modification after validation

Document the result in the plan summary.
</action>

- `logo_status` in DB is still `'generated'` (not `'failed'`)
- `identity_state` in DB is still `'visual_signature'`
- Primary button shows "Tentar novamente" (generation error, no drift object)
- Secondary button shows "Cancelar"

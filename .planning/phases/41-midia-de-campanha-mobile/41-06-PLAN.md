| T-41-06a | DoS | Payload de imagens | mitigate | Limites por item (4MB) + teto agregado (8MB) → 413 PT-BR antes de qualquer IA/stream (D10); `MAX_CAMPAIGN_IMAGES = 4` no zod limita o array |
| T-41-06b | Tampering | IDs de imagem | mitigate | Ids gerados pela ROTA (`crypto.randomUUID()`), nunca do cliente — cliente não envia `id` (D2/D5); path de storage `{imageId}` sob controle do servidor |
| T-41-06c | Tampering | Uploads pré-stream | mitigate | `uploadCampaignInputImage` via supabaseAdmin (service_role), bucket privado, `upsert: false`; path com prefixo `storeId` preserva owner select (D5) |
| T-41-06d | DoS | Inputs órfãos | mitigate | `removeCampaignInputs` em falha pré-stream (sem órfãos); falha pós-stream → `deleteCampaignImage` atual (D5) |
| T-41-06e | Tampering | Snapshot storagePath | mitigate | storagePath preenchido no runtime tipado (`CampaignProductImageInput`) após upload verificado — antes do snapshot (D5, sem cast) |
| T-41-06f | Spoofing | Validação primária-only | mitigate | `inputValidation.validate` recebe APENAS a primary (posição 0) — auxiliares não participam; fluxo de 409 inalterado (D8) |
| T-41-06g | Tampering | Telemetria | accept | Uploads não geram eventos de custo; `recordCall` permanece 1 evento `campaign_image` (D7) |

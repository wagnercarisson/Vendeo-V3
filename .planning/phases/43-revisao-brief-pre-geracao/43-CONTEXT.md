## Phase Boundary

Hoje o clique em **"Criar Campanha"** (`campaign-input-form.tsx:605-631`, texto em `:629`) dispara imediatamente o `POST /api/campaign/generate-image`, que já no pré-stream **chama IA de visão** (`InputValidationService`, `route.ts:337-399`, gate em `:338`), **cria a campanha** no banco (`:401-445`) e **reserva crédito** (`:447-476`) — tudo **antes** de o usuário ver um resumo do que será gerado. A F43 inverte isso: **revisão humana obrigatória em tela intermediária (`reviewMode`, não modal) antes de qualquer chamada de IA, reserva de crédito ou persistência**, tornando o fluxo mais honesto para o lojista e mais barato para o produto.

## Constraints

- **Migration SQL limitada à flag admin (D5)** — **NENHUMA** mudança no domínio da campanha (snapshot `campaign_brief_v1`, `campaigns`, storage, RLS intocados — revisão é client-side pura). A **única** migration é a criação/uso da tabela `feature_flags` + RPC + extensão dos CHECKs de `admin_audit_log`. Ordem de deploy fail-closed: migration → código → smoke → UAT → produção.
- **`feature_flags` é greenfield** — tabela **nova** (não existe em `supabase/migrations/`). Criar `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`, `key TEXT UNIQUE NOT NULL`, `enabled BOOLEAN NOT NULL DEFAULT false`, `description TEXT`, `updated_by UUID NULL REFERENCES auth.users(id)`, `updated_at TIMESTAMPTZ DEFAULT now()`. Seed `force_brief_vision_check` (`enabled=false`). RPC `admin_update_feature_flag` transacional/idempotente com **motivo obrigatório** + auditoria na mesma transação.
- **CHECKs de `admin_audit_log` estendidos (D5)** — nova action `feature_flag_update` + novo `target_type` `feature_flag` via `ALTER TABLE ... DROP CONSTRAINT IF EXISTS / ADD CONSTRAINT` (precedente `20260810010000_create_access_requests.sql:146-163`), preservando valores existentes.
- **`id` UUID PK obrigatório** — `admin_audit_log.target_id` é `UUID NOT NULL` (`20260718000001_create_admin_tables.sql:25`); a auditoria referencia `target_id = feature_flags.id` e identifica a flag via `metadata.key`.
- **Override `brief_review_confirmed` com semântica distinta de `user_confirmed_continue`** — matriz documentada no schema e nos testes (ver D5 no `<decisions>`).
- **Fase `input_validation` `skipped` obrigatório quando override pula** — `ImageGenerationService` Phase 1 (`:162-277`) NUNCA emite `running → complete` nem `complete` com detail sem chamada real; usa `emitSkipped` (`:141`) com detail opcional. Aplica-se a `brief_review_confirmed` E `user_confirmed_continue`.
- **Flag ligada normaliza o input na rota** — remove `brief_review_confirmed` do `inputValidationOverride` **antes** de `route.ts:338` e usa o mesmo `effectiveParsedData` para a checagem, o brief e `generateImage`; `user_confirmed_continue` **nunca removido**.
- **Fallback de leitura da flag não derruba geração** — falha na leitura → `enabled=false` (fluxo padrão pula vision), log warning; env var `VENDEO_FORCE_BRIEF_VISION_CHECK=true` só como fail-safe emergencial (pode forçar `true`).
- **`buildCampaignGenerationBody` espelha a lógica XOR atual do body** (`use-campaign-form.ts:906-917`) — `productImages[]` (sem `id`) quando `preparedImages.length > 1`; `productImageDataUrl` quando 1 (legado). Idempotente com o que a revisão mostra.
- **`prepareCampaignImages` não re-comprime itens de draft com `dataUrl`** — só normaliza `mimeType` para `image/jpeg` e preserva `role`/`source`.
- **Tela intermediária NÃO modal (D2)** — `reviewMode` no mesmo fluxo (padrão `isSubmitting` → `GenerationProgress`); modal aperta no mobile e piora acessibilidade.
- **Revisão mostra o payload final (D3)** — compressão ANTES da revisão; o que o usuário vê é o que será enviado; submit deixa de re-comprimir.
- **Preview das imagens sem recorte (D7)** — `object-contain` em célula `aspect-square`; nunca cortar a imagem visualmente, especialmente no mobile.
- **`StoreIdentityBlock` com snapshot real resolvido no server (decisão do usuário 2026-08-21)** — a identidade exibida no topo da revisão é o snapshot real resolvido em `src/app/(app)/campanhas/nova/page.tsx` via `resolveStoreIdentity(store)` (+ `validateIdentityReference`), propagado por `CampaignPageClient` → `CampaignInputForm` → `campaign-brief-review` → `StoreIdentityBlock({ store, identity })` — mesma fonte canônica da geração; **sem** fallback visual "nome/segmento/cor do form" como caminho principal (evita divergência entre o que o usuário viu e o que a geração usou).
- **`GenerationProgress` ganha estado `skipped` no indicador principal** (`generation-progress.tsx:86-103`) — hoje só o painel colapsável trata `skipped`.
- **Slot Tema reservado (D6)** — não renderiza enquanto `themeId` null (hoje sempre); preparação para a F44 (não é desta fase criar a seção funcional).
- **Comportamento de refresh na revisão preservado** — limpeza de draft no mount (`campaign-page-client.tsx:19-25`); retenção da revisão em `sessionStorage` é decisão de planejamento, não exigência.
- **Artefatos históricos não são reescritos** na renumeração D1; `openspec/changes/fase-43-revisao-brief-pre-geracao/` é a fonte da verdade.

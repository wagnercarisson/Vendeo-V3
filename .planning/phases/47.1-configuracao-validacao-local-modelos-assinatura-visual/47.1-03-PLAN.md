    Criar `src/lib/ai-cost/visual-signature-usage.ts` puro (sem I/O), preservando o `usage` bruto sanitizado para auditoria. Normalizar `I=input_tokens`, `O=output_tokens`, `C=cached_input_tokens`, `IT/II` de `input_tokens_details.text_tokens/image_tokens`, `OT/OI` de `output_tokens_details.text_tokens/image_tokens`, `R=reasoning_tokens`, `Ct/Ci` de cache atribuível quando o provider detalhar, e usage da tool quando presente.

    Implementar `normalizeVisualSignatureUsage(raw)` que valida consistência: `C <= I`, `R <= O`; breakdown só é utilizável quando `IT + II` é compatível com `I` e `OT + OI` é compatível com `O`; caso contrário marca o breakdown como inconsistente e não o usa para completar custo. Nunca converter ausência em zero silencioso.

    Implementar `computeVisualSignatureCost({usage, rates, providerReportedCostUsd, preset})` retornando `{ estimatedCostUsd: number | null, costCoverage: 'complete'|'partial'|'unknown', costSource: 'pricing_table'|'provider_reported'|'not_available', costEstimationNote: string | null, components }` e aplicando as fórmulas A–E do design:
    (A) breakdown completo: `(IT-Ct)*input_text_rate + Ct*cached_text_rate + (II-Ci)*input_image_rate + Ci*cached_image_rate + OT*output_text_rate + OI*output_image_rate`, sem adicionar unitário histórico; complete somente com todas as tarifas e atribuição de cache.
    (B) totais + reasoning: `(I-C)*input_rate + C*cached_rate + O*output_rate`; nunca somar reasoning de novo; sem breakdown de imagem, não adicionar unitário histórico nem inventar componente de imagem; complete só se a imagem estiver comprovadamente incluída ou houver custo reportado.
    (C) totais com usage de tool separado: fórmula de B sobre os totais do orquestrador EXCLUINDO o usage da tool; tool precificada uma vez; complete só com exclusão e tarifas comprovadas.
    (D) custo reportado: retornar `provider_reported` e manter estimativa separada; não somar componentes ao reportado.
    (E) campos ausentes/ambíguos: apenas componentes confirmados; `partial`/`unknown` com motivo; nunca inventar total.
    Regras: `R` é precificado dentro de `O` uma única vez, salvo declaração explícita do provider de que está fora de `O` (então uma única vez na tarifa documentada); se só houver `C` total sem atribuição texto/imagem, cobertura parcial; sem usage suficiente, a referência histórica pode ser registrada UMA vez na nota `visual_signature_image_estimate_no_usage`, com `estimatedCostUsd=null`, `costSource='not_available'` e `costCoverage='partial'`, nunca junto de componentes de tokens nem persistida como custo real; ambiguidade insolúvel → `costSource='not_available'` com motivo.

    Testes: reasoning não duplica output; cache não duplica input; imagem separada do texto; `Ct`/`Ci`; cache sem atribuição; apenas totais; breakdown inconsistente; reasoning fora do output; output ausente; custo reportado separado; sem usage com referência única na nota, `estimatedCostUsd=null`, `costSource='not_available'` e `costCoverage='partial'`.

|----------|------------|-----------|
| provider → estimador | usage/custo | Dados de usage podem vir incompletos ou ambíguos; não podem gerar total inventado. |
| pricing operacional → custo | `ai_model_pricing` | Tarifa ausente não pode ser substituída silenciosamente. |
| telemetria → auditoria | sink | Custo estimado e reportado não podem se sobrescrever. |

| Threat ID | Categoria | Componente | Disposição | Mitigação |

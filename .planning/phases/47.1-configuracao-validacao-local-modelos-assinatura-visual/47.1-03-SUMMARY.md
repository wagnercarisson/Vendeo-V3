# Phase 47.1 Plan 03: Usage, pricing e percurso completo do custo

## One-liner

Usage normalizado com tarifas separadas de orquestrador e imagem/tool, fórmulas A–E sem dupla contagem nem cache inventado, cobertura honesta e percurso resposta → gateway → estimador → evento fechado — com `maxRetries=0`, auditoria de tentativa/credencial e sem `0.065`/`fallback_static` no caminho com preset.

## Status

**Corrigido em 2026-10-22 após segunda revisão bloqueante; aguardando nova revisão do Codex.** O plano 47.1-04 **não foi iniciado**.

## Correções da revisão (5 achados)

1. **Tarifas do orquestrador × imagem/tool separadas.**
   - `getVisualSignatureOrchestratorPricing` lê `params.model` (GPT-5.5/Luna) sem `quality`.
   - `getVisualSignaturePresetPricing` lê somente a imagem por `(provider, model, quality)`.
   - Cada componente usa sua própria tarifa; as versões ficam em `orchestratorPricingVersion`/`imagePricingVersion`.
   - A tarifa única de imagem do schema NÃO é copiada para entrada E saída: com ambas as direções, a cobertura é `partial` (`image_rate_direction_unproven`).
2. **Fórmula C sem imagem contada como texto.**
   - Tool com `output_tokens` + `output_tokens_details.image_tokens` deriva o texto por subtração (`total - imagem`), sem somar a imagem novamente.
   - Usage da tool só é precificado quando é a única fonte. Com usage principal presente, a exclusão não é comprovada e as duas fontes NÃO são somadas (`tool_usage_overlap_unproven`).
3. **Cache sem atribuição não é inventado.**
   - Removido o `Math.min` que alocava cache ao texto.
   - Com breakdown de imagem e cache sem `Ct`/`Ci`, os componentes de ENTRADA não são precificados; apenas a saída confirmada continua, com `partial`.
   - Fórmula B usa o cache total na tarifa de cache (sem atribuição modal), nunca como input normal.
4. **Inconsistência impede `complete`.**
   - `reasoning_tokens > output_tokens` (quando não declarado fora), `cached_input > input`, cache de texto/imagem maior que a modalidade e breakdown inconsistente marcam `usage.inconsistent`.
   - A cobertura nunca é `complete` nesses casos: `usage_inconsistent_coverage_not_complete`.
5. **Auditoria de tentativa/credencial.**
   - Primeira tentativa do Diretor de Arte passou de `attempt=1` para `attempt=0`; `retry_used` nasce `false`.
   - O request da validação semântica dedicada leva `credential_scope`, `retry_used` e `retry_prompt_variant`.
   - O sink enriquece eventos com `credential_scope` mesmo sem `visual_signature_preset` (validação coberta).
   - O caminho legado continua sem metadata adicional.

## Segunda revisão (3 achados)

1. **Ramo da tool com as mesmas regras do usage principal.**
   - A tool usa `toolRates` do PRÓPRIO modelo (texto + imagem), nunca as tarifas do orquestrador.
   - `toolUsage.inconsistent` (reasoning/cache/breakdown) entra integralmente na decisão e impede `complete`.
   - Cache sem atribuição na tool não precifica nenhum componente de entrada; apenas a saída confirmada.
   - Tool sozinha, sem usage do orquestrador, permanece `partial`/`unknown` (`orchestrator_usage_missing_tool_only`): o custo total da chamada não está comprovado.
2. **`code_default` não é tarifa operacional no caminho dedicado.**
   - `getVisualSignatureOrchestratorPricing` trata `versionId='code_default'` como ausência.
   - O bootstrap legado continua intacto para os consumidores antigos.
   - O caminho novo não registra `pricing_table`/`complete` com bootstrap estático.
3. **`rejectionContext` separado do índice da operação.**
   - O Diretor de Arte envia sempre `attempt=0` na chamada inicial; o histórico de rejeição fica apenas no prompt.
   - Uma nova geração após rejeição nasce com `retry_used=false`; retries internos continuam `>=1` no chamador.

Regressões novas: tool com reasoning inconsistente, cache sem atribuição, tool sem tarifa própria, tool isolada sem orquestrador, `code_default` no orquestrador e geração inicial com `rejectionContext`.

## Entregas

### Usage e fórmulas

- `reasoning_tokens` é subconjunto de `output_tokens` e nunca é somado novamente.
- `cached_input_tokens` é subconjunto de `input_tokens`; quando há `Ct`/`Ci`, cada parcela usa sua tarifa. Cache sem atribuição não é precificado como input normal.
- Tokens de imagem são excluídos do texto e precificados uma única vez.
- Breakdown inconsistente é descartado; input/output sem total não inventam total.
- Tarifa ausente de qualquer componente → `partial` com `missingRates`, sem unitário histórico por cima.
- Sem usage: `estimatedCostUsd=null`, `costSource=not_available`, `costCoverage=partial` e nota `visual_signature_image_estimate_no_usage` com referência histórica.
- Custo reportado: fonte `provider_reported`, campo próprio, estimativa separada.

### Pricing

- Orquestrador e imagem têm leituras e versões independentes.
- Sunburst Medium procura `openai/gpt-image-2.5-sunburst/medium`; o orquestrador é buscado pelo modelo real do request.
- Nenhuma leitura de `responses:image_generation` no caminho com preset.
- `VISUAL_SIGNATURE_HISTORICAL_ESTIMATES` mantém `low: 0.036` e `medium: 0.044` apenas como referência local rotulada.
- Modelo do request divergente do preset → `not_available`/`partial` com motivo; nunca correção silenciosa.

### Telemetria

O evento call-level registra, no caminho com preset/credencial dedicada:

- `responses_model`, `image_model`, `image_quality`, `visual_signature_preset`, `reasoning_effort`, `config_version_id`;
- `attempt_number`, `retry_used`, `retry_prompt_variant`, `credential_scope`;
- `cost_coverage`, `cost_source`, `cost_estimation_note`, `provider_reported_cost_usd`;
- `orchestrator_pricing_version`, `image_pricing_version`;
- `image_tool_usage`/`image_tool_usage_source` quando existirem.

O sink não recalcula custo: apenas encaminha os valores já calculados. Campos canônicos não podem ser forjados pelo caller. Fluxos legados permanecem byte-compatíveis.

### Retry

- Gateway de validação constrói o cliente com `maxRetries=0`.
- Uma falha gera exatamente uma chamada e um envelope `failed`.
- Adapter default mantém a configuração existente (sem `maxRetries` injetado).
- Limite efetivo registrado no teste: até 2 imagens e 2 validações por geração.

## Deviations from Plan

1. **[No-op técnico] `ai-model-pricing.ts` não precisou de alteração.** A leitura aditiva por `(provider, model, quality)` já existia desde a F56.1. O orquestrador usa a leitura legada sem `quality`; a imagem usa a leitura com `quality`. Nenhuma tarifa ou query legada foi alterada.
2. **[Schema] Tarifa única de imagem.** O banco só possui `image_token_usd_per_1m`; ela não é reutilizada para entrada E saída. Com ambas as direções, o resultado é `partial` até existir tarifa separada explícita.
3. **[Aditivo] Cobertura/versões em metadata.** Não existe coluna dedicada para `cost_coverage`/versões separadas em `generation_events` e o plano proíbe migration. A cobertura e as duas versões viajam no `CostResolution` e são persistidas em metadata; `cost_source`, `cost_estimation_note` e `provider_reported_cost_usd` continuam em seus campos/colunas próprios.
4. **[Honestidade] `complete` restrito a A/C.** Fórmula B (apenas totais) permanece `partial` porque a inclusão da imagem não é comprovável. Inconsistências também forçam `partial`.
5. **[Preservação] Ajuste manual explícito continua vencendo o pricing automático**, mas nunca sobrepõe custo reportado.
6. **[Legado] Nenhuma alteração de `DEFAULT_AI_MODEL_PRICING` nem das linhas de `ai_model_pricing`.** O valor legado `0.065` continua apenas no caminho sem preset.

### Binding e `--network-id`

- A rede atual `supabase_network_vendeo_f47_2_disposable_20261024` é bridge;
  suas opções são apenas `enable_ipv4=true` e `enable_ipv6=false`, sem
  `com.docker.network.bridge.host_binding_ipv4`.
- `docker inspect` dos containers Kong/API, DB e Studio mostrou
  `HostConfig.PortBindings` com `HostIp` vazio. O CLI não gravou `0.0.0.0` como
  endereço explícito; a documentação Docker confirma que host IP omitido publica
  em todos os endereços por default.
- Help e binário efetivo do Supabase CLI documentam `--network-id` como usar uma
  rede Docker especificada em vez da rede gerada. A opção não é um argumento de
  host bind. Docker documenta `com.docker.network.bridge.host_binding_ipv4` como
  default de binding para redes bridge user-defined. Portanto o CLI não mostrou
  forçar explicitamente `0.0.0.0`; proposta é fornecer uma bridge dedicada com
  default `127.0.0.1` via `--network-id`. A efetividade exata no Docker Desktop
  Windows **não foi testada** e terá de ser validada por `docker inspect` e
  listeners antes de aceitar o ambiente ou prosseguir.

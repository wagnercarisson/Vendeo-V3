**B) RPC `public.lab_reserve_run` (task 1.9).**

Assinatura exata: `lab_reserve_run(p_experiment_id UUID, p_variant_id UUID, p_scenario_version_id UUID, p_repetition_index INT, p_supersedes_run_id UUID, p_snapshot JSONB, p_operation_id UUID, p_actor_id UUID) RETURNS JSONB`, `LANGUAGE plpgsql`, `SECURITY DEFINER`, `SET search_path = ''`.

Ordem obrigatória das checagens (nesta ordem, nada antes do lock):
1. `p_snapshot IS NULL OR p_snapshot = '{}'::jsonb` → `RAISE EXCEPTION 'missing_snapshot'`.
2. `p_operation_id IS NULL` → `RAISE EXCEPTION 'missing_operation_id'`.
3. `SELECT * INTO v_experiment FROM public.lab_experiments WHERE id = p_experiment_id FOR UPDATE;` — lock **antes** de qualquer checagem; `NOT FOUND` → `RAISE EXCEPTION 'experiment_not_found'`.
4. Idempotência **após o lock**: `SELECT id, experiment_id, variant_id, scenario_version_id, repetition_index FROM public.lab_runs WHERE operation_id = p_operation_id`. Se encontrado e o payload divergir em qualquer um dos 4 campos → `RAISE EXCEPTION 'idempotency_conflict'`; se coincidir → `RETURN jsonb_build_object('success', true, 'idempotent', true, 'run_id', v_existing)`.
5. Prontidão: `v_experiment.status NOT IN ('ready','running','evaluated')` → `RAISE EXCEPTION 'experiment_not_ready'`.
6. `variant_not_in_experiment` (variante não pertence ao experimento), `scenario_not_in_experiment` (par ausente em `lab_experiment_scenarios`), `repetition_out_of_range` (`p_repetition_index` nulo, `< 1` ou `> v_experiment.repetitions`).
7. `p_supersedes_run_id` não nulo exige linha com o mesmo `experiment_id`, `variant_id`, `scenario_version_id` **e `repetition_index`**, com `status IN ('succeeded','failed','cancelled','timeout')`; senão `RAISE EXCEPTION 'invalid_supersedes_run'`.
8. Budget: `SELECT count(*) FROM public.lab_runs WHERE experiment_id = p_experiment_id`; `>= v_experiment.max_runs` → `RAISE EXCEPTION 'budget_exceeded'`.
9. `run_sequence` **derivado no banco**: `COALESCE(max(run_sequence), 0) + 1` restrito à combinação `(experiment_id, variant_id, scenario_version_id, repetition_index)`. Nunca aceito do cliente.

11. `UPDATE public.lab_experiments SET status = 'running', updated_at = now() WHERE id = p_experiment_id AND status IN ('ready','evaluated');` (avaliar **não** encerra execuções).
12. `RETURN jsonb_build_object('success', true, 'idempotent', false, 'run_id', v_run_id, 'run_sequence', v_sequence);`
13. Bloco `EXCEPTION WHEN unique_violation` — reler por `operation_id`: se existir e o payload coincidir → retorno idempotente; se existir e divergir → `RAISE EXCEPTION 'idempotency_conflict'`; se não existir → `RAISE EXCEPTION 'run_already_active'` (é o índice único parcial **global** de run ativo).

`REVOKE EXECUTE ON FUNCTION public.lab_reserve_run(UUID, UUID, UUID, INT, UUID, JSONB, UUID, UUID) FROM PUBLIC, anon, authenticated;` + `GRANT EXECUTE ... TO service_role;`.

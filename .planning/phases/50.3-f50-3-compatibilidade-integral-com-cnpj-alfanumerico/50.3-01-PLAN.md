A coesão justifica a consolidação; o custo de contexto permanece ~30–35%.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| input do usuário → domínio `src/lib/cnpj` | Texto arbitrário (teclado, colagem, IME) cruza para normalização/validação |
| domínio → hash/raiz | A raiz canônica alimenta HMAC com `CNPJ_PEPPER` (server-side) |
| valor persistido → exibição | Dado inesperado pode chegar à máscara de telas administrativas |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-50.3-01 | Tampering | `normalizeCnpj` / `validateCnpj` | mitigate | Allowlist `[0-9A-Za-z./\-\s]` checada ANTES de qualquer transformação; caractere desconhecido permanece e invalida; DV recalculado no servidor; nenhuma "correção" silenciosa. |
| T-50.3-02 | Tampering | `formatCnpjInput` | mitigate | Fail-closed: retorna `previousValue` quando `hasInvalidCnpjChars` for verdadeiro; teste de componente/task garante que o valor hostil não entra no DOM. |
| T-50.3-03 | Information Disclosure | `maskCnpj` | mitigate | Placeholder `"CNPJ inválido"` para entrada fora da regex; nunca devolve o identificador integral; suíte cobre entradas inválidas. |
| T-50.3-04 | Information Disclosure | `hashCnpjRoot` | mitigate | Algoritmo e pepper inalterados; nenhum valor de `CNPJ_PEPPER` é impresso em teste/log; raiz é sempre canônica. |
| T-50.3-05 | Tampering | dependências | accept | Nenhum pacote é instalado nesta fase (`npm install` proibido); qualquer dependência nova é mudança de escopo e retorna ao OpenSpec. |

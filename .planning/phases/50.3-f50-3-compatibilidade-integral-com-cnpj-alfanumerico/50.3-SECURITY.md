# Phase 50.3 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.
> Scope: F50.3 — integral compatibility with numeric and alphanumeric CNPJ.
> Method: read-only static verification of the implementation against the eight PLAN `<threat_model>` blocks. No app, Docker, database, migration, fixture, UAT or paid provider was executed.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Browser input → `src/lib/cnpj` | Arbitrary keyboard/paste/IME text enters normalization, validation and progressive masking | Fiscal identifier (raw, possibly hostile characters); no secrets |
| Client components → API routes | Cookie-authenticated mutations and lookups cross into route handlers | CNPJ input, store identity, lookup payloads |
| API routes → PostgreSQL RPC / cache | Canonical CNPJ, root HMAC and verification signals define fiscal writes and cache keys | Fiscal data, `cnpj_root_hash`, verification status |
| API routes → external providers (BrasilAPI / CNPJá) | Canonical CNPJ is sent to third-party HTTP services; responses influence verification and freemium | CNPJ and public company data; no local secrets |
| DB → passive/admin display surfaces | Persisted `cnpj_normalized` is rendered in admin listings/detail and owner screens | Fiscal identifier (must be masked on passive surfaces) |
| Migration / verifier → isolated PostgreSQL | DDL and constraint-matrix INSERTs target only `supabase_db_vendeo-f562a-isolated` (127.0.0.1:56322) | Schema and synthetic fixtures; no production data |
| Documentation / UAT → evidence | Commands, baselines and results are recorded for repudiation control | No pepper, secret or customer data |

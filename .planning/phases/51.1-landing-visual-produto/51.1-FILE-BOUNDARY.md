## 4. Pausa de briefings e exemplos finais (geração humana x execução autônoma)

**Separação explícita entre execução autônoma e geração humana:**

- A **execução automática** (o agente e a landing) **nunca** chama a API de geração/provider e **nunca** executa geração paga; nenhum teste invoca a API de geração (D-03/D-09).
- Os **exemplos finais** de campanha são produzidos por **geração humana** no laboratório, com **autorização específica** (pelo usuário, fora da execução automática) — **não** fazem parte da execução automática desta fase.
- O **executor apenas ANEXA** os exemplos previamente aprovados e pertencentes à landing (assets landing-owned), sem gerar nada.
- Os exemplos finais exigem uma **SEGUNDA aprovação humana** (executada no plano de fechamento 51-1-08) antes de a entrega ser considerada concluída (D-02).

**Fluxo de pausa (ordem):**
1. Aprovação da candidata visual (Plano 01, checkpoint bloqueante) → libera a implementação.
2. Implementação com placeholders (Planos 02–07).
3. **Pausa de briefings**: definição dos briefings e **geração humana** dos exemplos finais no laboratório, com autorização específica.
4. Troca dos placeholders pelos exemplos aprovados (sem refazer layout) + revalidação (typecheck/lint/build/testes e revisão visual dos dois modos — D-18).
5. **SEGUNDA aprovação humana** dos exemplos finais (Plano 51-1-08) → conclusão da entrega.

# Phase 51.1 — UI Design Contract

> Visual and interaction contract for the public landing renewal (`src/app/page.tsx` + `src/components/landing/*`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This contract makes an ALREADY-APPROVED visual direction verifiable. It does not redesign scope, does not add metrics, localization or SEO, and does NOT replace the human approval of the visual candidate (design D9 / CONTEXT D-01/D-02, task §1.3).** The checkpoint in Plano 01 is blocking and remains the authority on composition, copy and image function.

## Spacing Scale

Declared values (all multiples of 4; aligned with `MASTER.md §4`):

| Token | Value | Usage on this landing |
|-------|-------|-----------------------|
| 2xs | 4px | Icon–text gaps, badge inline padding |
| xs | 8px | Inline gaps, small stack gaps, badge padding |
| sm | 12px | Button vertical padding (`py-3`), select compact padding |
| md | 16px | Form field gaps (`space-y-4`), standard element spacing |
| lg | 24px | Card padding (`p-6`), between cards in a grid |
| xl | 32px | Gaps between sub-elements / layout gaps |
| 2xl | 48px | Section vertical breaks (`py-12`), hero bottom (`pb-12`) |
| 3xl | 64px | Hero top padding (`pt-16`), page-level spacing |

Mobile-first vertical rhythm: section blocks use `py-12` (48px) with 32px internal gaps; hero uses `pt-16`/`pb-12` on mobile and `sm:pt-24` on desktop. Max content width `max-w-5xl` (header, sections, footer); forms/cards `max-w-md`; copy columns `max-w-2xl` (headline) / `max-w-xl` (subheadline).

**Exceptions:** none. Every interactive element keeps `min-height: 44px` (see Accessibility Contract) — the 44px touch target is a hard floor, not a spacing token substitution.

**Accent (`#22C55E`) reserved for — explicit list, never "all interactive elements":**
1. Primary CTA buttons: "Solicitar acesso free" (flag off) and the solid Google button (flag on), in hero, offer and final blocks.
2. Form submit button (`Button variant="primary"`).
3. Success state text/icon of the access form and success confirmation heading accent.
4. The single emphasis span in the distinction line "Você **define** como quer apresentar. **O Vendeo prepara a campanha.**" — green is used on the "Vendeo prepara" half only.
5. Positive "proof" labels/badges (e.g. step/approach markers) where a check/positive signal is required.

Green is **NOT** used for: body text, headings at rest, legal footer links, generic borders, or the "Entrar"/secondary buttons (those use `text-secondary` + `border-light`). Secondary buttons use `border`/`border-light` + `text-secondary`, with `accent-blue` ring on focus.

**Contrast correction (local, justified):** `#22C55E` with **white** text is ≈**2.1:1** — insufficient (WCAG AA needs 4.5:1 for normal text). All primary CTA surfaces in this landing therefore use the **dark** text token `text-bg-deep` (`#020617`) on `bg-accent-green`, giving ≈**8.8:1**. `MASTER.md §6.1` currently says "Primary (CTA): bg accent-green (#22C55E), text: white" — that guidance is a **design-system discrepancy**. This phase corrects it **locally** on the landing (and records the global MASTER/`Button` discrepancy as a follow-up); it does **NOT** modify the global design system or shared tokens silently. The flag-on `GoogleButton variant="solid"` already uses `text-slate-950` (consistent with this). For the form submit (`Button variant="primary"`, which hard-codes `text-white`), apply a **local override** (e.g. `!text-bg-deep` or a landing wrapper class) — do not change the shared component silently.

Order is fixed and verifiable. Each block answers one distinct question and has one visual function (design D1 / CONTEXT D-04). "Como funciona" is absorbed by the transformation block and MUST NOT exist as a separate block.

| # | Block | Question | Single function | Key approved copy |

| 2 | Transformação e simplicidade | "É fácil de usar?" | Proof of simplicity (info → campaign → download) | — |
| 3 | Apresentação do produto | "Consigo escolher como apresentar meu produto?" | Proof of visual flexibility (stúdio / ambientado / fundo original) | "Escolha como apresentar seu produto." / "Estúdio, ambientado ou mantendo o fundo original." |
| 4 | Identidade e controle | "Fica com a cara da minha loja? Eu mando?" | Proof of coherence + user control | Preserve the distinction line |
| 5 | Abordagens de divulgação | "Como comunico meu produto?" | Proof of different ways to communicate the product (oferta / destaque / exclusivo) | "Uma campanha para cada jeito de divulgar." / "Mostre uma oferta, valorize um produto ou apresente algo especial." |
| 6 | Oferta (independent component) | "Quanto custa começar?" | Isolated commercial message | Offer main message (below) |
| 7 | FAQ + CTA final + rodapé legal | "Ainda tenho dúvidas?" | Objections + conversion + legal | Legal links + Novidades (secondary/footer) |

**Invariants:**
- "Novidades" (`NovidadesLink`) MUST render in the footer/secondary position (variant `footer`, or `prominent` only if placed as a secondary element below the fold) — never as a primary hero element.
- The nav/header "Entrar" link is secondary and always present; header brand "Vendeo" stays `font-heading text-xl font-bold`.
- No block repeats another's function; no block requires internal terms (`briefing`, `intenção`, `F56`) to be understood (D-06/D-08).
- The two demonstration blocks (Apresentação do produto; Abordagens de divulgação) use the SAME image size and stable 1:1 proportions; the abordagens block has lower editorial weight (short title, support, three examples) and adds no explanatory cards, extra CTAs or process repetition. Never reuse the same campaign to fake differences.
- The abordagens block remains in the final delivery ONLY if its campaigns show clear commercial differences and add a new proof; if they are redundant or merely aesthetic, re-present the streamlining/removal proposal for human approval.
- Only approved capabilities are communicated: 1:1 product campaigns; studio/ambient/original-background presentations; offer/featured/exclusive approaches. No services, no informatives, no non-1:1 formats, and never framed as "em breve"/future (D-08).

## Image Contract

Each image carries exactly ONE proof function, a stable proportion, and a swappable placeholder. Component containers must fix the aspect ratio so replacing a placeholder with an approved campaign does NOT change layout (design D2 / REQ "Direção e função das imagens").

| Block | Proof function | Recommended proportion | Requirement / implementation notes |
|-------|----------------|------------------------|-------------------------------------|
| Hero | **Quality** | 1:1 (square) | One protagonist campaign. Mobile: message + CTA render BEFORE the image (`order`/stack) so the image never pushes the CTA far below the fold. Desktop: two-column (copy left, 1:1 image right). |
| Transformação | **Simplicity** | Entry = compact text summary (no image); result = full 1:1 | Entry is a short summary of product/price/details (NOT a square image); the resulting campaign stays COMPLETE at 1:1 with **no crop**; entry↔result correspondence preserved. |
| Apresentação do produto | **Flexibility (visual)** | Three 1:1 campaigns — desktop 3 columns; mobile horizontal scroll-snap strip | Estúdio · Ambientado · Fundo original — SAME commercial approach and equivalent information, so the only difference shown is the visual presentation. Exactly three slots. |
| Abordagens de divulgação | **Different ways to communicate** | Three 1:1 campaigns — desktop 3 columns; mobile horizontal scroll-snap strip | Oferta · Destaque · Exclusivo — SAME scenario and store identity, varying the necessary information. Lower editorial weight (short title, support, three examples). Exactly three slots. |
| Identidade e controle | **Brand coherence** | 1:1 example(s) | Compact block; supported by examples only. User "reviews and decides what to publish". |

**Hard rules:** no image without a proof function; never fabricate testimonials, commercial results or identity proofs; all campaigns shown are 1:1; interface/text are support, the campaign is the protagonist; final examples are produced by **authorized human generation in the lab** (outside autonomous execution) and require human approval (D-02/D-03/D-07). The prohibition on generation applies to **autonomous execution** (agent/landing/tests) — authorized human lab generation remains allowed. Placeholder implementation MUST use a fixed `aspect-ratio` container (e.g. `aspect-square` + `object-cover`) with a neutral `bg-surface`/`border` skeleton — no `next/image` intrinsic sizing that would shift layout on swap.

## Accessibility Contract

Preserves current semantics and adds no regressions (D-16, REQ "Acessibilidade e preservação").

- **Heading hierarchy:** exactly one `h1` (hero headline); each section has an `h2` via `aria-labelledby` (e.g. `id` + `aria-labelledby`), card titles use `h3`. No skipped levels.
- **Landmarks:** page wrapped by `header` / `main` / `footer` semantics; each block a `<section>` with an accessible name. Form is a `<form>` with labeled controls (`htmlFor`/`useId`).
- **Focus:** visible ring on every interactive element (`focus:ring-2`, green for primary, `accent-blue` for secondary) with `focus:outline-none` only when the ring is present.
- **Touch targets:** every interactive element ≥ 44×44px (`min-h-[44px]`, buttons/links/select/inputs); Novidades close button `min-h-[44px] min-w-[44px]`.
- **Contrast (WCAG 2.x relative luminance; on `#020617` / `#0F172A` respectively):** `text-primary` `#F8FAFC` ≈**19.3:1** / **17.1:1**; `text-secondary` `#94A3B8` ≈**7.9:1** / **7.0:1**; `text-muted` `#64748B` ≈**4.2:1** / **3.8:1** — **below 4.5:1 for normal text on surfaces, so restrict it to non-essential helper/legal text; use `text-secondary` for essential text**; primary CTA `#22C55E` with `#020617` text ≈**8.8:1** and **never** white on `#22C55E` (≈2.1:1). Color is never the only state indicator (icons/labels accompany success/error).
- **Forms state:** flag off → `AccessRequestForm` present with `idle` / `submitting` (spinner + "Enviando...", disabled) / `success` (`role="status"`) / `error` (`role="alert"`, no field association leak); inline validation on blur where applicable; anti-enumeration response preserved.
- **Legal links preserved:** `/termos`, `/privacidade`, `/uso-aceitavel`, Contato (`mailto:SUPPORT_EMAIL`) stay functional in the footer and the form's privacy/terms notice. Novidades modal keeps `role="dialog"`, `aria-modal="true"`, Esc to close, focus to first interactive on open, focus return to trigger on close.
- **Motion:** respect `prefers-reduced-motion` via `motion-safe:`; transitions 150–300ms (the prototype's demonstration-set entrance uses 200ms opacity + `translateY(8px)`, runs ONCE on view, and animates no layout-affecting property); no layout-shifting hover scale transforms; no zoom, parallax, blur, continuous effects or auto-rotation; never animate the headline, primary CTA, form or essential text.
- **Mobile-first:** message + hero CTA visible without scrolling past an oversized image (hero image renders after copy/CTA on mobile). Demonstration sets (apresentação/abordagens) use a NATIVE horizontal scroll-snap strip on mobile (one legible campaign + part of the next; overflow confined to the strip; keyboard-focusable with visible focus) and a 3-column layout on desktop; section vertical spacing starts at 32px on mobile. FAQ closed by default; the offer stays short and independent; important content is never hidden just to reduce height.

## Assumptions

1. **Weight set:** The contract uses Poppins 500/600/700 + Open Sans 400 rather than the generic "2 weights max" guideline, because `MASTER.md §3` mandates these families/weights as the controlled design source of truth.
2. **Type scale:** Four declared sizes (30/48 display, 24/30 heading, 16/18 body, 12 label) with responsive variants counted within the same role; card sub-titles reuse the Body size at Poppins 600 (weight variant, not a new size).
3. **Hero image on mobile:** assumed the image renders after the message + CTA (stack order) to satisfy "CTA not pushed below the fold"; desktop uses a two-column layout.
4. **All campaign images 1:1:** assumed because the only approved campaign format is 1:1; the transformation entry is a compact text summary (no image) and only the result is a 1:1 campaign.
5. **Novidades placement:** assumed footer `variant="footer"` preferred; `prominent` allowed only in a clearly secondary position below the fold.
6. **`data-public-signup-enabled`:** assumed the existing attribute is retained (or an equivalent explicit prop) so tests can assert all acquisition blocks share the flag mode.
7. **Contrast correction:** primary CTA text on `#22C55E` is dark (`#020617`) locally because white-on-green is ≈2.1:1; the `MASTER.md §6.1` / shared-`Button` discrepancy is recorded as a follow-up and is **not** changed silently in this phase.

## 4. Mapa das imagens (função / proporção / requisito)

Cada imagem carrega **exatamente uma** função de prova e uma proporção estável. Imagens sem função de prova são eliminadas. Nunca fabricar depoimentos, resultados comerciais ou provas de identidade.

| Bloco | Função de prova | Proporção | Requisito / implementação |
|-------|-----------------|-----------|---------------------------|
| Hero | **Qualidade** | 1:1 (quadrada) | Uma campanha protagonista. Mobile: mensagem + CTA antes da imagem. Desktop: duas colunas. |
| Transformação | **Simplicidade** | 2 painéis antes/depois, **cada um 1:1** | Esquerda = informação simples preenchida (produto/oferta/preço); direita = campanha resultante. Empilha no mobile. |
| Variações | **Flexibilidade** | Conjunto de tiles **1:1** (mesmo produto, apresentações distintas) | Demonstra estúdio / ambientado / fundo original e as abordagens oferta / destaque / exclusivo. Grade responsiva. |
| Identidade | **Coerência de marca** | 1:1 (exemplo) | Bloco compacto sustentado por exemplo; **não fabricar** prova de identidade. |

**Estratégia de placeholders:** todo contêiner de imagem fixa a proporção com `aspect-square` (1:1) e um esqueleto neutro `bg-surface #0F172A` + borda `#1E293B`/`#334155`. Trocar o placeholder pela campanha aprovada mantém o layout (mesmo `aspect-ratio`, `object-cover`) — sem `next/image` de dimensionamento intrínseco e **sem refazer layout**.

## 5. Teste de compreensão

**Objetivo:** verificar que um visitante entende o produto após ler **apenas hero + transformação**.

**Declaração de sucesso (passa se):** ao terminar o hero e o bloco de transformação, o visitante consegue dizer, com as próprias palavras, que (a) o Vendeo transforma informações simples da loja (produto, oferta, preço) em uma **campanha pronta para publicar**, e (b) o processo é **simples** (informar → receber → conferir/baixar), sem precisar de design, copywriting ou marketing.

**Falha se:** o visitante não souber o que o produto faz, achar que precisa "desenhar" a campanha, ou precisar dos blocos posteriores (variações/identidade/oferta) para entender a proposta central.

**Método deste plano:** revisão humana da candidata (composição + protótipo). Sem instrumentação de funil (fora de escopo).

## 7. Briefings propostos para os exemplos finais (rascunho — pausa humana D-02/D-03)

> **Natureza:** propostas para a **pausa humana** definida em D-02. São o alvo dos **briefings** que orientarão a geração **humana** dos exemplos finais. **Não** fazem parte da execução automática do Plano 01, **não** são gerados pelo agente/protótipo e **não** ativam a API de geração. Sem valores comerciais reais inventados, sem depoimentos, sem provas de identidade fabricadas.

| Slot (bloco) | Briefing proposto (a confirmar na pausa) |
|---|---|
| Hero — campanha protagonista | Produto de loja física + oferta clara (preço com desconto), abordagem **oferta**, fundo **estúdio**, formato **1:1**. |
| Transformação — "antes" | Captura/representação do formulário simples preenchido (produto/oferta/preço) — **não** é campanha; é a entrada. |
| Transformação — "depois" | A campanha resultante do "antes", formato **1:1**, mesmo produto. |
| Variações — apresentação 1 | Mesmo produto, fundo **estúdio**, abordagem **destaque**, 1:1. |
| Variações — apresentação 2 | Mesmo produto, fundo **ambientado**, abordagem **oferta**, 1:1. |
| Variações — apresentação 3 | Mesmo produto, **fundo original** preservado, abordagem **exclusivo**, 1:1. |
| Identidade — exemplo | Uma campanha do mesmo produto que preserve a identidade da loja (logo/cores), sem prova de identidade fabricada, 1:1. |

**Regra de geração (D-03):** a execução **automática** (agente + landing + testes) **nunca** chama a API de geração/provider. As artes finais são produzidas por **geração humana** no laboratório, com **autorização específica**, fora da execução automática; o executor apenas **anexa** os assets aprovados. Os exemplos finais exigem **segunda aprovação** humana (Plano 51-1-08) antes de a entrega ser considerada concluída.

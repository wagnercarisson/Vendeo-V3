### `src/lib/seo/origin.ts` — `resolveCanonicalOrigin()` (utility, transform)

`src/lib/store-readiness.ts` (explicit result type + never-throws + diagnostic).

**Env-reading idiom** — `src/lib/ai/api-keys.ts` lines 35-46:
```typescript
function resolveKey(provider: AiProvider, envName: "OPENAI_API_KEY" | "GEMINI_API_KEY"): string {
  const value = process.env[envName];
  if (value !== undefined && value.length > 0) {
    return value;
  }
  if (process.env.NODE_ENV === "production") {
    throw new Error(
      `[api-keys] ${envName} não configurada para o provider "${provider}" (fail-fast em produção)`,
    );
  }
  return "";
}
```

**Env-derived boolean idiom** — `src/lib/launch-config/config.ts` lines 20-26:
```typescript
function envBool(key: string, defaultValue: boolean): boolean {
  const raw = process.env[key];
  if (raw === undefined) return defaultValue;
  if (raw === "true") return true;
  if (raw === "false") return false;
  return defaultValue;
}
```

async function getRedirects() {

## Shared Patterns

### Fail-closed single source of truth
**Source:** `src/lib/seo/origin.ts` + `src/lib/seo/environment.ts`
**Apply to:** `layout.tsx`, `page.tsx`, `robots.ts`, `sitemap.ts`, `next.config.ts` `headers()`.
Every consumer must derive indexability from `isIndexableEnvironment()`, never from `NODE_ENV`.

### Never-throws / explicit-result contract
**Source:** `src/lib/store-readiness.ts` (lines 10-13, 43-53) and `src/lib/ai/api-keys.ts` (lines 20-33)
**Apply to:** all `src/lib/seo/*` helpers. Return explicit result objects with a `diagnostic`;
never throw for missing/invalid env (contrast with `site-url.ts`, which throws — do not reuse it).

### Typed metadata / MetadataRoute exports
**Source:** `src/app/layout.tsx` (lines 1-28) and `src/app/manifest.ts` (lines 1-26)
**Apply to:** all new/modified server components and route files — use `Metadata`, `Viewport`,
`MetadataRoute.Robots`, `MetadataRoute.Sitemap`.

### Vitest environment directives
**Source:** `vitest.config.ts` (lines 15-19, `environment: 'node'`, alias `@`, `globals: true`)
**Apply to:** all tests. Pure helper/config tests stay in `node` (explicit
`// @vitest-environment node` is the codebase convention, e.g. `next.config.test.ts` line 1);
only DOM tests use `// @vitest-environment jsdom`.

### Env stubbing in tests
**Source:** `src/lib/ai/__tests__/api-keys.test.ts` (lines 6-15) and
`src/lib/launch-config/__tests__/config.test.ts` (lines 3-20)
**Apply to:** SEO helper/metadata tests — `vi.stubEnv` + `vi.unstubAllEnvs()` in
`beforeEach`/`afterEach`, or `vi.resetModules()` + `process.env = { ...OLD_ENV }` when the
module reads env at import time.

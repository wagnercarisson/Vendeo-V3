# Phase 56.1 — UI Design Contract

> Visual and interaction contract for the **single admin screen** of Phase 56.1.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Source of truth for the admin config screen that sets the new-flow image model pair
> (primary + fallback, each `model + quality`).

---

## Scope Guardrails (read first)

This phase exposes **exactly one** UI surface: the **admin configuration screen** for the
new-flow image model pair. Everything below is bounded by that.

**Primary focal anchor:** the configuration form (region E) with the `Salvar configuração` CTA is
the single primary visual anchor; the amber inactive-production banner (region B) is the persistent
secondary anchor.

**In scope (this contract covers):**
- One admin screen under `/admin/*` (existing `(app)/admin/layout.tsx` shell, `requireAdmin`).
- Primary + fallback pair selection (`model + quality`), restricted to the eligible catalog.
- Explicit, persistent warning that the configuration is **NOT active in production**.
- Display of eligible catalog, current pair, origin (`human_decision`/`selection`), version UUID.
- Display of pricing coverage (`complete`/`partial`/`missing`) with missing components.
- Mandatory `motivo` (reason) and audited save — **save is allowed with incomplete coverage**.

**Explicitly out of scope (do NOT design/build here):**
- Any lojista-facing UI, campaign form, or intent selector (Oferta/Destaque/Exclusivo) — F56.2.
- Mobile store-owner flows, campaign preview, approval/correction screens — F56.2/F56.3.
- Destructive actions, reset-to-default, or activation toggles (origin `default` does not exist — D-12).
- Provider calls, credit ledger UI, generation triggers.

**Locked inputs used:** CONTEXT.md D-01..D-25 (esp. D-23, D-24), `design.md` D12, OpenSpec
`image-generation-model-pair-config` and `ai-model-pricing`, tasks.md §4, `openspec/design-system/MASTER.md`.
Initial pair is **already decided** (primary `gpt-image-2.5-sunburst / medium`, fallback `gpt-image-2 / medium`) — do **not** re-ask.

## Spacing Scale

Declared values (multiples of 4). Aligned with MASTER §4 and Tailwind tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inner padding |
| sm | 8px | Compact element spacing, label→input gap |
| md | 16px | Card padding baseline, form field gaps (`gap-3`/`gap-4` region) |
| lg | 24px | Section padding, gap between page sections (`space-y-6`) |
| xl | 32px | Major section breaks (`space-y-8`) |
| 2xl | 48px | Page-level vertical rhythm (reserved) |
| 3xl | 64px | Reserved (not expected on this admin screen) |

- **Exceptions:** `12px` (`space-sm`, MASTER §4) is allowed for compact control padding only.
- **Touch/click targets:** minimum **44px** height for every interactive element (shared `Button` already enforces `minHeight: 44px`; selects use `min-h-11` = 44px). No exceptions.
- Content max-width: `max-w-3xl` for header/intro; form cards in a `grid gap-4 xl:grid-cols-2` (mirror `ai-model-selection`), collapsing to a single column below `xl`.

## Typography

Exactly **4 sizes**, **2 weights** (`400` / `600`). Both weights are within MASTER §3's allowed
heading (600/700) and body (400/500) sets.

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Body | 14px (`text-sm`) | 400 | 1.5 | Open Sans |
| Label / Caption | 12px (`text-xs`) | 600 | 1.2 | Poppins, uppercase, `tracking-wider` |
| Heading (page/section) | 20px (`text-xl`) | 600 | 1.2 | Poppins |
| Display (page title) | 30px (`text-3xl`) | 600 | 1.2 | Poppins |

- **Data/monospace** (version UUID, model ids): JetBrains Mono **400** at **12px** (uses the Caption size slot; does not count as a fifth size). Reuses the body weight `400` — no third weight.
- Body line-height 1.5; headings 1.2. Applied via MASTER classes (`font-heading`, `font-body`, `text-*`).
- **Registered exception:** the shared `Badge` primitive bakes in Poppins `500`; on this screen, badges render through a screen-local variant/override at Poppins **600** (label-like), so the baked `500` is not used. `Button` renders `font-heading font-semibold` (600). This screen therefore declares exactly two weights: **400 / 600**.

## Color

60/30/10 split per MASTER §2. Dark OLED only — **no light mode, no `#FFFFFF` backgrounds**.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#020617` (`bg-bg-deep`) | Page background (deepest layer) |
| Secondary (30%) | `#0F172A` (`bg-bg-surface`) / `#1E293B` (`bg-bg-elevated`) | Cards, panels, hover/elevated surfaces |
| Accent (10%) | `#22C55E` (`accent-green`) | **Reserved** — see list below |
| Destructive | `#EF4444` (`accent-red`) | Not used this phase (no destructive actions); reserved for inline error text |

**Accent reserved for (explicit, exhaustive):**
1. The single primary CTA — **Salvar configuração** (`Button variant="primary"`).
2. Success confirmation feedback only (saved-with-audit message + `Check` icon).

**Semantic colors (from MASTER, not "accent"):**
- `accent-blue` `#3B82F6` — focus rings (`ring-accent-blue`), header eyebrow dot, informational read-only banner, "Decisão humana" origin badge.
- `accent-amber` `#F59E0B` — the **"not active in production"** warning banner, and all incomplete-pricing (`partial`/`missing`) warnings.
- `accent-red` `#EF4444` — validation errors and load/save error messages.
- `accent-green` `#22C55E` — only as accent-reserved (1) and (2) above.

**Accent is NOT used for:** selects, selects' focus, inputs, nav links, section headings, coverage badges, or arbitrary icons. Do not color "all interactive elements" green.

## Screen Anatomy (layout contract)

Single server page + client form container, mirroring the `ai-model-selection` structure.

```
<AdminShell> (existing (app)/admin/layout.tsx — requireAdmin + nav)
 └─ Page (max width container, space-y-6)
    ├─ A. Page Header
    │     eyebrow: "Operação de IA" (accent-blue dot) · title · description
    ├─ B. Inactive-Production Warning  (ALWAYS visible, amber, non-dismissible)   ← REQUIRED (D-23)
    ├─ C. Current Configuration Card
    │     • Par vigente: primary  <model> · <quality>
    │                      fallback <model> · <quality>
    │     • Origem: "Decisão humana" badge   • Versão (UUID, mono)
    │     • Autor · Atualizado em · Motivo da última alteração
    │     • Pricing coverage per pair (badge + missing components)
    │     • OR Empty State when no configuration exists
    ├─ D. Eligible Catalog (read-only)
    │     3 models × { low, medium } · status active · "entram por migration"
    └─ E. Configuration Form (client)
          • Primary  pair: model select + quality select
          • Fallback pair: model select + quality select
          • Live pricing coverage for each drafted pair (warn only)
          • Motivo (required) textarea
          • Primary CTA: "Salvar configuração"
          • Inline error / success feedback
```

**A. Page header** — same construction as `ai-model-selection/page.tsx:11-21`.
Eyebrow: `Operação de IA`. Title: `Modelos do novo fluxo Produto 1:1`.
Description: `Defina o par principal e o fallback (modelo + qualidade) do novo fluxo de imagem. Restrito ao catálogo elegível, com auditoria e motivo obrigatório.`

**B. Inactive-production warning** — required element (D-23). `rounded-xl border border-accent-amber/20 bg-accent-amber/5 p-4`, `AlertTriangle` (lucide, `h-5 w-5`, `text-accent-amber`), `aria-live` off (static). Persistent — **not dismissible**, present on every render including empty and success states.

**C. Current configuration card** — read-only. Origin values allowed: `human_decision` (label "Decisão humana") or `selection`. Never render an origin `default` (does not exist — D-12). Version UUID shown in JetBrains Mono 12px (selectable text; copy affordance optional — recommendation). Each pair shows a pricing coverage badge.

**D. Eligible catalog** — read-only list/table of the closed eligible set: `gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst`, each eligible in `low` and `medium`, status `active`. Wrap in a card with an informational note that the catalog is read-only and new models arrive by migration. Do not add selection controls here.

**E. Configuration form** — client container owning primary model/quality, fallback model/quality, reason, operation id/fingerprint, loading/error/success. Each `model` select lists **only** eligible catalog models for the new capability; each `quality` select lists only `low`/`medium`. Selecting is restricted at the source (options), and out-of-catalog values are additionally rejected server-side with a clear error.

## Interaction & State Contract

| State | Behavior |
|-------|----------|
| Initial load | Server component fetches current config + eligible catalog + coverage; page uses `export const dynamic = "force-dynamic"` (mirror `ai-model-selection/page.tsx:4`). Loading route may use `loading.tsx`/`LoadingSkeleton`. |
| No configuration (empty) | Show Empty State in region C; the form (region E) is still available so the admin can register the initial human decision. |
| Default form values | When a config exists, prefill selects with the current pair; `motivo` starts empty. When empty, prefill with the responsible-approved initial pair (primary `gpt-image-2.5-sunburst`/`medium`, fallback `gpt-image-2`/`medium`). |
| Editing | Any select change clears operation id/fingerprint, success and error (idempotency reset — mirror `form.tsx:65-67`). |
| Incomplete pricing (`partial`/`missing`) | Render amber warning for the affected pair(s). **Do not disable Save and do not block submission** (D-24). |
| Submitting | Validate `motivo` non-empty client-side first; if empty show inline `Motivo obrigatório` and stop. Otherwise `Button loading` with `Salvando...`, disabled. |
| Save request | `PUT`/`POST` to the admin API with Zod-validated body, `requireAdmin`, audited RPC, `operationId` for idempotent resend. Never mutate directly via query builder (D-04). |
| Save success | Show `Configuração salva com auditoria.` (`Check` icon, `text-accent-green`), invalidate cache/refresh view so region C reflects the new version. |
| Save error | Show inline `role="alert"` message: reason invalid, or out-of-catalog pair, or generic save error. Keep the draft so the admin can correct it. |
| Load error | Region-level `ErrorState` with the load-error copy and a retry/refresh affordance. |
| Unauthorized | Handled upstream by `(app)/admin/layout.tsx` → `redirect("/dashboard")`. No UI state needed here. |
| Cache | After save, explicit cache invalidation is server-side (D-05); the screen must show the newly persisted version. |

**Restriction to eligible catalog:** `quality` options are `low` + `medium` only; `model` options are the three eligible models only. Any value outside this set is rejected with `Modelo ou qualidade fora do catálogo elegível`.

## Accessibility

- Focus visible on every interactive element: `focus:ring-2 ring-accent-blue` (MASTER §11).
- Every select/textarea has an associated `<label htmlFor>` and visible label text.
- Coverage and origin badges encode meaning with **icon + text**, never color alone (MASTER requirement).
- Inline errors: `role="alert"`; success: `role="status"`; warnings associated to controls via `aria-describedby`.
- Minimum interactive height 44px (selects `min-h-11`; shared `Button` enforces 44px).
- Semantic HTML: `<header>`, `<main>` (layout), `<section aria-labelledby>`, `<form>`.
- `prefers-reduced-motion` respected via `motion-safe:`/`motion-reduce:`; no infinite animation beyond the spinner.
- Transitions 150–300ms (`transition-colors duration-200`), no layout-shifting hover/scale.
- Contrast: text at ≥7:1 on dark backgrounds (MASTER §2 tokens) — use only registered text tokens.

## Admin Integration & Navigation

- **Route (recommendation, discretion):** `/admin/image-model-pair` — a new, distinct page. Do not overload `/admin/ai-model-selection` (different entity, has `quality`).
- **Nav (recommendation):** add one additive entry to `(app)/admin/layout.tsx`, label `Par de modelos (novo fluxo)`. Existing links untouched, no reordering.
- Server page calls the server-only read (region C/D) and passes a view model to the client form.
- The client form talks to the admin API (`requireAdmin` + Zod + audited RPC + cache invalidation). No provider call, no credit mutation, no campaign creation anywhere in this screen.
- **Isolation reminder surfaced in UI:** the inactive-production banner is the visible guarantee that this screen does not alter the legacy flow (REQ-56.1-07).

## Non-Blocking Recommendations (agent discretion)

Recorded, not blocking — CONTEXT.md delegates these:

1. **Route/nav naming** — `/admin/image-model-pair` + label `Par de modelos (novo fluxo)` are recommendations; align to repo conventions at implementation time.

5. **Layout grid** — `grid gap-4 xl:grid-cols-2` for the two pair selectors is a recommendation; a stacked single-column layout is also acceptable.

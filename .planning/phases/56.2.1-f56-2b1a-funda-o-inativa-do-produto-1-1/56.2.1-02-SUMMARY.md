## Accomplishments

- Local-only migration `product_flow_stage_authorizations`: append-only ledger (event_type/stage/scope/instance_identity/grantor/reason/operation_id/expires_at/created_at), RLS service_role, SELECT/INSERT only, immutability trigger, and audited `SECURITY DEFINER` RPCs (grant + revoke) with `search_path=''` and mandatory reason/operation_id/actor.
- Enabling-stage grants (`isolated_pilot`/`test_stores`/`all_stores`) are **refused** and recorded as `refused` events; only `off` is granted. Operational state stays `off` in b1a.
- Pure, deterministic `decideProductFlowAuthorization` (fail-closed): flags-unavailable, missing authorization, non-enabling stage, instance/scope mismatch, revoked, expired, and applicable-flag-off all deny; general-flag precedence honored (D-03).
- `deriveCurrentAuthorization` reconstructs state from the append-only history; server-only `resolveProductFlowAuthorization` reads flags + history and fails closed (`read_failure`).
- Admin API `src/app/api/admin/product-flow-authorizations/route.ts`: `GET` (history, requireAdmin) and `POST` (Zod-validated, delegates to the audited RPC; enabling grants → 403 refusal). No generation/provider/credit/delivery/download.
- F56.2a guard narrowed exactly as instructed: only the authorized route may import `@/lib/product-1-1/authorization/**`; the exception restricts both importer and modules, and other admin routes/modules remain forbidden.

## Post-review corrections (2026-10-08)

Independent review found two defects; both are fixed with new tests.

1. **Idempotent replay returned an improper approval.** The grant RPC's replay branch returned only `event_type`; the route's `refused === true` check then fell through to a `200 { granted: true }`. Fix: the RPC now **preserves the original result** on replay (refused replay → `granted:false, refused:true`; off-grant replay → `granted:true, refused:false`), and the route **validates the response explicitly**, returning `502 authorization_rpc_invalid_response` for missing/invalid shapes instead of success.
   - Tests: first refusal + repeat both `403`; off-grant + repeat both `200`; legacy `{ event_type }` and `{}` responses → `502`. DB contract test asserts replay preservation markers.
2. **Any non-`off` stage was treated as enabling.** Added an explicit **stage × scope × environment matrix** (`STAGE_SCOPE_COMPATIBILITY`, `STAGE_ENVIRONMENT_COMPATIBILITY`): `isolated_pilot` maps only to `test_stores` scope and **only the `isolated` environment** (never operational stores). Invalid combinations deny with `stage_scope_mismatch` / `stage_environment_mismatch`.
   - Tests: `isolated_pilot` + `all_stores` → deny; `isolated_pilot` + operational env → deny; `isolated_pilot` + `test_stores` + isolated → allow; `test_stores` + `all_stores` → deny; `all_stores` + isolated → allow.

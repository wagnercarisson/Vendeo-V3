# Phase 56.2.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail. (F56.2b1a — fundação inativa do Produto 1:1.)

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Executor/CLI → instância Supabase isolada | Inspeção/aplicação local pode alcançar stack compartilhada/remota se a identidade não for comprovada | Metadados, migrations, credenciais locais |
| Logs/CLI → artefato de planejamento | Evidência pode conter segredos/URLs credenciadas | Tokens, headers, dados pessoais |
| Admin browser → API → RPC | Entrada administrativa não confiável; identidade não pode vir do payload | Estágio/escopo/instância, motivo, operation_id |
| Cliente → endpoint de geração | Campos do cliente podem forjar novo fluxo ou gerar cobrança indevida antes da validação | Payload bruto (campos exclusivos) |
| Corpo bruto → schema `.strict()` | Campos exclusivos são rejeitados/descartados pelo parse se o guard não rodar antes | Payload de submissão |
| Serviço/handler → RPC Postgres de crédito | Retries/concorrência cruzam o limite de integridade financeira | Identidade `campanha+operação`, valor, estado |
| Gate/checkpoint → CLI local | Target errado pode aplicar migrations na stack compartilhada/remota | Workdir, hashes, identidade |
| Test runner → Postgres descartável | Corrida/retry pode duplicar ledger | Ledger, saldo, estado |
| Fixtures → estruturas append-only | Cleanup individual é proibido; fixture/target precisa ser rastreável | IDs de fixture |
| Build/test env → provider externo | Má configuração de teste poderia incorrer custo/divulgar entradas | Credenciais de provider |
| Revisão humana → autorização operacional | A aprovação da fase não pode ser interpretada como concessão de estágio | Decisão de UAT |

## Threat Register

| Threat ID | Category | Component | Disposition | Mitigation | Status |
|-----------|----------|-----------|-------------|------------|--------|
| T-56.2.1-01 | Tampering | Instância Supabase | mitigate | Diagnóstico somente leitura; nenhuma escrita/reset/migration; identidade/isolamento comprovados antes de conectar (`56.2.1-01-GATE.md`) | closed |
| T-56.2.1-02 | Information Disclosure | Logs do serviço | mitigate | Evidência sanitizada (tokens/URLs credenciadas omitidos); `.env.local` com backup fora do repo, sem imprimir/commitar segredos (`56.2.1-01-GATE.md` §9) | closed |
| T-56.2.1-03 | Elevation of Privilege | Admin API/RPC | mitigate | `requireAdmin`, actor server-side, recusa de estágio habilitador, motivo/`operation_id` obrigatórios e grants mínimos (`authorization/schemas.ts`, `route.ts`, RPC `SECURITY DEFINER`) | closed |
| T-56.2.1-04 | Tampering | Histórico de autorização | mitigate | Append-only (trigger de imutabilidade) + escrita **SOMENTE** por RPCs SECURITY DEFINER — `service_role` recebe apenas `SELECT`; a migration corretiva `20261008000003` revoga INSERT/UPDATE/DELETE. INSERT direto recusado na instância isolada (prova Postgres) | closed |
| T-56.2.1-05 | Tampering | Payload de submissão | mitigate | Detector sobre o corpo bruto + guard antes do `safeParse` estrito e da reserva; sem fallback que descarte conteúdo (`submission/*`, guard em `generate-image/route.ts`) | closed |
| T-56.2.1-06 | Elevation of Privilege | Guard de elegibilidade | mitigate | Consome apenas a decisão server-side fail-closed; escopo/instância/ambiente derivados do servidor; forjar payload é ignorado (teste) | closed |
| T-56.2.1-07 | Tampering | RPC reserve/finalize/refund | mitigate | Transação atômica, identidade única `campanha+operação`, CAS, RPC de menor privilégio e constraints (migration `20261008000002` + provas Postgres); **escrita direta removida da `service_role`** na tabela financeira (migration `20261008000005`; apenas `SELECT`) | closed |
| T-56.2.1-08 | Repudiation | Credit ledger | mitigate | Identidade durável da operação e correlação no ledger em cada transição (chave de idempotência composta) | closed |
| T-56.2.1-09 | Elevation of Privilege | Credit service | mitigate | Caller server-only; sem actor/valor/estado controlados pelo cliente (valor fixo = 1 crédito); `delivered` terminal | closed |
| T-56.2.1-10 | Tampering | Migration/test target | mitigate | Gate `APPROVED` + aceite humano + match de identidade antes de migration/conexão; apenas comandos explicitamente locais (`--workdir --local`) | closed |
| T-56.2.1-11 | Elevation of Privilege | Stage fixtures | mitigate | Fixtures sintéticas no harness; **nenhuma concessão habilitadora efetivada** (`granted` com `stage <> 'off'` = 0). A RPC de concessão foi exercitada para estágio `off`, recusa de estágio habilitador, replay/conflito e revogação — todas sem efetivar estágio habilitador | closed |
| T-56.2.1-12 | Denial of Service | Concurrent ledger tests | mitigate | Instância descartável isolada, concorrência limitada e IDs únicos; append-only não é apagado individualmente | closed |
| T-56.2.1-13 | Information Disclosure | Test/build environment | mitigate | Sem credenciais de provider nos testes; adapters/provider mockados; build/testes sem chamadas pagas | closed |
| T-56.2.1-14 | Elevation of Privilege | UAT approval | mitigate | Aprovação explicitamente de verificação apenas; stage permanece `off`; nenhuma RPC de concessão habilitadora invocada (`56.2.1-UAT.md`) | closed |
| T-56.2.1-SC | Tampering | npm/pip/cargo installs | accept | Nenhuma dependência nova instalada na fase (todos os 6 planos) — ver Accepted Risks Log |

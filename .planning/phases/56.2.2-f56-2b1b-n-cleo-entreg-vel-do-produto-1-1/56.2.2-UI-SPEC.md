# Phase 56.2.2 — UI Design Contract

> Visual and interaction contract for **F56.2b1b — Núcleo entregável do Produto 1:1**.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Source of truth for the **four connected surfaces** this phase links for the first time:
> (1) the lojista form with eligibility-governed selectors, (2) the generation-tracking
> surface, (3) the unknown-result surface, and (4) the admin pending-list/resolution surface.

---

## Scope Guardrails (read first)

This phase connects **exactly four visible surfaces**. Everything below is bounded by them.

**Primary focal anchor:** the lojista form submit CTA (`Revisar e gerar`) is the single
primary visual anchor of the lojista flow; the admin **`Resolver pendência`** CTA is the
single primary anchor of the admin surface.

**In scope (this contract covers):**

1. **Formulário (lojista)** — eligibility-gated **intent selector** (Oferta/Destaque/Exclusivo)
   and **direção de fundo** selector (Estúdio/Ambientado/Original), the rule *“Original exige
   exatamente uma imagem de produto”*, inline field validation, and the rule that exclusive
   controls are **mounted only when eligible** (applicable flag + authorization). In `off`,
   **no** exclusive selector/field is rendered and the legacy payload is sent intact.
2. **Acompanhamento da geração** — progress of a generation running **inside the request cycle**
   (NDJSON streaming), with the four states **em andamento / concluída / falha confirmada /
   resultado desconhecido**. The UI **shall not promise** post-disconnection continuity nor
   automatic resume.
3. **Resultado desconhecido** — message **“Não foi possível confirmar a conclusão desta geração”**
   plus a **support reference**; **no “Gerar novamente”** for this operation; a lojista resend
   is **query-only** (retrieves the saved art if it exists).
4. **Lista/resolução administrativa** — a **pending list only** (no automatic execution) and
   evidence-based **resolution by an authorized admin** with **mandatory reason** and an
   audited record (deliver existing art or refund once). **No re-queue, no new generation, no
   automatic provider call.**

**Explicitly out of scope (do NOT design/build here):**

- Approval / rejection / correction and correction billing — **F56.3**.
- Durable execution independent of the request/browser (queue/outbox, cron/dispatcher, worker,
  claim/lease/heartbeat/fencing, automatic resume) — **deferred** (needs Vercel Pro; new
  investigation). The UI must not imply any of it.
- Copy retry button, full E2E, paid pilot, enabling authorization — **F56.2b2** (`56.2.3`).
- Any new design token, light mode, or new component library.

**Locked inputs used:** `openspec/design-system/MASTER.md`; `56.1-UI-SPEC.md` (admin form analog);
`48.2.4-UI-SPEC.md` (generation-tracking analog); OpenSpec change
`fase-56-2b1b-nucleo-entregavel-produto-1-1/` (proposal, design B1B-D1..D12, tasks §0–§7,
`TRACEABILITY.md`); `56.2.2-CONTEXT.md`; `REQUIREMENTS.md` §F56.2b1b (REQ-56.2.2-01..13).
New-flow pair is **already decided** (primary `gpt-image-2.5-sunburst / medium`, fallback
`gpt-image-2 / medium`) — do **not** re-ask. Flags `false`; authorization `off`; no store enabled.

## Color

60/30/10 split per MASTER §2. Dark OLED only — **no light mode, no `#FFFFFF` backgrounds**.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#020617` (`bg-bg-deep`) | Page background (deepest layer) |
| Secondary (30%) | `#0F172A` (`bg-bg-surface`) / `#1E293B` (`bg-bg-elevated`) | Cards, panels, radio rows, hover/elevated surfaces |
| Accent (10%) | `#22C55E` (`accent-green`) | **Reserved** — see list below |
| Destructive | `#EF4444` (`accent-red`) | Destructive actions + error/validation states only |

**Accent reserved for (explicit, exhaustive):**

1. The single primary CTA per surface — lojista `Revisar e gerar`; admin `Resolver pendência`.
2. Success confirmation only (delivery confirmed / saved-with-audit message + `Check` icon).

**Semantic colors (from MASTER, not “accent”):**

- `accent-blue` `#3B82F6` — focus rings (`ring-accent-blue`), header eyebrow dot, informational
  banners, and the **“em andamento” (running)** generation state.
- `accent-amber` `#F59E0B` — **the “resultado desconhecido” state** (attention, *not* failure),
  incomplete-eligibility / not-active warnings, and admin warn banners.
- `accent-red` `#EF4444` — **falha confirmada**, validation errors, load/save errors, and the
  destructive **Estornar** action.
- `accent-green` `#22C55E` — **concluída / delivered** success and the accent-reserved items above.

**Critical semantic rule — unknown ≠ failure.** The **resultado desconhecido** state is rendered
in **amber** (attention/uncertainty), never red. Red is reserved for a **confirmed failure**.
Do not color “all interactive elements” green.

## Surface 1 — Formulário (lojista)

**Route:** existing `/campanhas/nova` (`src/app/(app)/campanhas/nova/page.tsx` →
`CampaignPageClient` → `campaign-input-form.tsx`). No new top-level route.

**Anatomy (form region, order preserved):**

```
<CampaignInputForm>
  ├─ product name / description / prices / badge            (legacy, unchanged)
  ├─ product images (principal + up to 3 adicionais)        (legacy, unchanged)
  ├─ A. Intenção da campanha  (radio group)                 ← eligibility-governed
  │      Oferta · Destaque · Exclusivo
  ├─ B. Direção de fundo      (radio group)                 ← EXCLUSIVE new-flow control
  │      Estúdio · Ambientado · Original
  ├─ C. Inline validation feedback (per field, on blur)     ← role="alert"
  └─ D. Submit CTA "Revisar e gerar"                        ← single primary anchor
```

**Eligibility gating (B1B-D1 / REQ-56.2.2-01):**

- The server decides eligibility (valid read of **both** flags, the flag applicable to the scope
  ON, and independent authorization in force) and passes it to the client.
- **Eligible:** region A (intent) and region B (direção de fundo) are **mounted**; the POST sends
  the new-flow fields (`backgroundDirection`, `campaignIntent`) and the exclusive payload.
- **Not eligible / `off` (current state):** neither region A’s new-flow treatment nor region B is
  rendered as an exclusive control; **no exclusive field** is sent; the **legacy payload remains
  byte-compatible** (`buildCampaignGenerationBody` output unchanged). This phase ships and tests
  both branches but keeps flags `false` and authorization `off` in production (B1B-D11).
- Revocation between render and POST is rejected server-side **before credit** with a safe error;
  the client redraws without the exclusive controls and **does not discard** the user’s draft fields.

**Direção de fundo options (labels → semantics):**

| Label | Meaning | Requirement |
|-------|---------|-------------|
| `Estúdio` | Clean studio background composed by the pipeline | none extra |
| `Ambientado` | Contextualized ambient/scene background | none extra |
| `Original` | Uses the original product image as the composition basis | **exactly one product image** |

**Rule — “Original exige exatamente uma imagem de produto”:** when `Original` is selected and
the product-image set is not exactly one, block submit and show an inline error on the image
field (region C): `A direção Original usa exatamente uma imagem de produto. Ajuste as imagens para continuar.`
Selection can switch to `Estúdio`/`Ambientado` to proceed with multiple images. Enforced on the
server too, before credit.

**Validation feedback:** inline on **blur** (MASTER §6.3 — never validate only on submit),
`text-accent-red text-xs` with `AlertCircle` below the field, `role="alert"`; success/pass states
use `text-accent-green text-xs` with `Check`.

## Surface 2 — Acompanhamento da geração

**Where:** inline in the lojista flow during submit and on the persisted campaign page
(`/campanhas/[id]`), reusing the `GenerationProgress` shell.

**Progress source:** generation runs **inside the request cycle** with **NDJSON streaming**
(`src/app/api/campaign/generate-image/route.ts`, `runtime = "nodejs"`). The browser watches; it
does **not** control durable execution.

**Required states (the four):**

| State | Color | Copy (see Copywriting) | Behavior |
|-------|-------|------------------------|----------|
| **Em andamento** | `accent-blue` | `Gerando a campanha...` + current phase message | Phase nodes + spinner; submit disabled. |
| **Concluída** | `accent-green` | `Campanha gerada.` | Art shown (private Storage, `delivered`); download enabled. |
| **Falha confirmada** | `accent-red` | `A geração falhou e o crédito foi devolvido.` | One-time `refunded`; **no** reuse of the same operation; user may start a **new** campaign. |
| **Resultado desconhecido** | `accent-amber` | `Não foi possível confirmar a conclusão desta geração` | Surface 3; pending/limited; query-only. |

**Continuity disclaimer (B1B-D2 / proposal “Comportamento quando a conexão cai”):** the UI
**shall not** state or imply that a disconnection cancels the provider call **or** that
processing will continue/resume. If the connection drops mid-generate, the view shows the
neutral persisted state (`Não foi possível confirmar a conclusão desta geração` per Surface 3
when unknown). **No** copy such as “pode fechar a página”, “continuaremos”, or “retomaremos”.

**Persisted result (B1B-D7 / REQ-56.2.2-09):** the concluded campaign is persisted and recoverable
**on return to the app**. The result page polls (`router.refresh()` every 5s, mirroring
`campanhas/[id]/client.tsx:26-34`) only to reflect persisted state — it does **not** control or
resume processing.

## Surface 3 — Resultado desconhecido

**Trigger:** a persisted operation whose outcome is **unknown** (e.g. provider timeout) —
pending/limited, **no** blind repetition, **no** resume (B1B-D5 / REQ-56.2.2-06, -07).

**Anatomy:**

```
<UnknownResultPanel>   (amber, banner/card — NOT an error/red state)
  ├─ Icon: <AlertTriangle /> (lucide, w-5 h-5, text-accent-amber, aria-hidden)
  ├─ Title:  "Não foi possível confirmar a conclusão desta geração"
  ├─ Body:   "A geração pode ter sido concluída ou interrompida. Não vamos repetir a
  │           geração automaticamente para não consumir um novo crédito."
  ├─ Support: "Referência de suporte: {IMG-001 / operation reference}"  (JetBrains Mono 12px)
  │           Action: "Falar com o suporte" (mailto: supportEmail)
  └─ Action: "Verificar novamente"  (SECONDARY — query-only, no new generation)
```

**Hard rules:**

- **NO “Gerar novamente”** button/link for this operation. Do not render it anywhere on this surface.
- The **only** lojista resend is **query-only**: “Verificar novamente” re-reads the saved operation
  by `campaignId + operation_id`; if a saved art exists it is retrieved, otherwise the unknown
  state is re-displayed. It starts **no** attempt, generation, or charge.
- The support reference is **opaque** (`IMG-001` + random reference, F56.1 decision) — never the
  internal cause. Use `supportEmail` from the page props (as `campanhas/nova/page.tsx:44,68`).
- **No** automatic refund is implied (resultado desconhecido is **not** refunded on timeout alone).

## Surface 4 — Lista/resolução administrativa

**Route (recommendation, discretion):** `/admin/product-1-1-pending` — a new, distinct admin page.
**Nav (recommendation):** add **one additive** `<Link>` to `(app)/admin/layout.tsx`, label
`Pendências Produto 1:1`. Existing links untouched, no reordering.

**Anatomy:**

```
<AdminShell> (existing (app)/admin/layout.tsx — requireAdmin + nav)
 └─ Page (max-w-5xl, space-y-6)
    ├─ A. Page Header
    │     eyebrow "Operação de IA" (blue dot) · title "Pendências do Produto 1:1" · description
    ├─ B. Read-only notice (ALWAYS visible)              ← this list NEVER executes anything
    │     "Esta lista é somente para consulta e resolução por evidência. Nenhuma geração
    │      é reiniciada, reenfileirada ou enviada automaticamente ao provedor."
    ├─ C. Pending list  (cards or table; one row per pending operation)
    │     • Produto / Loja (test store) · Campanha (id) · Estado da operação (badge)
    │     • Crédito: reserva temporária · Referência de suporte (mono)
    │     • Criado em · Última tentativa · Motivo de pendência (sanitized)
    │     • OR Empty State when no pending operation exists
    └─ D. Resolution panel (opens per row; client)
          • Evidence summary (read-only): arte existente? execução encerrada?
          • Admin action select: "Entregar arte existente" | "Estornar uma vez"
          • Motivo (required) textarea
          • Primary CTA: "Resolver pendência"
          • Inline error / success feedback
```

**Hard rules (B1B-D5 / REQ-56.2.2-08):**

- The list is a **pending list only** — **no** automatic execution, **no** re-queue, **no** new
  generation, **no** automatic provider call. The only affordance is evidence-based resolution.
- Resolution requires an **authorized admin**, a **mandatory `motivo`**, and an **audited,
  atomic record of the evidence and transition** (`resolve` is atomic/audited). No two-approver
  step in this version.
- `Entregar arte existente` is enabled **only** when integral art exists; `Estornar uma vez` is
  enabled **only** after confirming **absence of art and execution end**. Never present refund as
  a generic timeout remedy.
- After success, refresh so region C reflects the resolved operation (removed from the pending set).
- This is **not** approval/rejection/correction — those remain **F56.3**.

**Destructive confirmation:** `Estornar` is the only destructive action ⇒ confirm via a dialog
(MASTER §6.5): title `Estornar esta operação?`, body `Esta ação devolve o crédito reservado uma única vez e não pode ser desfeita.`, confirm `Estornar`, cancel `Cancelar`.

## Interaction & State Contract

| State | Behavior |
|-------|----------|
| Eligibility load | Server page decides eligibility (both flags + applicable flag + authorization). Client receives an `eligible` boolean. |
| Not eligible (`off`) | Regions A (new-flow) and B are **not mounted**; legacy payload sent unchanged; no exclusive field, no empty banner. |
| Eligible | Regions A and B mounted; POST includes `campaignIntent` + `backgroundDirection` + exclusive payload. |
| Background direction change | Selecting `Original` validates “exactly one product image”; violation blocks submit with inline error. |
| Image set change | Re-evaluates the `Original` rule when images are added/removed. |
| Submit | Validate fields client-side first; `Button loading` (disabled) with `Revisar e gerar` → review → generation. |
| Revocation between render and POST | Server returns a safe pre-credit error; client redraws without exclusive controls and **keeps** the draft (no field discard). |
| Generation streaming | Consume NDJSON; show the current phase; exactly one terminal event. |
| Connection drops | Show the persisted state; if unknown, Surface 3 (amber). Never claim guaranteed cancel or guaranteed continuation. |
| Resultado desconhecido | Amber Surface 3; **no “Gerar novamente”**; resend = `Verificar novamente` (query-only). |
| Concluída | `delivered`; download enabled only with integral object + `delivered` (`art_uploaded` alone does not unlock). |
| Falha confirmada | `refunded` once; message states the credit was returned; new attempts require a **new** campaign (new operation). |
| Admin list load | Server page reads pending operations + credit state; `export const dynamic = "force-dynamic"`. |
| Admin resolution | Require `motivo` client-side; then POST to admin API with Zod body, `requireAdmin`, `requireSameOrigin`, audited atomic RPC, stable `operationId` for idempotent resend. Never mutate via query builder. |
| Admin resolution success | `Resolução registrada com auditoria.` (`Check`, `text-accent-green`); refresh so resolved row leaves the pending set. |
| Admin unauthorized | Handled upstream by `(app)/admin/layout.tsx` → `redirect("/dashboard")`. No UI state needed. |
| Copy / cancel states | Persisted with safe feedback; **no retry action**; cancellations shown separately from copy status (B1B-D8). Never block art delivery on copy. |
| Reduced motion | All transitions 150–300ms via `transition-colors duration-200`; `motion-safe:`/`motion-reduce:`; no infinite animation except the spinner. |

- State meaning is encoded with **icon + text**, never color alone (unknown vs failure differ by
  icon and copy, not only by hue).
- Inline errors `role="alert"`; success `role="status"`; warnings/help associated via `aria-describedby`.
- Minimum interactive height 44px (radio rows `p-3`, selects `min-h-11`, `Button` 44px).
- Semantic HTML: `<header>`, `<main>` (layout), `<section aria-labelledby>`, `<form>`, `<fieldset>`.
- `prefers-reduced-motion` respected; transitions 150–300ms; no layout-shifting hover/scale.
- Contrast ≥7:1 on dark backgrounds — use only registered text tokens (MASTER §2).
- Support reference and operation ids use JetBrains Mono (selectable text; copy affordance optional).

## Non-Blocking Recommendations (agent discretion)

Recorded, not blocking. These were not answered by upstream artifacts and use sensible defaults:

1. **Route/nav naming** — `/admin/product-1-1-pending` + label `Pendências Produto 1:1` are

   “resultado desconhecido” never renders as a confirmed failure. [default]

   reserving green for success. [default]

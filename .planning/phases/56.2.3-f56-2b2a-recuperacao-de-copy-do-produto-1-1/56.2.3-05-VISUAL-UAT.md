## 1. Como iniciar e acessar a interface

1. **App local:** `npm run dev` (Next dev, porta 3000). `NEXT_PUBLIC_SITE_URL=http://localhost:3000`.
2. **Ambiente:** `.env.local` já aponta `NEXT_PUBLIC_SUPABASE_URL` para `http://127.0.0.1:56321` (instância isolada). Conferir **apenas a linha da URL**; nunca imprimir chaves.
3. **Login:** `/login`, e-mail + senha (`supabase.auth.signInWithPassword`). As credenciais do usuário de teste são definidas na preparação (§3) — conhecidas **apenas localmente**.
4. **Acesso à campanha:** `/campanhas/<CAMPAIGN_ID>`. A página exige usuário autenticado e **uma** loja do usuário (`stores.user_id = auth.uid()`); a campanha precisa pertencer a essa loja (leitura via client do usuário/RLS).

## 3. Preparação das fixtures (script local; a criar/aprovar antes de rodar)

Ferramenta: **script local** (Node/tsx) reutilizando os helpers existentes `src/lib/product-1-1/__tests__/integration-harness.ts` — **não** é rota do app nem contorna autorização. Passos:

6. Registrar `CAMPAIGN_ID`, `OPERATION_ID`, `STORE_ID` e as credenciais para o revisor.
7. Ao final do UAT: o revisor decide se os dados de teste permanecem ou são limpos (a limpeza é uma ação separada, **não** incluída aqui).

## 4. Como apresentar cada um dos 7 estados

Pré-requisito comum: `OPERATION_ID` com crédito `delivered` e arte válida (para a imagem aparecer). A **linha corrente** = maior `attempt_seq`; `lease_at` vigente = `now - lease_at < 45s`; espera = `updated_at + recovery.nextWaitMs`. Recarregar `/campanhas/<CAMPAIGN_ID>` após trocar as linhas.

> Convenção: substitua `:cid` = CAMPAIGN_ID e `:oid` = OPERATION_ID.

**Antes de cada caso:** `DELETE FROM public.product_1_1_copy_state WHERE campaign_id=':cid' AND operation_id=':oid';` e `DELETE FROM public.product_1_1_copy_cancellations WHERE campaign_id=':cid' AND operation_id=':oid';`

| # | Estado | Fixture (INSERT em `product_1_1_copy_state`) | Esperado na UI |
|---|---|---|---|
| a | **Textos entregues** (`concluída`) | `attempt_seq=1, state='completed', attempt_token=<uuid>, copy_text='Legenda pronta para publicar', copy_payload='{"title":"Oferta","caption":"Legenda pronta para publicar","hashtags":["#promo"],"cta_post":"Compre já","recovery":{"kind":"auto"}}'` | Badge **verde**, ícone `Check`, **"Textos prontos."**; **sem** CTA de recuperação; **textos exibidos** (painel de texto entregue) |
| b | **Tentativa ativa** | `attempt_seq=1, state='pending', attempt_token=<uuid>, lease_at=now(), copy_payload='{"recovery":{"kind":"auto"}}'` | Badge **azul**, **spinner**, botão **desabilitado** |
| c1 | **Espera (correndo)** | `attempt_seq=1, state='failed', attempt_token=<uuid>, updated_at=now(), copy_payload='{"recovery":{"kind":"auto","failureClass":"transient","nextWaitMs":5000}}'` | **Aguardando**: **contagem 5s** (`role="timer"`), botão **desabilitado** enquanto conta |
| c2 | **Espera vencida → retomada manual** *(correção aprovada)* | igual a c1 com `nextWaitMs=0` (ou `updated_at=now()-interval '10 seconds'`) | **Aguardando** com **0s** e CTA **habilitada** para retomada **manual** (sem aba dirigente) |
| d | **Leitura indisponível** (`indeterminada`) | **não é possível só com dados** — ver §6 | Painel **âmbar** "indeterminada", `canRetry=false`, ação **"Verificar novamente"** (query-only), **sem spinner**; **arte continua visível** |
| e | **Falha definitiva** | `attempt_seq=1, state='failed', attempt_token=<uuid>, copy_payload='{"recovery":{"kind":"auto","failureClass":"definitive"}}'` | **Falha definitiva**: ícone `ShieldAlert`, CTA **Gerar os textos novamente** + **Falar com o suporte** |
| f | **Automáticas esgotadas** | 3 linhas `recovery.kind='auto'` (`attempt_seq=1,2,3`), corrente `attempt_seq=3, state='failed', failureClass='transient'` | **Falha**: contador **automáticas 3 de 3**; CTA habilitada (manual disponível, 0<3) |
| g1 | **Interrupção com retomada manual** | `attempt_seq=1, state='failed', attempt_token=<uuid>, copy_payload='{"recovery":{"kind":"manual","failureClass":"transient"}}'` | **Interrompida**: badge âmbar, **sem spinner**, CTA habilitada (`canRetry=true`), contador manual ≥1 |
| g2 | **Limite manual atingido** | 3 linhas `recovery.kind='manual'` (`attempt_seq=1,2,3`, `state='failed'`) | **Interrompida** com **"Tentativas manuais: 3 de 3"**, CTA **desabilitada** + **"Você atingiu o limite de tentativas. Fale com o suporte para continuar."** |

## 5. Checagens transversais (obrigatórias)

- **Arte visível/baixável:** a imagem aparece **antes** dos painéis e o botão/link de download funciona (URL assinada server-side). Independe dos estados de copy.
- **Contadores:** `Tentativas automáticas: N de 3` e `Tentativas manuais: M de 3` coerentes com as linhas (contagem por `recovery.kind`).
- **Máximo 3 manuais:** no caso **g2** a CTA fica `disabled` + `aria-disabled="true"` e mostra a mensagem de limite.
- **Reload/outra aba NÃO inicia automática:** com o caso **c1/c2** aberto, **recarregar** (F5) e/ou abrir a mesma URL em **outra aba** e observar a **aba Network**: **não** pode haver `POST /api/campaign/<id>/copy-recovery`. A aba sem handle (`isDriving=false`) apenas **acompanha** (contagem + CTA manual) — nunca emite `auto_retry`.
- **Aviso de escopo:** "Isso gera apenas os textos. A imagem da campanha não muda e nenhum crédito adicional é usado." presente no painel.
- **Sem emojis / dark OLED / sem vermelho para falha de copy.**

## 6. Estado (d) `indeterminada` — alternativa LOCAL (apresentar antes de implementar)

`indeterminada` só aparece quando a leitura do **sumário** **lança** (`readCopyAttempts` → erro PostgREST); **nenhum valor de dados** provoca isso (tabela vazia ⇒ `null`/sem superfície). Portanto, apresentá-la exige uma manipulação **local e reversível** (a autorizar):

- **Opção 1 (preferida, cirúrgica):** renomear a coluna lida **só** pela consulta de tentativas, preservando a leitura da entrega:
  - Quebrar: `ALTER TABLE public.product_1_1_copy_state RENAME COLUMN lease_at TO lease_at_hidden;` (+ `NOTIFY pgrst, 'reload schema';`)
  - Restaurar: `ALTER TABLE public.product_1_1_copy_state RENAME COLUMN lease_at_hidden TO lease_at;`
  - Requisito: a linha corrente **não** pode estar `state='completed'` (senão a precedência de sucesso devolve `concluída`). Com uma linha `pending/failed` corrente ⇒ **indeterminada** com **arte visível**.
- **Opção 2 (ampla):** `REVOKE SELECT ON TABLE public.product_1_1_copy_state FROM service_role;` → `GRANT SELECT ON TABLE public.product_1_1_copy_state TO service_role;` (a entrega também falha ⇒ `delivery=null`; ainda assim ⇒ **indeterminada** com arte).

> **Nada disso está autorizado nem implementado.** Se o revisor quiser apresentar (d) ao vivo, escolha a opção e autorize; caso contrário, (d) permanece coberto apenas pelo teste automatizado.

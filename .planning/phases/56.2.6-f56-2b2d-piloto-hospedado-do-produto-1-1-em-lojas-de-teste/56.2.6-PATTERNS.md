## Shared Patterns

### 1. RPC-only / `SECURITY DEFINER` / append-only / REVERT
**Fonte:** `supabase/migrations/20261017000001_f56_2b2c_narrow_authorization.sql` (16-28, 96-166), `20261008000001`, `20261008000004`.
**Aplicar a:** nova migration.
```sql
CREATE OR REPLACE FUNCTION public.admin_grant_product_flow_stage_authorization(
  p_actor_id UUID, p_stage TEXT, p_scope TEXT,
  p_instance_identity TEXT, p_reason TEXT, p_operation_id UUID
) RETURNS JSONB LANGUAGE plpgsql SECURITY DEFINER SET search_path = '' AS $$ ... $$;
REVOKE ALL ON FUNCTION public.admin_grant_product_flow_stage_authorization(UUID, TEXT, TEXT, TEXT, TEXT, UUID)
  FROM PUBLIC, anon, authenticated;
GRANT EXECUTE ON FUNCTION public.admin_grant_product_flow_stage_authorization(UUID, TEXT, TEXT, TEXT, TEXT, UUID)
  TO service_role;
```
Assinatura de **6 parâmetros** preservada (sem overload). Tabela: `service_role` **SELECT-only**; escrita só por RPC; trigger de imutabilidade; bloco `REVERT` comentado.

### 2. Identidade canônica server-side + fail-closed
**Fonte:** `src/lib/product-1-1/authorization/instance-identity.ts` (18-37) e `submission/eligibility-context.ts` (24-40).
**Aplicar a:** rota admin, gate de gasto, testes.
```ts
export function resolveCanonicalInstanceIdentity(): string {
  const rawUrl = process.env.NEXT_PUBLIC_SUPABASE_URL ?? process.env.SUPABASE_URL ?? "";
  if (rawUrl.trim() === "") throw new Error("product_flow_instance_config_missing");
  let url: URL;
  try { url = new URL(rawUrl); } catch { throw new Error("product_flow_instance_config_invalid"); }
  if (!url.host) throw new Error("product_flow_instance_config_invalid");
  return url.host; // comparação EXATA; nunca do payload
}
```
`expectedEnvironment` é derivado do host server-side (`LOOPBACK_HOSTNAMES` ⇒ `isolated`, senão `operational`). **Nunca** aceitar instância/ambiente do cliente.

### 3. Matriz de autorização já fechada — reusar, não reescrever
**Fonte:** `src/lib/product-1-1/authorization/authorization-decision.ts` (24-56).
```ts
export const STAGE_SCOPE_COMPATIBILITY = { off: [], isolated_pilot: ["test_stores"],
```

### 4. Tri-state do gate de gasto (nunca desarmar por incerteza)
**Fonte:** `src/lib/product-1-1/pilot/resolve-pilot-spend-gate.ts` (9-74) e `pilot/spend-control.ts` (11-97).
**Aplicar a:** gate operacional.
- `armed` só com via **estreita** + flag aplicável válida;
- `inactive` só para leitura **determinística** de piloto desligado (segue legado);
- `blocked` para **qualquer incerteza** (falha de leitura/flags/contexto) e para `all_stores`;
- a chamada paga só ocorre com `acquired`; `existing_in_flight`/`closed` nunca chamam provider; `markUnknown` bloqueia novas chamadas **sem liberação por tempo**.

### 5. Fence de publicação (não reimplementar)
**Fonte:** `generation-orchestrator.ts` (196-232, 883-997), `credit-operation-client.ts`, migration `20261016000001_f56_2b2b_publication_fence.sql`.
**Aplicar a:** orquestração/deadline.
- `beginPublication` adquire token **antes** do upload; `abort` só `before_upload`; `markResultUnknown` para incerteza;
- frescor do epoch capturado **antes** da sonda; `evidence_stale` bloqueia encerramento;
- `integral`/`invalid`/`indeterminate` **nunca** autorizam estorno; só `absent` + `failed` persistido + decisão terminal;
- kill **não** prova ausência e **não** autoriza via nenhuma (automática exige probe fresco + fence; administrativa exige autorização/auditoria).

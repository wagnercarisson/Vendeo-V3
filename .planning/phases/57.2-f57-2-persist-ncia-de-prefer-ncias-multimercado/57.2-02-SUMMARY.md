# 57.2-02 — Fundação market-preferences + idioma do aplicativo

## Entregue

- `src/lib/market-preferences/errors.ts`: taxonomia fechada (6 códigos), 5 classes com status e
  3 type guards + extração de versão de HINT/DETAIL, sem lançar em entrada `unknown`.
- `src/lib/market-preferences/dtos.ts`: DTOs allowlisted, renomeação explícita
  (`ui_locale → uiLocale`, `ui_locale_source → source`, demais colunas snake_case), sem spread de
  linha crua e sem identificadores internos.
- `src/lib/market-preferences/user-preferences-service.ts`:
  - `mapStoredUserLocalePreference` é o único tradutor linha→DTO (GET, PATCH omitido e pós-escrita);
  - `NULL + legacy_br` ⇒ `pt-BR/legacy_br`; `valor + explicit` ⇒ valor; qualquer outro par ⇒ 500;
  - leitura sem linha ⇒ `pt-BR/legacy_br` versão 0 sem escrita; erro de banco ⇒ 503;
  - escrita via `write_user_locale_preference` com exatamente 3 chaves (sem fonte);
  - `null` limpa; valor é revalidado; omitido apenas valida a versão e **não chama RPC**;
  - conflito usa versão do hint (fallback: releitura); retorno incoerente ⇒ 500.
- `src/app/api/preferences/route.ts`: `GET`/`PATCH` com `apiHandler`, `requireApiUser`, CSRF no
  PATCH, Zod estrito e HTTP 200/400/401/403/409/500/503.
- Testes: DTOs (allowlist/renomeação), serviço (legado, null, omitido, CAS, corrupção, A/B,
  3 chaves) e rota (todos os status, `userId` no corpo rejeitado, sem chaves cruas).

## Decisões de implementação

- `StoredPreferencesInvalidError` é o único erro de linha persistida inválida; nenhum caminho
  devolve `pt-BR` quando há `error`.
- `updateUserLocalePreference` mantém `uiLocale: undefined` como “omitido”; o valor explícito
  `null` é preservado e convertido em limpeza pela RPC.
- O serviço usa `supabaseAdmin` apenas para leitura filtrada pelo `userId` do servidor e para a RPC;
  nenhum `insert`/`update` direto de tabela.
- `src/lib/market-context/**` não foi alterado.

## Divergência constatada

No relatório do checkpoint `prove` (2026-10-28), a ACL real do homolog era:

```text
postgres=X/postgres, anon=X/postgres, authenticated=X/postgres, service_role=X/postgres
```

O bloco ativo versionado em
`supabase/migrations/20260920000001_f50_demo_credits.sql` determina:

```sql
REVOKE ALL ON FUNCTION public.admin_create_store_for_user(UUID, UUID, TEXT, TEXT)
  FROM PUBLIC, anon, authenticated;
GRANT EXECUTE ON FUNCTION public.admin_create_store_for_user(UUID, UUID, TEXT, TEXT)
  TO service_role;
```

A F57.2 **não recriou** essa função; as duas migrations F57.2 são
`20261028145738` (schema/RPCs) e `20261028171746` (onboarding/settings).

## Investigação da origem — evidências disponíveis

- `20260914000002_f47_fix_admin_create_store_lint.sql` usa `CREATE OR REPLACE` para a
  função, sem um `GRANT` posterior para `authenticated`.
- O bloco ativo da F50 revoga `PUBLIC, anon, authenticated` e concede a `service_role`.
- Não foi encontrado, nas migrations versionadas consultadas, um `GRANT EXECUTE` para
  `anon`/`authenticated` dessa assinatura.
- A ACL observada é semelhante ao estado default de função recriada, mas **a origem da
  divergência não está concluída**. Hipóteses não confirmadas: aplicação parcial/fora de
  ordem, operação manual, restore/seed externo ou recriação posterior não versionada.
- O estado de produção é **desconhecido** nesta entrega.

Não trate a hipótese preferida como diagnóstico. A investigação remota exige autorização
separada e evidência read-only.

## Risco

A função é `SECURITY DEFINER` e o corpo versionado não verifica o papel administrativo do
chamador. A proteção da rota web não substitui a proteção da RPC direta. Enquanto
`anon`/`authenticated` tiverem `EXECUTE`, a superfície direta permanece exposta. Não testar
exploração; registrar e corrigir a ACL primeiro.

## Aplicação em transação única

Somente após preflight aprovado e autorização explícita. O arquivo SQL controla
`BEGIN`/`COMMIT`; **não** usar `--single-transaction` junto.

```powershell
$localSql = "scripts/f57-2/reconcile-admin-acl.sql"
$containerSql = "/tmp/f57_2_reconcile_admin_acl.sql"
$applyLog = ".planning/phases/57.2-f57-2-persist-ncia-de-prefer-ncias-multimercado/evidence/57.2-05-admin-acl-reconcile.txt"
$applyErr = ".planning/phases/57.2-f57-2-persist-ncia-de-prefer-ncias-multimercado/evidence/57.2-05-admin-acl-reconcile-stderr.txt"

docker cp $localSql "supabase_db_vendeo-homolog:$containerSql"
if ($LASTEXITCODE -ne 0) { throw "docker cp falhou; não aplicar" }

$localHash = (Get-FileHash $localSql -Algorithm SHA256).Hash.ToLowerInvariant()
$containerHash = (docker exec supabase_db_vendeo-homolog sha256sum $containerSql | ForEach-Object { ($_ -split '\s+')[0] })
if ($LASTEXITCODE -ne 0 -or $containerHash -ne $localHash) {
  docker exec supabase_db_vendeo-homolog rm -f $containerSql
  throw "hash da cópia divergiu (local=$localHash container=$containerHash); não aplicar"
}

try {
  $applyOutput = & docker exec supabase_db_vendeo-homolog psql `
    -U postgres -d postgres -v ON_ERROR_STOP=1 -f $containerSql 2> $applyErr
  $applyExit = $LASTEXITCODE
  $applyOutput | Tee-Object -FilePath $applyLog
} finally {
  docker exec supabase_db_vendeo-homolog rm -f $containerSql
  $removeExit = $LASTEXITCODE
}
if ($applyExit -ne 0) { throw "psql falhou (exit=$applyExit); rollback pelo ON_ERROR_STOP; ver $applyLog" }
if ($removeExit -ne 0) { throw "a cópia temporária não foi removida; verificar $containerSql" }
```

O arquivo `scripts/f57-2/reconcile-admin-acl.sql`:

- captura owner, ACL, hash do corpo e definição antes;
- valida banco/assinatura/`SECURITY DEFINER`/marcadores do corpo;
- executa somente `REVOKE EXECUTE ... FROM PUBLIC, anon, authenticated` e
  `GRANT EXECUTE ... TO service_role` nessa assinatura;
- não altera owner, corpo ou assinatura;
- verifica `anon=false`, `authenticated=false`, `service_role=true`, ausência de
  `PUBLIC`, owner e hash do corpo inalterados;
- usa `ON_ERROR_STOP` e controla a transação no próprio arquivo (`BEGIN`/`COMMIT`).


## Verificação pós-condição

```sql

       has_function_privilege('anon', p.oid, 'EXECUTE') as anon_can_execute,
       has_function_privilege('authenticated', p.oid, 'EXECUTE') as authenticated_can_execute,
       has_function_privilege('service_role', p.oid, 'EXECUTE') as service_role_can_execute,
       md5(p.prosrc) as body_md5
  from pg_proc p join pg_namespace n on n.oid=p.pronamespace
 where n.nspname='public'
   and p.proname='admin_create_store_for_user'
   and oidvectortypes(p.proargtypes)='uuid, uuid, text, text';
```

`service_role_can_execute=true`, sem grantee `PUBLIC` para EXECUTE, owner e `body_md5`
iguais ao préflight.

## Pattern Assignments

### `src/lib/market-preferences/errors.ts` (utility, error taxonomy)

**Analog:** `src/lib/auth/errors.ts` (classes) + `src/lib/market-context/validation.ts:90-103` (`createError` frozen typed object).

O projeto tem **dois** estilos: classes `Error` (`auth/errors.ts`) para o que `apiHandler` intercepta, e objetos congelados tipados (`market-context`) para contratos puros. Este módulo precisa dos dois:

- **Classes** para o que atravessa a rota e vira status HTTP (não interceptadas por `apiHandler` — ver landmine L3).
- **Códigos string** para o corpo de resposta (`{ error, code }`), conforme specs (`country_not_mutable`, `preferences_unavailable`, `settings_version_conflict`, `preferences_version_conflict`, `stored_preferences_invalid`).

**Padrão de classe** (`src/lib/auth/errors.ts:1-20`):

```ts
export class StoreNotFoundError extends Error {
  constructor(message = "Store not found or access denied") {
    super(message);
    this.name = "StoreNotFoundError";
  }
}
```

**Padrão de erro congelado com campo/reason** (`src/lib/market-context/validation.ts:83-103`):

```ts
export interface CreateErrorOptions {
  readonly field?: string;
  readonly received?: unknown;
  readonly reason?: MarketContextErrorReason;
}

export function createError(code: MarketContextErrorCode, options: CreateErrorOptions = {}): MarketContextError {
  const error: MarketContextError = {
    code,
    ...(options.field !== undefined ? { field: options.field } : {}),
    ...(options.received !== undefined ? { received: options.received } : {}),
    ...(options.reason !== undefined ? { reason: options.reason } : {}),
  };
  return Object.freeze(error);
}
```

**Regra**: `*_source`/`country_source` e `code` são uniões literais fechadas — nunca `string`.

### `src/lib/market-preferences/dtos.ts` (utility, allowlist transform)

**Analog:** `src/lib/store-public-dto.ts` (allowlist por chave, nunca spread do raw).

**Allowlist + `pickKeys`** (`src/lib/store-public-dto.ts:48-77, 104-117`):

```ts
const PUBLIC_STORE_KEYS = ["id", "user_id", "name", /* ... */] as const;

function isRecord(value: unknown): value is Record<string, unknown> {
  return !!value && typeof value === "object" && !Array.isArray(value);
}

function pickKeys(source: Record<string, unknown>, keys: readonly string[]): Record<string, unknown> {
  const out: Record<string, unknown> = {};
  for (const key of keys) {
    if (key in source) out[key] = source[key];
  }
  return out;
}

export function toPublicStoreDTO(raw: Record<string, unknown>): PublicStoreDTO {
  const dto: Record<string, unknown> = pickKeys(raw, PUBLIC_STORE_KEYS);
  dto.cnpjRegistered = typeof raw.cnpj_normalized === "string" && raw.cnpj_normalized.length > 0;
  return dto as unknown as PublicStoreDTO;
}
```

**Comentário de intenção a copiar** (`src/lib/store-public-dto.ts:3-12`): o DTO é “a única barreira antes da resposta HTTP”, construído por allowlist explícita, nunca por spread — porque a linha crua contém identificadores internos.

Aplicar a `StoreMarketSettingsDTO` (`countryCode`, `countrySource`, `defaultCampaignMarket`, `defaultCampaignMarketSource`, `defaultContentLocale`, `defaultContentLocaleSource`, `defaultCurrency`, `defaultCurrencySource`, `timeZone`, `timeZoneSource`, `contextVersion`, `settingsVersion`) e `UserLocalePreferenceDTO` (`uiLocale`, `source`, `version`) — o DTO expõe `source`, NÃO `uiLocaleSource`. **Nunca** incluir `store_id`, `user_id` do alvo, `created_at`/`updated_at` se não especificado, nem qualquer campo fiscal/billing.

**Teste do DTO** deve seguir `src/lib/__tests__/store-public-dto.test.ts:42-59` (serializar o DTO e afirmar `not.toContain("...")`).

**Validação/derivação** — reutilizar puro (`src/lib/market-context/user-preference.ts:25-95`):

```ts
import { resolveUiLocale } from "@/lib/market-context";

// Mapa FECHADO — nunca tratar qualquer linha como preferência explícita.
// NULL + legacy_br => resolveUiLocale({ kind: "legacy" }) => pt-BR/legacy_br
// valor + explicit => resolveUiLocale({ kind: "explicit", uiLocale })
// qualquer outro par (valor+legacy_br, NULL+explicit, NULL+NULL, source desconhecido) => StoredPreferencesInvalidError
const resolution = resolveUiLocale(
  data.ui_locale === null && data.ui_locale_source === "legacy_br"
    ? { kind: "legacy" }
    : data.ui_locale !== null && data.ui_locale_source === "explicit"
      ? { kind: "explicit", uiLocale: data.ui_locale }
      : null,
);
if (!resolution || !resolution.ok) throw new StoredPreferencesInvalidError();
```

`resolveUiLocale` **nunca** recebe loja/país/mercado (regra dura documentada em `user-preference.ts:19-24`) — é exatamente a garantia “idioma do app independe do país da loja”.

**Escrita via RPC** — padrão de chamada RPC com erro checado (`src/app/api/store/route.ts:322-364`):

```ts
const { data, error } = await supabaseAdmin.rpc("write_user_locale_preference", {
  p_user_id: userId,          // vem do servidor (requireApiUser), NUNCA do body
  p_ui_locale: uiLocale,      // string | null
  p_expected_version: expectedVersion,
});
if (error) { /* mapear conflict / unavailable */ }
```

**Semântica PATCH** (spec `user-locale-preference`):
- campo omitido → **NÃO chama a RPC** e NÃO materializa/reescreve nada; apenas valida a versão contra a leitura atual e devolve o DTO (sem escrita);
- `null` → limpa e resolve `pt-BR`/`legacy_br`;
- inválido → `400` com `fieldErrors`, sem chamar RPC.

### `supabase/migrations/<UTC>_f57_2_market_preferences.sql` (migration, DDL + RPC)

Composição de cinco analógicos. **Não** criar a migration no planejamento (decisão travada).

**1) Tabela + checks + RLS de tabela filha** — `20260723000003_create_legal_acceptances.sql:5-37`:

(Repetir `SET search_path = ''` em toda função — padrão constante: `f34:68`, `f36:42`, `f50:936`, `create_credit_tables:134`.)

**3) RPC idempotente + lock + CAS** — `20260716000001_create_credit_tables.sql:163-201` é o molde exato de “linha ausente não é protegida por `FOR UPDATE`”:

```sql

  INSERT INTO public.credit_balances (store_id, balance)
  VALUES (p_store_id, 0)
  ON CONFLICT (store_id) DO NOTHING;

  -- Lock row and read current balance
  SELECT balance INTO balance_before
  FROM public.credit_balances
  WHERE store_id = p_store_id
  FOR UPDATE;

  IF balance_before IS NULL THEN
    INSERT INTO public.credit_balances (store_id, balance)
    VALUES (p_store_id, 0)
    ON CONFLICT (store_id) DO NOTHING;
    balance_before := 0;
  END IF;
```

Aplicar a: `ensure_store_market_settings` (`ON CONFLICT (store_id) DO NOTHING`, deriva defaults) e `write_store_market_settings` / `write_user_locale_preference` (`INSERT ... DO NOTHING` → `SELECT ... FOR UPDATE` → compara `_version` → `RAISE EXCEPTION` tipado com hint).

```ts
export async function requireUser(): Promise<AuthenticatedUser> {
  const supabase = await createServerClient();
```

### CSRF
**Source:** `src/lib/auth/csrf.ts:3-23`
**Apply to:** `PATCH /api/preferences`, `PATCH /api/store/market-settings` (nunca GET)
```ts
export function requireSameOrigin(request: Request): void {
  const origin = request.headers.get("origin");
  const host = request.headers.get("host");
  const forwardedHost = request.headers.get("x-forwarded-host");
  if (!origin) throw new ForbiddenError("Origin header required");
  let originUrl: URL;
  try { originUrl = new URL(origin); } catch { throw new ForbiddenError("Invalid origin"); }
  const effectiveHost = forwardedHost || host;
  if (!effectiveHost || originUrl.host !== effectiveHost) throw new ForbiddenError("Cross-origin request denied");
}
```

### Error → HTTP envelope
**Source:** `src/lib/auth/api-handler.ts:6-16` + `src/lib/api-error-response.ts:1-13`

```ts
export function apiHandler(handler: RouteHandler): RouteHandler {
  return async (...args) => {
    try { return await handler(...args); }
    catch (error) {
      if (error instanceof ForbiddenError) return forbidden(error.message);
      if (error instanceof UnauthorizedError) return unauthorized(error.message);
      if (error instanceof StoreNotFoundError) return notFound(error.message);

}
```

## Landmines (ler antes de planejar)

1. **`StoreFieldSource` ≠ vocabulário do design.** `src/lib/market-context/types.ts:81` define `"configured" | "default" | "legacy_br"`; o design/specs falam `explicit`. O banco guarda `explicit` e a biblioteca pura fala `configured`. O serviço precisa de um **mapa explícito** `db:'explicit' ↔ lib:'configured'` — não passar o valor direto, e não alterar `market-context` (contrato congelado, 72 testes).
2. **`getCurrentStore` / `requireOwnership` engolem `error`.** `store-ownership.ts:22-30, 41-54` fazem `const { data } = await ...` sem checar `error`. Reutilizá-los viola a decisão §10 (falha de banco viraria 404). Criar `loadOwnedStoreForMarketSettings` como descrito.
3. **`apiHandler` não conhece 409/503/500.** `api-handler.ts:11-14` só mapeia Forbidden/Unauthorized/StoreNotFound. Erros novos precisam de `try/catch` **dentro** de cada handler (como `store/route.ts:467-472` e `billing/confirm:39-44`), senão viram 500 genérico do Next.
4. **`.single()` vs `.maybeSingle()`.** `store-billing-info.ts:56-61` trata `PGRST116` como “sem linha”. Em 1:1 derivado (usuário) e na store (1 loja por usuário), `maybeSingle()` + checagem de `error` é mais seguro, mas `maybeSingle()` **também devolve `error`** em falha real — nunca descartar.
5. **RLS não concede privilégio de tabela.** `create_credit_tables.sql:111-114` documenta: “GRANT SELECT necessary for RLS to work with authenticated”. `legal_acceptances` não tem `GRANT SELECT` explícito (`20260723000003:20-37`) — ao criar `user_preferences`/`store_market_settings`, incluir `GRANT SELECT ... TO authenticated` (ou confirmar o default privilege do projeto) e **não** conceder INSERT/UPDATE/DELETE.
6. **Assinatura exata ao recriar RPCs.** `create_store_with_cnpj` tem 27 parâmetros (último `p_demo_grant_enabled BOOLEAN DEFAULT false`, `f50:904-932`); o `DROP FUNCTION IF EXISTS` precisa repetir a lista **sem defaults e sem nomes**, como em `f50:902`. Errar a lista deixa a versão antiga viva como overload.
7. **Não reintroduzir grant.** `create_store_with_initial_grant` vigente **não** concede crédito (`f50:1219-1240`, `balance = 0`) e `create_store_draft` retorna `onboardingGranted=false` (`f36:70`). Qualquer trecho copiado de `legal_acceptances` (`20260723000003:120-126` chama `public.grant_credits`) é histórico — **não** copiar.
8. **`legacy_pre_f32_onboarding_consumed`** é um `INSERT ... ON CONFLICT (root_hash, benefit_type, (COALESCE(cycle,'_nostring_'))) DO NOTHING` com índice de expressão (`f50:1046-1049`). Preservar literalmente, incluindo a expressão do `ON CONFLICT`.
9. **`search_path = ''`** obrigatório em toda função; por isso todas as referências são qualificadas (`public.stores`, `auth.uid()`).
10. **Timestamp de migration.** `AGENTS.md` e `docs/fluxo-de-desenvolvimento.md:36-41` exigem `YYYYMMDDHHmmss` UTC real e conferência de unicidade em worktree/main/branches paralelas — **antes** de criar e novamente antes do release. CONTEXT proíbe gerar a migration neste planejamento.
11. **Testes postgres rodam no `npm test` default.** `vitest.config.ts:23-31` não exclui `*.postgres.test.ts`; `npm test` = `vitest run` (`package.json:9`). Sem banco, a suíte já quebra hoje — planejar comando focado (`npx vitest run src/lib/__tests__/market-preferences-schema.postgres.test.ts, src/lib/__tests__/market-preferences-onboarding.postgres.test.ts e src/lib/__tests__/market-preferences-security.postgres.test.ts`) e `TEST_DATABASE_URL` explícito, nunca o fallback `127.0.0.1:54322` contra base compartilhada.
12. **`server-only`** em módulos importados por teste: mockar (`vi.mock('server-only', () => ({}))`, `check-readiness test:6`) ou depender do alias de `vitest.config.ts:4-13`.
13. **Rotas novas são API autenticada ativa sem UI** — não há flag/env nesta fatia (design §Migration Plan item 5); o teste de contrato é a única barreira.

# Phase 57.4 Plan 01: Base de tradução da interface — caminho de dados Summary

Fundação tipada de i18n (`pt-BR` | `es-419`) com catálogos congelados, resolução server-first via `cache()` + timeout de 200 ms e contrato de props proporcional no `AppShell`, sem dependências, migrations, APIs ou mudança de textos visíveis.

## What Was Built

- **Catálogos:** `common`, `shell`, `settings` em `pt-BR` (fonte de verdade) e `es-419` (`satisfies Messages`), congelados em todos os níveis.
- **Biblioteca client-safe:** `formatMessage` textual (sem HTML/eval), `translate` com fallback pt-BR → chave, `getCatalog` como único módulo que importa os catálogos.
- **Resolução server-side:** `getUiRenderContext(userId)` com `cache()` do React, `Promise.race` de 200 ms, timer limpo em `finally`, fallback conhecido e propagação de erro desconhecido; logs sem PII; timing opt-in via `I18N_TIMING=1`.
- **Layout:** resolve o locale no servidor e envia `locale`, `commonMessages`/`shellMessages` (pt-BR sempre) e `*Es` somente para `es-419`; namespace `settings` nunca vai ao shell.
- **AppShell:** contrato de props completo e `data-effective-locale` calculado por `usePathname` (admin forçado a `pt-BR`). Nenhum prop novo é encaminhado aos filhos neste plano.

## Known Limitations

- **`cache()` dedupe not reproduced in the node harness:** React's `cache()` only dedupes inside a server request scope; the unit harness does not create one, so it verifies the equivalent guarantees: no module state, distinct users never share results, and repeated calls are allowed to read again. Covered in `server.test.ts`.
- **`translate()` is defense-in-depth:** the UI consumes typed `messages.*` + `formatMessage`; no component is required to call `translate()`. Its tests keep the capability correct for future use.

## Known Stubs

None. This plan intentionally ships translated strings available in props but not yet consumed by children (plumbing-only scope; consumption is plan 02) — not a data stub.

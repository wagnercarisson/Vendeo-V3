# Phase 57.4 Plan 03: /configuracoes com idioma persistido Summary

`/configuracoes` autenticada e independente de loja, com leitura server-side sem escrita, formulário client de `fieldset`/radios nativos que salva apenas via `PATCH /api/preferences` (CAS + CSRF preservados), confirmação derivada de estado de sucesso e matriz completa de erros com `saving` encerrado em `finally`.

## What Was Built

- **`page.tsx` (Server Component):** `requirePageUser()` + `getUiRenderContext(user.userId)`; nenhuma chamada a `getCurrentStore`, `CreditService` ou `store-ownership`. `PageHeader` traduzido com breadcrumb Dashboard → Configurações, `Card` em `space-y-6 max-w-lg`, `lang` aplicado somente quando `locale === "es-419"`.

  `ok:true` → `SettingsLanguageForm` com `initialLocale`/`initialVersion`; `ok:false` → `SettingsLoadError`. O formulário nunca renderiza no ramo de falha.

- **`settings-load-error.tsx` (client):** `role="alert"` com `settings.error.load` e botão de retry 44 px (`RotateCcw`/`Loader2`) que chama `router.refresh()` dentro de `useTransition`, desabilitado enquanto `isPending`. Nenhum PATCH, nenhum formulário.

- **`loading.tsx`:** placeholder de título + `FormSkeleton`, no padrão de `conta/loading.tsx`.

- **`settings-language-form.tsx` (client):** import apenas de **tipo** (`@/lib/i18n/messages`, `@/lib/market-context`); nenhum valor do barrel `@/lib/i18n`. `fieldset`/`legend` com dois radios nativos (`name="uiLocale"`), seleção inicial das props, `dirty = selected !== savedLocale`, Salvar desabilitado sem mudança/durante envio/`isPending`. `PATCH /api/preferences` com `Content-Type: application/json` e `{ uiLocale, expectedVersion }`. Em `200` valida o DTO (locale suportado + `version` inteiro ≥ 0), atualiza seleção/`savedLocale`/`version`, marca `saved` (booleano) e chama `router.refresh()` em `startTransition`. Erros por status (409/403/401/400/5xx/4xx, `TypeError` → conexão) gravam apenas a **chave** de erro; a mensagem é lida de `messages` no render. `finally` sempre encerra `saving`. Conflito oferece `Recarregar` (nunca reenvia o PATCH).

- **Política de indexação:** `"/configuracoes"` adicionado a `PRIVATE_APP_PREFIXES` e à matriz `NOINDEX_SURFACES`; nenhuma outra regra alterada.

## Deviations from Plan

### Auto-fixed / structural

**1. [Rule 3 - blocking] Task 2 (form) was implemented before Task 1's GREEN**
- **Found during:** Task 1 GREEN.
- **Issue:** Task 1's behavior tests render the page and require the two radios, but `settings-language-form.tsx` is a Task 2 file. Without it the page cannot satisfy its own acceptance criteria.
- **Fix:** executed Task 1 RED → Task 2 RED → Task 2 GREEN (form) → Task 1 GREEN (page/loading/error/policy). Both tasks kept a real failing-first commit; the final state matches the plan's file ownership.
- **Commits:** `d145867b` (T1 test) → `3a9933b8` (T2 test) → `74dbab5f` (T2 feat) → `c8fcf6d6` (T1 feat) → `159a5b15` (T3 tests).

**2. [Rule 1 - dead state] `savedVersion` state omitted**
- **Found during:** Task 2 implementation.
- **Issue:** the plan listed `savedVersion` alongside `version`, but both would always hold the same value and only `version` feeds `expectedVersion`.
- **Fix:** single `version` state (initialized from props, updated from the 200 DTO). No behavior lost.

**3. [Rule 2 - correctness] Errors stored as a typed key, not a translated string**
- **Found during:** Task 2 implementation.
- **Issue:** the plan's `error: string | null` would freeze the message language at failure time and duplicate the "no stored translated string" rule already required for the success confirmation.
- **Fix:** `errorKey: keyof SettingsMessages["error"] | null`; the message (and the 401 `/login` link) is derived at render. Satisfies "no translated string in state" and stays locale-current after `router.refresh()`.

**4. [Rule 3 - blocking] `SettingsLoadError` uses `isPending` instead of a `retrying` + `finally` pair**
- **Found during:** Task 1 implementation.
- **Issue:** `router.refresh()` returns `void`; a `finally` around it would clear the loading state in the same tick, producing a fake pending indicator.
- **Fix:** the retry button is disabled by `isPending` from `useTransition` (the same signal used by the plan for reload actions in the form).

**5. [Test hygiene] amended the Task 2 RED commit**
- The es-419 label test initially omitted `initialLocale="es-419"`; the assertion was corrected before the GREEN commit (`git commit --amend` on the local test commit, not pushed).

### Known Limitations

- **`isPending` window is not observable in jsdom:** the tests mock `useRouter().refresh` as a synchronous no-op, so the transition settles inside `act()` and the "reload disabled while pending" state cannot be asserted black-box. The binding is implemented (`disabled={isPending}` on the reload button and on Salvar) and is exercised indirectly through the in-flight `saving` window (in-flight Salvar is asserted disabled). Plan 04's browser proof is the place to observe a real pending refresh.
- **`getUiRenderContext` cache dedupe** is still covered only at unit level (see plan 01 limitation); this plan relies on the same contract.

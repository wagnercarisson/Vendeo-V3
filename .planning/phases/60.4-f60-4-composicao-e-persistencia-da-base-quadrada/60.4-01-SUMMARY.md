## Deviations from Plan

### Auto-fixed / structural notes (no behavioral deviation)

1. **[Rule 3 — naming] Two dependency seams instead of one `SquareBaseDeps`**
   - Found during: Task 3.
   - The plan names a single `SquareBaseDeps`; this wave avoids a shared interface that plan 60.4-04 must later widen. Implemented `SquareBasePromptDeps` (`prompt.ts`, `promptBase` only) and `SquareBaseConfigDeps` (`config.ts`, client/clock/deadline/preflight/snapshot/persist/compose/pair seams). Plan 60.4-04 can compose them into its public `SquareBaseDeps`.

2. **[Rule 2 — correctness] `repairable` frozen state carries `operationId`**
   - Found during: Task 3.
   - Repair needs the operation identity to write evidence for the SAME snapshot without re-reading the binding. Added `operationId` to the `repairable` variant (additive) and populated it from the verified binding/input.

3. **[Rule 2 — correctness] `FrozenSnapshotRecord.createdAt`**
   - Found during: Task 3.
   - `ImageGenerationConfigSnapshot` requires `createdAt`; the reader now selects `created_at` so repair can rebuild the snapshot by value for `persistProductOneToOneSnapshot`.

4. **[Rule 2 — correctness] `deriveReferenceSelections` exported from `frozen-state.ts`**
   - Found during: Task 3.
   - The first composition must always freeze selections derived from the received data URLs (hash/kind/index) when the caller does not provide them. The helper is the single place applying the raw data URL hash rule, shared with the comparison.

5. **[Plan inconsistency — documented] forbidden-key source assertion**
   - The plan's acceptance says `rg "promptBase" types.ts validation.ts` should return only one forbidden-key occurrence in `validation.ts`, but the same plan places `FORBIDDEN_KEY_GROUPS` in `policy.ts` (single source) and types must carry `promptBaseVersion`.
   - Actual evidence: `policy.ts` contains `"promptBase"` in the `prompt_not_accepted` group; `validation.ts` contains no `promptBase` field read; `types.ts` contains only `promptBaseVersion` (frozen version), never an input `promptBase`. The forbidden-key behavior is proven per key by `validation.contract.test.ts`.

No bug, security, or blocking deviation required a plan change. No package install, no dependency added.

**Problema:** `referenceSelections: []` era preservado sem derivar hashes reais; a retomada comparava apenas `references` legadas e aceitava troca de produto/logo.

**Correção:**
- `config.ts` agora deriva SEMPRE as seleções reais de `productImagesDataUrls`/`identityImageUrl` (hash bruto, `kind`, ordem). Lista vazia é tratada como ausência e os hashes reais são congelados.
- Seleções fornecidas não vazias são validadas contra as imagens reais antes de preflight/persistência; divergência devolve `reference_selection_mismatch` sem I/O.
- `frozen-state.ts` compara as imagens reais contra as seleções congeladas; sem imagens verificáveis, imagem/logo recebidos são recusados (`references`).
- Seleções declaradas na retomada também precisam corresponder aos data URLs recebidos.
- Testes adicionados: lista vazia deriva produto+identidade; seleções divergentes falham antes de preflight; seleções correspondentes são aceitas; produto/logo diferentes e retomada idêntica cobertos.

## Deviations from Plan

### Auto-fixed / interpretation notes (no behavioral scope change)

1. **[Plan inconsistency — documented] `runSquareBaseCopy` takes no `attemptSeq` input.**
   - Found during: Task 1.
   - The plan's action line lists `attemptSeq` among the function inputs, but the acceptance criteria and the hard boundary state that the drain identity must come **exclusively** from `acquired` (`CopyAcquisitionResult`). An input `attemptSeq` would either be dead or become a second authority. The function therefore takes `{ campaignId, operationId, storeId, frozen, deadlineAtMs, usdBrlRateAtGeneration?, creditValueBrlAtGeneration?, traceId? }`, and `drainCopyTask` reads `attemptSeq`/`attemptToken` only from the acquisition envelope.

2. **[Rule 2 — correctness] Reused `attemptSeq` read from the persisted history.**
   - Found during: Task 1.
   - The `product_1_1_acquire_copy_attempt` RPC returns only `{ acquired: false, reason: "attempt_already_completed" }` (no sequence). To avoid fabricating `0`, `readPersistedCompletion` reads `readCopyDelivery` (text/payload) plus `readCopyAttempts` (current sequence) from the same table. Read errors map to `unavailable("read_failed")`.

3. **[Rule 2 — security/cost] Missing invoker fails closed.**
   - Found during: Task 1 hardening.
   - A runtime guard returns `unavailable("not_attempted")` before acquisition when `deps.invoker` is absent, so the default runner can never fall back to the default gateway (hidden retry). Covered by a dedicated test.

4. **[Interpretation] `copyOutcomeFromAcquisition` accepts only the losing variant (`CopyAcquisitionLoss`).**
   - The winner path is `runSquareBaseCopy`'s drain; typing the exported mapper to loss results keeps it total and prevents misuse (it cannot silently report `in_progress` for a winner).

5. **[Test seam] `copyOps` is a factory, not a runner instance.**
   - The plan deps list names `copyOps?`; implemented as `SquareBaseCopyOpsFactory(input, deps) => ops` so tests capture the exact runner input (frozen content, `runId`, pricing) while still exercising the real drain/store. Default remains `createDefaultProductOneToOneCopyOps`.

No bug, security or blocking deviation required a plan change. No package install, no dependency added.

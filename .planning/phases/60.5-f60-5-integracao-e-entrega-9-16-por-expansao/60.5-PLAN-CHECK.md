### W2 — `getOperationView` null conflates “absent” with “read failed” (m6)

- **Severity:** WARNING
- **Evidence:** `01/T4a` Test 1: missing operation and read error both return `null`; `03/T2a` maps `null` to 409 `operation_not_found`; `03/T2b` maps `null` to 404.
- **Impact:** a transient DB/read failure can be presented as “operation not found” and suppress a safe retry/processing path for a valid operation. No cost/data loss, but misleading and potentially blocking.
- **Fix:** return a discriminated result (`absent` vs `indeterminate`/`read_failed`) and map indeterminate to 5xx/processing; or document that `getOperationView` fails closed to 503 and test that path. Keep 404 only for a confirmed absence.
- **Addressed in plans (directed check, 2026-11-12):** `01/T4a` defines `OperationViewLookup = found | absent | read_failed`; `03/T2a` maps `absent`→409 and `read_failed`→503 `operation_unavailable`; `03/T2b` maps `absent`→404 and `read_failed`→503; behavior/acceptance tests added. Original finding preserved above.

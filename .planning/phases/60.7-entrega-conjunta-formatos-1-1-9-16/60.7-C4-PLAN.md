## 0. Decisões fechadas para C4

1. **C5a é gate pré-escrita.** Nenhuma escrita no homolog (DB/Storage/auditoria) começa antes de a baseline de conteúdo ser autorizada e capturada. O desenvolvimento **offline** do wiring pode preceder C5a; a validação integrada não.
2. **Wiring administrativo dedicado, sem tocar o legado.** C4 cria uma rota administrativa conjunta própria (`/api/admin/product-two-format-pending`) e uma composição de produção para `resolveJointPending`. O schema/rota legados de 1:1 não são alterados e não há fallback conjunto → legado.
3. **Sem fakes nas fronteiras DB/RPC/Storage.** A validação integrada usa PostgreSQL/PostgREST/RPC/Storage reais no ambiente local/homolog autorizado. Um adapter determinístico de provider é permitido **somente** como fronteira explícita e sem chamada paga; nunca é apresentado como provider real.
4. **Arte sintética, nunca de lojista.** Bytes canônicos são gerados/fixados localmente e persistidos com evidência F60.1 verificável (dimensão/MIME/checksum/metadata). Nenhum objeto real de loja é lido, copiado ou reutilizado.
5. **C4-A3 só é reivindicado se o wiring for realmente exercitado.** Se a autorização para a rota/escrita administrativa não for concedida, C4 para e registra **“entrega administrativa não coberta”**; C4-A1/A2/A4/A5 continuam obrigatórios e C4 não é declarado completo.
6. **Sem ativação.** A opção conjunta permanece indisponível ao lojista; nenhuma flag/pricing/publicação é alterada.
7. **Auditoria é pós-efeito e não transacional.** A janela efeito→auditoria permanece explicitamente documentada; `resolveJointPending` já trata replay/conflito. C4 não move a auditoria para SQL nem cria RPC.

## 2. Wiring administrativo (offline primeiro)

### 2.1 Contrato e rota
- Novo schema estrito em `src/lib/admin/schemas.ts`:
  - `campaignId`, `operationId` (controle), `format` (`"1:1" | "9:16"`), `action` (`"deliver" | "refund"`), `reason` (não vazio);
  - `.strict()`; nenhum `actorId`, evidência, path, checksum ou token aceito do cliente.
- Nova rota `src/app/api/admin/product-two-format-pending/route.ts`:
  - `requireAdmin` + `requireSameOrigin`;
  - classifica a campanha como `two_format`; `not_two_format`/`inconsistent` falham fechado sem cair em `resolvePendingOperation`/RPC legada;
  - chama `resolveJointPending` com `actorId` do admin e composição de produção;
  - mapeia resultado de forma tipada: `resolved`/`reconciled` → 200; `invalid_request` → 400; `blocked` → 409; `publication_pending` → 409; `audit_pending`/`audit_unavailable`/`unavailable` → 503; `audit_conflict` → 409;
  - nunca grava auditoria/efeito por query builder.
- **Sem UI nova obrigatória:** a rota é o wiring administrativo; o painel existente permanece intocado. Registrar explicitamente que a UI conjunta não foi coberta (se aplicável).

### 2.2 Composição de produção de `resolveJointPending`
Novo módulo server-only (nome indicativo `src/lib/product-two-format/admin/joint-admin-deps.ts`) compondo as portas reais:
- `readDelivery` → `readTwoFormatDelivery` (admin, operação de controle);
- `readResolutionState` → leitura conjunta real: vínculo por formato, crédito próprio e compartilhado, outcomes (view canônica), claim ativo, `storeId`, `linkComplete`;
- `probeSquare` → `CompositionSquareOriginalProbe` (bytes + evidência F60.1);
- `probeVertical` → sonda vertical real;
- `beginPublication`/`abortPublication`/`getPublicationEpoch` → `ProductOneToOneCreditOperationClient`;
- `recordFormatOutcome` → `ProductOneToOneAttemptStartClient.recordOperationOutcome`;
- `deliverFormat`/`refundFormat` → `TwoFormatJointFinancialClient`;
- `writeAudit`/`readAuditByOperationId` → `admin_audit_log` com ação `product_1_1_pending_resolution`, `metadata.flow:"two_format"`, `kind:"resolution"|"reconciliation"` e `operation_id = deliveryOperationId`.

## 3. Arte íntegra sintética

1. Gerar/fixar bytes JPEG determinísticos e autorizados; calcular `checksumSha256`, dimensões e MIME.
2. Persistir no bucket interno canônico via caminho de produção (`CompositionArtifactStorage.uploadImmutable` + `buildObjectEvidence` + linha em `campaign_composition_artifacts`), com `storeId/campaignId/operationId` sintéticos.
3. Provar `probeSquareOriginal` real → `integral` (bytes + row + metadata/evidência), não apenas linha no banco.
4. Negativo: linha sem objeto, objeto sem metadata/evidência, path/dimensão/MIME/checksum divergentes ⇒ `invalid`/`indeterminate`, nunca `integral`.
5. Nenhum byte/objeto de loja real é acessado; declarar fixture e retenção.

## 8. Riscos e limitações

1. **Provider determinístico ≠ provider real.** C4 não prova qualidade/arte real de IA; só a fronteira de entrega/evidência.
2. **Auditoria pós-efeito** continua não transacional; C4 prova retry/reconciliação, não atomicidade perfeita.
3. **C5a não prova o passado**; a janela de C é o limite, e C5b é etapa separada.
4. **UI administrativa conjunta** não é obrigatória; a rota é o wiring. A lacuna de UI deve ser declarada.
5. **Sem produção/ativação**: a opção conjunta continua indisponível ao lojista.

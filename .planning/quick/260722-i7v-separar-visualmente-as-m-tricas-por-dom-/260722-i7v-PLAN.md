  <behavior>
    - **getVsSuccessRate(hours)**: Fetches generation_events with generation_type="visual_signature", returns percentage of "success" status. Returns null if no data.
    - **getVsErrorRate(hours)**: Fetches generation_events with generation_type="visual_signature", returns percentage of "failed" status. Returns 0 if no data.
    - **getVsAvgDuration(hours)**: Fetches generation_events with generation_type="visual_signature" with non-null duration_ms, returns average. Returns null if no data.
    - **getVsCreditsConsumed(hours)**: Fetches credit_transactions with type="deduction" AND metadata->>feature="visual_signature", sums ABS(amount). Returns 0 if no data.
    - **getVsCreditsRefunded(hours)**: Fetches credit_transactions with type="refund" in the period. Classifies each refund:
        - If refund.metadata->>feature = "visual_signature" → count it.
        - If not, look up referenced deduction via reference column: fetch deduction by ID (no time filter), check its metadata.feature. If deduction is VS → count the refund.
        - Sums ABS(amount) for eligible refunds. Returns 0 if no data.
    - **getVsRefundRate(hours)**: Same classification logic as getRefundRate but scoped to VS domain. Returns 0 if denominator=0 (no VS deductions in period).
    - **Cross-window fix**: Both getRefundRate and getVsRefundRate use a shared helper:
        1. Query all credit_transactions in period
        2. Classify eligible deductions (campaign or VS) → Set<id>
        3. Classify refunds in period: if reference in eligible set → count. If orphan (reference not in any set), do second SELECT ... IN (orphanReferences) no time filter to find the referenced deduction
        4. If denominator=0 → return 0 (never critical from isolated old refund)
    - **duration_ms persistence for VS**: In generate-without-logo/route.ts, measure elapsed time and persist duration_ms in generation_events after generation completes (success or failure). Use existing pipeline-logger or direct update pattern.
  </behavior>

    **B) In pipeline-metrics.ts, add 6 new functions:**

    1. `getVsSuccessRate(hours)` — `.from("generation_events").select("status").eq("generation_type", "visual_signature").gte("created_at", hoursAgo(hours))` — return `Math.round((successCount / data.length) * 100)` or null.
    2. `getVsErrorRate(hours)` — Same query, `failedCount / data.length * 100` rounded, 0 if no data.
    3. `getVsAvgDuration(hours)` — Same query with `.not("duration_ms", "is", null)`, average of duration_ms, null if no data.
    4. `getVsCreditsConsumed(hours)` — `.from("credit_transactions").select("amount").eq("type", "deduction").eq("metadata->>feature", "visual_signature").gte("created_at", hoursAgo(hours))` — sum `ABS(amount)`, 0 if no data.
    5. `getVsCreditsRefunded(hours)` — Must include historical VS refunds via reference chain:
       - Fetch all refund-type transactions in period
       - Classify each: if `metadata->>feature = "visual_signature"` → count it directly
       - If not classified by metadata (historical), collect orphan references and do second SELECT ... IN (orphanIds) no time filter to find referenced deductions
       - If referenced deduction's metadata.feature = "visual_signature" → count the refund
       - Sum `ABS(amount)` for eligible refunds. Returns 0 if no data.
    6. `getVsRefundRate(hours)` — Scoped to VS domain. Same shared classification helper as getRefundRate (refactored). Returns 0 if denominator=0.

    **C) Cross-window refund reference fix (shared helper):**
    Extract a shared `classifyDomainRefunds(data, isDomainDeduction, featureFilter)` helper:
    1. Separate deductions and refunds from the queried data
    2. Classify eligible deductions using `isDomainDeduction(deduction)` predicate into a Set of IDs → `deductionCount` for denominator
    3. Classify refunds whose reference is in the eligible set → count them
    4. **Cross-window step:** For refunds whose reference is NOT in any eligible set (orphans), collect `reference` values, do second query: `.from("credit_transactions").select("id, amount, metadata, reference").in("id", orphanReferences)` — no time filter
    5. Classify referenced deductions from the second query with same predicate; if domain match, add deduction to eligible set and count the refund
    6. If `deductionCount === 0` → return 0
    7. Return `round(refundCount / deductionCount * 100)` or 0

    **D) Export new functions from index.ts**:
    Add to the existing re-export block: `getVsSuccessRate, getVsErrorRate, getVsAvgDuration, getVsCreditsConsumed, getVsRefundRate, getVsCreditsRefunded`

    **E) Persist duration_ms for VS in generate-without-logo/route.ts:**
    - Measure `const startTime = performance.now()` before VS generation begins
    - After generation completes (success or failure), pass `duration_ms: Math.round(performance.now() - startTime)` directly in the `insertGenerationEvent({...})` call
    - No separate update needed — insert once with duration_ms
    - This makes Tempo Médio VS useful going forward

    - Use exact PT-BR labels: Taxa de Sucesso VS, Taxa de Erro VS, Tempo Médio VS, Créditos Consumidos VS, Créditos Estornados VS, Taxa de Estorno VS

### /loja Step 1 — o que precisa mudar

**Hoje:**
- CNPJ/razao/nome aparecem no Step 1 apenas na criação (storeId=null) ou quando o form detecta `!hasExistingCnpj`
- Para loja com CNPJ existente mas razao/nome incompletos, os campos não são exibidos (a menos que o usuário explicitamente vá editar)
- `handleSaveAndContinue` sempre avança para Step 2 após salvar, sem considerar `returnTo`

**Precisa:**
1. CNPJ/razao/nome ficam SEMPRE visíveis no Step 1, independente do estado da loja
2. **Badge/readOnly "Dado oficial" APENAS quando** `cnpjLookupStatus === 'resolved'`, ou quando loja já tem `cnpj_official_data` preenchido (veio de consulta anterior). O simples fato de `razao_social`/`nome_fantasia` estarem preenchidos NÃO basta — pode ser dado manual do usuário.
3. Se loja tem CNPJ mas razao/nome incompletos → mostrar lookup button "Reconsultar CNPJ" que chama o reconsult-cnpj route (que deve persistir verification_data)
4. billing é pré-preenchido quando lookup resolved (já existe no create, precisa existir também no edit)
5. Após save bem-sucedido:
   - Sempre chamar check-readiness primeiro
   - Se brand_profile pendente → Step 2
   - Se cadastro_fiscal ainda pendente → fica no Step 1 (não avança)
   - Se tudo ok → redirect para `returnTo` (se existir) ou dashboard
   - Se erro (CNPJ duplicado, inválido) → fica no Step 1 com erro inline

### Navegação pós-save (handleSaveAndContinue)

Ordem CORRETA (sempre):
1. Save bem-sucedido
2. Chamar `POST /api/store/check-readiness`
3. Se ainda falta `brand_profile` → permanecer em /loja, abrir Step 2
4. Se ready → redirect para `returnTo` (se existir) ou `/dashboard`
5. Se erro (CNPJ duplicado, inválido) → fica no Step 1 com erro inline

**/loja?required=cadastro-fiscal bloqueia avanço:**
Enquanto `required=cadastro-fiscal` estiver presente na URL e o readiness check mostrar `cadastro_fiscal` pendente, o formulário NÃO deve:
- Avançar para Step 2 automaticamente
- Redirecionar para returnTo
- Permitir navegação para fora

O usuário só sai do Step 1 quando `cadastro_fiscal` passa no readiness (CNPJ + razao + nome ok). Isso é implementado via o loop: save → check-readiness → se cadastro_fiscal ainda pendente → fica no Step 1 com erro/mensagem.

Para simplificar, o `returnTo` é lido via `useSearchParams()` no componente.

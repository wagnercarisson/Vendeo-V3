## Diagnóstico (resultado da investigação)

### 1. Mapeamento do fluxo multi-imagem

| Etapa | Onde | O que chega |
|-------|------|-------------|
| Form | `campaign-input-form.tsx:372` | `fields.productImages[]` (CampaignProductFormImage) |
| Transporte | `schema.ts:43` (`ProductImageInputSchema`) | `productImages[]` (MAX_CAMPAIGN_IMAGES=4, teto agregado 8MB) |
| Brief | `brief.ts:170-182` | `media.images[]` com `role`/`source`/`mimeType`/`dataUrl` (dataUrl em memória) |
| Snapshot | `buildCampaignBriefSnapshot` | remove `dataUrl` (base64 nunca persiste — D6/D7) |
| Geração | `image-generation-service.ts:352` → `openai.ts:71-74` | provider recebe **todas** as imagens (`productImagesDataUrls`) |
| **Revisão** | `image-generation-service.ts:414` → `image-review-service.ts:54-78` | revisor recebe **apenas** gerada + `primaryImageDataUrl(brief)` |

### 2. O que o revisor recebe hoje

`ImageReviewService.review(generatedImageDataUrl, input, primaryImageDataUrl?)`:
- `callVisionModel(prompt, generated, primary)` envia gerada + **uma** referência (a primary).
- Imagens adicionais (`role: "reference"`) **não são enviadas** ao revisor.

### 3. Como o prompt descreve imagens hoje

- `campaign-image-reviewer.md:33` — `{{authorizedContextSection}}`, construída **só de texto** (`campaignDetails`/`additionalDetails`) em `buildAuthorizedContextSection`.
- Critério #5 (`invented_information`) referencia contexto autorizado **textual**; nada fala sobre imagens de referência.
- Linha fixa pós-prompt: "Compare o produto da arte com a imagem de referência" (singular).

### 4. Causa raiz

**Não é apenas prompt pouco claro — é falta real de envio das imagens adicionais ao revisor.** O provider usa todas as imagens na geração; o revisor só vê a primary e não tem como saber que o 2º produto veio de uma referência autorizada. Abordagem **C** (envio real das referências adicionais) **+** atualização do prompt.

---

## Decisão de abordagem

**Abordagem C + prompt:**
1. Passar **todas** as imagens de referência ao `ImageReviewService`/vision call (primeira posição = primary), reutilizando `mediaImagesDataUrls(brief)` já existente.
2. Nova seção textual `referenceImagesContextSection` no prompt do revisor explicando que imagens adicionais são referências **autorizadas** de apoio/variação (variações, combos, ângulos, itens de apoio), que produto/variação presente em qualquer referência não é invenção, **e** que a primeira imagem continua sendo a referência principal (hierarquia preservada — referência adicional não substitui o herói).
3. Manter proteção: produto ausente de **todas** as referências e dos dados continua `invented_information` crítico.
4. Linha de instrução dinâmica (singular 1 ref / plural 2+ refs / ausente sem refs).
5. Não alterar contratos públicos (rota/`GenerateImageRequest.productImages[]` inalterados); mudança restrita a API interna do serviço.

**Fora de escopo (confirmado):** Copy Director, validação de data/validity, input/form de upload (dado já chega ao pipeline), regras do Image Director (sem inconsistência — provider já recebe N imagens), critérios de preço/loja/nome/legibilidade, input-validation (primary-only é intencional — D8).

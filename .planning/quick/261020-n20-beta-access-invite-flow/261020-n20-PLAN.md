# Quick task 261020-n20 — Fechar o fluxo de convite do beta

## Goal

Completar o caminho **solicitação → aprovação → e-mail de convite → definição de senha → onboarding** sem abrir o cadastro público, sem conceder créditos antes do onboarding e sem alterar o Produto 1:1.

## Locked decisions (aprovadas pelo usuário em 2026-10-20)

1. **Migration**: `20261020000005_beta_access_invite.sql` — `20261020000001` já pertence à F50.2. Não renumerar/sobrescrever migrations publicadas.
2. **Convite pendente ≠ conta ativa**:
   - convite pendente (usuário criado pelo convite, ainda não confirmado nem autenticado) → link de continuação (`magiclink`) para concluir o acesso;
   - conta já ativa → **não** forçar troca de senha; enviar orientação para `/login` (status `account_active`);
   - jamais tratar qualquer erro do Supabase como “usuário já existe”.
3. **Proteção contra verificadores automáticos**: o link do e-mail abre `/convite` (GET não consome token). O consumo ocorre apenas no POST disparado pelo clique humano em `/auth/confirm`. E-mail sem pixel/rastreamento; rastreamento de clique do domínio deve permanecer desligado.
4. **Envio ≠ entrega**: persistir `invite_provider_message_id`; UI mostra “Enviado ao provedor”. Timeout/resultado ambíguo → `invite_status=unconfirmed`, nunca reenvio automático. Lease adquirido atomicamente.
5. **F50.2**: a primeira geração do convite cria `auth.users` e, portanto, deve ocorrer **depois** da ativação da oferta (`trial_offer_settings.launch_at`); reenvios não alteram `created_at`. Validar essa ordem no teste real. A escolha do mecanismo se justifica pelo controle de envio/reenvio do app.

## Mechanism

`supabaseAdmin.auth.admin.generateLink({ type: "invite" | "magiclink" })` → `properties.hashed_token` (single-use, nunca logado/persistido) → e-mail próprio via Resend → `SITE_URL/convite?token_hash=…&type=…` → POST `/auth/confirm` (`verifyOtp`) → cookies → `/update-password` → `/dashboard` → `PrivacyGate` → `/loja`.

## Tasks

1. Migration `20261020000005_beta_access_invite.sql`: colunas de convite em `access_requests`, CHECK de `invite_status`, extensão do CHECK de `admin_audit_log` com `access_request_invite`, REVERT comentado.
2. `src/lib/email/access-invite.ts`: preflight (`NEXT_PUBLIC_SITE_URL`, `VENDEO_EMAIL_ENABLED`, `RESEND_API_KEY`, `VENDEO_EMAIL_FROM`), template sem tracking, resultado discriminado `sent | failed | unconfirmed`.
3. `src/lib/access-requests/invite.ts`: lease atômico, resolução convite/magiclink/conta ativa, persistência de status e auditoria.
4. Rotas admin: aprovação dispara convite (sem desfazer aprovação); nova rota de reenvio.
5. `/auth/confirm`: POST consome token; GET de `invite|magiclink` redireciona para `/convite` sem consumir.
6. `/convite`: página “Aceitar convite” com POST; link inválido/expirado com orientação por e-mail de suporte.
7. `/login`: banner de erro `invite_failed` com `SUPPORT_EMAIL`.
8. `/update-password`: guarda de sessão, mínimo 8, sucesso → `/dashboard`.
9. Admin: coluna de status do convite + “Reenviar convite”.
10. Landing: confirmação explica resposta por e-mail.
11. Testes: rotas admin, convite, confirm, login, update-password e landing; `npm test`, typecheck, lint, build.

## Failure handling

| Falha | Resultado |
|---|---|
| Config de envio ausente | Aprovação mantida; `failed` com motivo; reenvio disponível |
| Erro do Supabase não relacionado a e-mail existente | `failed` genérico |
| Usuário existe e convite pendente | `magiclink` de continuação |
| Usuário existe e conta ativa | e-mail de orientação para `/login`; `account_active` |
| Resend 4xx | `failed` |
| Timeout/5xx/rede | `unconfirmed`; sem reenvio automático |
| Lease ocupado | 409; nenhum envio paralelo |
| Link expirado/já usado | `/login?error=invite_failed` com orientação |

## Out of scope

Cadastro público, créditos/F50.2, Produto 1:1, `.dev.log`, credenciais. Aplicar migration, ativar env de envio e deploy exigem autorização explícita.

# Quick 261020-n20 — Convite de acesso ao beta

## Resultado

O caminho **solicitação → aprovação → e-mail de convite → definição de senha → onboarding** está implementado, sem abrir o cadastro público.

Fluxo entregue:

1. Aprovação admin mantém o RPC atômico existente (`admin_review_access_request`: status + auditoria + limite F50.2).
2. Após aprovar, o servidor gera o link com `supabaseAdmin.auth.admin.generateLink({ type: "invite" })` e envia e-mail pelo Resend do app.
3. E-mail aponta para `/convite` (GET **não consome** o token).
4. Clique humano → POST `/auth/confirm` (`verifyOtp` invite/magiclink) → `/update-password` → `/dashboard` → `PrivacyGate` → `/loja`.
5. Reenvio pelo admin sem reaprovar; status próprio e auditado.

## Decisões aplicadas (revisão do usuário)

1. **Migration `20261020000005_beta_access_invite.sql`** — próxima versão livre; `20261020000001` (F50.2) preservada.
2. **Convite pendente ≠ conta ativa** — `invite-policy.ts` classifica somente `invited_at` + sem confirmação/login como pendente; conta ativa recebe orientação para `/login`, sem reset de senha. Somente `already registered`/`email_exists` aciona a busca de usuário existente; outros erros são falha genérica.
3. **Link protegido contra verificadores** — `/convite` não consome no GET; consumo apenas no POST do clique. E-mail sem pixel/parâmetros de rastreamento; rastreamento de clique do domínio deve permanecer desligado (runbook).
4. **Enviado ao provedor ≠ entregue** — `invite_provider_message_id` persistido; UI “Enviado ao provedor”. Lease atômico via UPDATE condicional (2 min). Timeout/5xx/rede = `unconfirmed`, sem reenvio automático.
5. **F50.2** — documentado que o primeiro `generateLink` cria `auth.users`; deve ocorrer **depois** de `trial_offer_settings.launch_at`. Reenvio não altera `created_at`.

## Riscos e observações

- Entrega de e-mail depende de `NEXT_PUBLIC_SITE_URL`, `VENDEO_EMAIL_ENABLED=true`, `RESEND_API_KEY`, `VENDEO_EMAIL_FROM` e domínio verificado. Sem isso, aprovação permanece válida e o admin vê `failed` + reenvio.
- O convite expira conforme a configuração de tokens do Supabase; link expirado orienta o lojista a pedir novo convite ao suporte.
- Conta já ativa não é forçada a trocar senha.
- Nenhum crédito é concedido; sistema de créditos, F50.2 e Produto 1:1 intocados. `.dev.log` permanece fora do commit.

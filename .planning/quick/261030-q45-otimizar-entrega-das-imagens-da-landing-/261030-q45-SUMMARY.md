# Quick 261030-q45 — Landing image delivery Summary

Responsive webp variants (320/480/640/768) plus the existing 1024w original are now delivered through `srcset`/`sizes` for all nine square campaign images, with `fetchPriority="high"` on the hero only. The approved visual (fixed 1:1 `object-contain` box, plain `<img>`, copy/layout) is unchanged.

## Delivered

- **Generator** `scripts/generate-landing-image-variants.mjs`: Sharp-only (no new deps), closed allowlist of the nine campaign basenames, deterministic `quality 82 / effort 6 / smartSubsample`, metadata stripped, `withoutEnlargement` + explicit skip, square-original guard, `--check` and `--force`, idempotent output (two `--force` runs produced byte-identical files).
- **36 variants** in `public/landing/variants/` (`{name}-{320,480,640,768}w.webp`). Originals untouched (`git diff --name-only -- public/landing/*.webp` empty).
- **`landing-image-srcset.ts`**: `LANDING_IMAGE_WIDTHS = [320,480,640,768,1024]` and `buildLandingSrcSet` (rejects anything outside `/landing/*.webp`).
- **`CampaignImage`**: optional `srcSet`, `sizes`, `fetchPriority` forwarded to the plain `<img>`; fixed `aspect-square`/`object-contain`/skeleton behavior preserved.
- **Per-section `sizes`** matching the measured widths (hero 468px, transformação 452px, identidade 476px, tiles 315px / mobile 78%), `loading="eager"` and `fetchPriority="high"` only on the hero; all other campaign images stay lazy.
- **Ration thumbnail (320×293 at 112px) and logo (384×82)**: no variants, no `srcset`, no resize.

## Serving sanity (production build, `next start`)

- `img[srcset]` = **9**, `img[fetchPriority]` = **1**, `img[loading="eager"]` = **1**, `img[loading="lazy"]` = **10** (9 campaigns + ration).
- React 19 streamed markup uses camelCase `srcSet`/`fetchPriority` on `<img>` (HTML attribute names are case-insensitive) and automatically emits a single hero preload link with `imageSrcSet`/`imageSizes`/`fetchPriority="high"`.

### Flag-off visual limitation

The current production build is prerendered with `VENDEO_PUBLIC_SIGNUP_ENABLED=true` from `.env.local`; runtime env overrides do not change the frozen HTML. Flag-off screenshots would require a second build with the flag frozen to `false`, which is outside this task's scope and would disturb the measured build. Flag-off is covered by the automated both-modes suite; the image delivery markup is flag-independent. This is recorded for the human reviewer.

Flag-on was smoke-checked automatically: temporary `PORT=3100 VENDEO_PUBLIC_SIGNUP_ENABLED=true npm start` returned HTTP 200 with `data-public-signup-enabled="true"` (5 markers) and no `#acesso` form; the temporary process and env vars were cleared.

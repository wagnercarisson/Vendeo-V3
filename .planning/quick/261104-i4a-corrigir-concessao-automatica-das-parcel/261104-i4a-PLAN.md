# Quick 261104-i4a — Concessão automática das parcelas do teste gratuito (F50.2)

## Escopo

Corrigir o caminho que impede o cron diário `/api/cron/demo-credits` de conceder
as parcelas 1/2/3 do teste gratuito de 28 dias, e provar o comportamento com
testes que exercitam o **middleware real** e o RPC real em banco descartável.

Esta quick é **local-only**. Ela não aplica migration, não altera banco
compartilhado/produção, não faz reset, push, deploy, nem executa cron de
produção. A ativação em produção é um passo separado, com autorização própria.

## Diagnóstico confirmado (não re-litigar)

1. `/api/cron/demo-credits` está agendado no `vercel.json` (diário 07:00), mas não
   está em `API_PASSTHROUGH` no `src/middleware.ts`. O scheduler não tem sessão,
   `updateSession` devolve `claims: null`, e o middleware responde 401 antes de a
   rota validar `CRON_SECRET`.
2. A rota valida `Authorization: Bearer CRON_SECRET`, mas responde HTTP 200 mesmo
   quando o RPC `process_trial_offer_installments` falha (`trialOffer.error`) e
   mesmo quando o RPC reporta `errors > 0`. Também vaza
   `balanceError.message` (detalhe interno do banco).
3. O teste atual da rota só inspeciona o texto-fonte; não usa o middleware real.
   O padrão estabelecido é `src/app/api/cron/sync-openai-pricing/__tests__/route.test.ts`.
4. Nenhum teste chama `process_trial_offer_installments`; não há cobertura para
   recuperação de parcelas atrasadas nem para idempotência de execuções repetidas.

## Regras preservadas (não alterar)

- 5 créditos nos dias 0/7/14/21, máximo 20, um único `expires_at` de 28 dias
  compartilhado, independente de login/consumo/saldo restante.
- Elegibilidade, coortes, histórico, locks e idempotência existentes.
- Nenhuma mudança de data, nenhuma concessão manual.
- `CRON_SECRET` continua obrigatório no handler; o passthrough só libera a sessão.

## Caso de referência (evidência de produto, não teste)

Usuário `f52de76e-30df-4da0-9aab-da12985b21a2` / "Farmácia do Povo":
enrollment iniciado em 2026-10-20 18:50, expira em 2026-11-17 18:50. Em
2026-11-04 o extrato mostrava apenas os 5 iniciais. Uma execução em 2026-11-04
deve conceder seq 1 (devido 27/10) e seq 2 (devido 03/11) — 15 acumulados; seq 3
(10/11) ainda não. **Nada deve ser concedido manualmente.**

O teste de integração usa um relógio controlado em ~dia 21 para cobrir seq 1/2/3
na mesma execução, conforme o escopo aprovado.

## Tasks

### Task 1: Liberar o cron no middleware e corrigir os status da rota

**Files:** `src/middleware.ts`, `src/app/api/cron/demo-credits/route.ts`

**Action:**

1. Em `src/middleware.ts`, adicionar exatamente `"/api/cron/demo-credits"` ao
   `API_PASSTHROUGH`, junto das outras rotas de cron, com o mesmo comentário
   usado nas vizinhas ("A rota valida CRON_SECRET; agendamentos não possuem
   sessão de usuário"). Não usar prefixo/glob, não alterar `matcher`, não
   remover a validação de `CRON_SECRET` da rota.
2. Em `route.ts`:
   - Trocar o vazamento `balanceError.message` por
     `{ ok: false, error: "balance_query_failed" }` com status 500.
   - Normalizar a ausência de `CRON_SECRET` para
     `{ ok: false, error: "cron_secret_not_configured" }` com status 500,
     alinhado ao padrão da rota irmã `sync-openai-pricing`.
   - Manter a reconciliação atual (materialização de expiração, notificações,
     eventos, dreno de e-mail) na mesma ordem e com o mesmo comportamento.
   - Após a reconciliação, calcular
     `processingFailed = Boolean(trialOfferError)` e
     `processingErrors = Number(trialOfferData?.errors ?? 0) > 0`.
   - Se qualquer um for verdadeiro, responder status 500 com `ok: false` e:
     - `error: "trial_offer_processing_failed"` quando o RPC falhou;
     - `error: "trial_offer_processing_errors"` quando o RPC reportou `errors > 0`;
     - agregados seguros `materialized`, `repaired`, `emails` e
       `trialOffer: { granted, skipped, errors }` (somente números, nunca
       mensagem de banco/stack).
   - Sucesso continua 200 com `{ ok: true, materialized, repaired, emails,
     trialOffer }`, normalizando `trialOfferData` ausente para
     `{ granted: 0, skipped: 0, errors: 0 }`.

**Verify:**

```bash
npx vitest run src/app/api/cron/demo-credits/__tests__/route.test.ts src/app/api/cron/sync-openai-pricing/__tests__/route.test.ts src/__tests__/middleware/redirect.test.ts
npm run typecheck
```

**Done:**

- `"/api/cron/demo-credits"` presente no `API_PASSTHROUGH` (caminho exato).
- RPC com erro e RPC com `errors > 0` retornam status não-2xx e código estável.
- Nenhuma resposta contém mensagem interna de banco.
- Contrato antigo (Bearer, materialização, dedup, agendamento) continua verde.

### Task 2: Testes comportamentais da rota com middleware real

**Files:** `src/app/api/cron/demo-credits/__tests__/route.test.ts`

**Action:**

Substituir o teste baseado em texto-fonte por testes comportamentais, seguindo o
padrão de `src/app/api/cron/sync-openai-pricing/__tests__/route.test.ts`:

- `vi.hoisted` para `mockUpdateSession`, `mockRpc`, `mockFrom` e mocks de
  `@/lib/notifications/outbox`, `@/lib/email/resend` e
  `@/lib/product-events/service`.
- `vi.mock("@/lib/supabase/middleware")` e
  `vi.mock("@/lib/supabase/server", () => ({ supabaseAdmin: { rpc: mockRpc, from: mockFrom } }))`.
- Importar `GET` da rota e `middleware` **real** de `@/middleware` depois dos
  mocks. **Não copiar/reimplementar o middleware** (o teste em
  `src/__tests__/auth/middleware.test.ts` copia — não seguir esse padrão).
- Helper de cadeia para `credit_balances` (`select().gt()`) e
  `credit_transactions` (`select().in().order().limit()`), com dados vazios por
  padrão; `claimEmailNotification` resolve `null`.
- Casos obrigatórios:
  1. Scheduler sem sessão (`claims: null`) e bearer válido: `middleware(req)`
     devolve `x-middleware-next: "1"` e `GET(req)` executa o RPC e responde 200.
  2. Bearer ausente e bearer inválido (`it.each`): middleware ainda alcança o
     handler (`x-middleware-next: "1"`), `GET` responde 401 e o RPC **não** é
     chamado.
  3. `CRON_SECRET` ausente: 500 com `cron_secret_not_configured`.
  4. RPC retorna `error`: status 500, `ok: false`,
     `error: "trial_offer_processing_failed"`, sem mensagem interna no corpo.
  5. RPC retorna `errors > 0`: status 500, `ok: false`,
     `error: "trial_offer_processing_errors"`, com agregados numéricos.
  6. Sucesso: 200, `ok: true`, `trialOffer` repassado.
  7. Exceção exata: `/api/cron/demo-credits/other` continua 401 no middleware e
     o handler não é chamado.
- Manter a asserção de `vercel.json` (`demo-credits`, `0 7 * * *`) e que os
  demais crons permanecem agendados.

**Verify:**

```bash
npx vitest run src/app/api/cron/demo-credits/__tests__/route.test.ts
npm run typecheck
```

**Done:**

- Todos os casos acima verdes usando o `middleware` real importado.
- Nenhuma cópia do middleware no arquivo de teste.
- Falha de RPC e `errors > 0` provadas como não-sucesso.

### API do ESLint usada (Node 24, ESM)

- `import { ESLint } from "eslint";`
- Instância estrita: `new ESLint({ overrideConfigFile, allowInlineConfig: false })` — honra os `ignores` do config (usar para `isPathIgnored`/`calculateConfigForFile` de arquivos reais).
- Instância de fixtures: `new ESLint({ overrideConfigFile, allowInlineConfig: false, ignore: false })` — `lintText(code, { filePath })` analisa caminhos ignorados pelo config. Nunca usar `ignore:false` para concluir que um arquivo real "não é ignorado".
- `await eslint.isPathIgnored(relPath)`; `await eslint.calculateConfigForFile(relPath)` → objeto com `parser` e `rules`.
- `const [res] = await eslint.lintText(code, { filePath: relPath });` → `res.messages[]` (`ruleId`, `severity`, `line`, `message`) e `res.fatalErrorCount`.

### CLI para a prova de paridade

```js
spawnSync(process.execPath, [
  "node_modules/eslint/bin/eslint.js",
  "--config", "eslint.diagnostic.config.mjs",
  "--no-inline-config",
  "--no-ignore",
  "--format", "json",
  <caminho absoluto de um fixture>,
], { cwd: repoRoot, encoding: "utf8" });
```

`--no-ignore` é obrigatório para alcançar os fixtures (o diretório está nos ignores do config). Verificado: sem `--no-ignore`, o CLI devolve `ruleId: null` com "File ignored because of a matching ignore pattern".

**Exit code esperado:** o CLI do ESLint devolve `1` quando há achados — isso é resultado normal do diagnóstico, NÃO falha do teste.

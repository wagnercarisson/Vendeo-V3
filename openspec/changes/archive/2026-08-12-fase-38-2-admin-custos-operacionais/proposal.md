## Why

A F38 entregou "quanto o usuário paga/debita" (`credit_operation_costs`, em créditos) e a F38.1 entregou "quanto a entrega custou para o Vendeo" (`generation_events` call-level, em USD estimado) — mas **sem UI** (decisão D8/D10 da F38.1: "medir primeiro, exibir depois"). O `GET /api/admin/ai-costs` existe e é testado, porém **ninguém consome**; o RPC `admin_get_ai_costs` é bom para agregado mas insuficiente para UI real (não traz `created_at`, `delivery_status`, provider/model principal, distribuição de `cost_source` nem detalhe call-level por run); os badges de confiança (`cost_formula_version`/`cost_estimation_note`/`text_component_usd`/`image_tool_component_usd`) são computados e **descartados** no `AiCostTracker.record`; os parâmetros econômicos (taxa USD→BRL e valor do crédito) existem **só como env** (`VENDEO_USD_BRL_RATE`, `VENDEO_AI_CREDIT_UNIT_USD_VALUE`), sem configuaração por admin; e o card "Custo Médio" do `/admin/metrics` quebrou por consequência da nova contabilidade (delivery marker `campaign_pipeline` com custo NULL desde a F38.1 → `getAvgCost` agora sempre NULL). A F38.2 é o "exibir depois": a camada de admin/observabilidade que transforma a apuração em decisão econômica para **precificar o beta** antes do Stripe (F39).

## What Changes

- **Parâmetros Econômicos configuráveis por admin** — dois parâmetros **separados** (D1): `usd_brl_rate` (converte o custo estimado do provider) e `credit_value_brl` (estima a receita operacional interna), defaults/fallback **1.00** (conservador), administráveis sem deploy com motivo obrigatório e auditoria; **nenhum altera ledger de créditos nem transações históricas** (D1/D2)
- **Página `/admin/operation-costs` mantém a rota, título visual vira "Configurações Econômicas"** — não quebra bookmarks/testes/links; conteúdo ganha a seção de Parâmetros Econômicos além da tabela de créditos por entrega existente (D2)
- **Página nova `/admin/ai-operation-costs`** ("Custos de Operação") com filtros (período, loja, tipo de entrega, status, provider/model, `generation_type`, `operation_run_id`, **segmento econômico**), KPIs (custo USD/BRL, créditos, receita/resultado/margem BRL, tempo médio/P95, total de entregas, erros/sucessos), tabela por entrega com badges de confiança e **drilldown call-level por `operation_run_id`** (D3/D4)
- **Badges de confiança do custo** — `estimated` / `partial` / `provider_reported` / `provisional image tool estimate` / `not_available`, derivados de `cost_source` + `cost_estimation_note` persistidos; a UI **nunca apresenta estimativa como "verdade financeira"** (D5)
- **Migration pequena em `generation_events`** — `cost_formula_version`, `cost_estimation_note`, `text_component_usd`, `image_tool_component_usd`; `AiCostTracker.record` passa a persistir **daqui para frente** (sem reclassificar histórico) (D5)
- **Endpoints novos** `GET /api/admin/ai-operation-runs` e `GET /api/admin/ai-operation-runs/[operationRunId]` (+ RPCs `admin_get_ai_operation_runs` / `admin_get_ai_operation_run_events`, `SECURITY DEFINER`, sem leitura direta das views) — paginação obrigatória, P95 via `percentile_cont`, `estimated_cost_brl`/receita/margem derivados **no service layer** em BRL (D1/D4)
- **Segmentação econômica da entrega (D9)** — classificação **best-effort** no service: `test` (`is_test_store`), `freemium/promotional` (`metadata->>'bonus_amount'`), `paid` (`metadata->>'purchased_amount'`), `manual/admin` (`admin_grant`), `unknown` (fallback); filtro "Segmento econômico" + agregados por segmento (custo, resultado operacional estimado, margem estimada %, taxa de erro); **sem alterar ledger** nem criar `operation_runs`
- **Correção obrigatória do `/admin/metrics` (D6)** — `getAvgCost` deixa de ler `campaign_pipeline.estimated_cost_usd` (NULL por desenho) e passa a apurar **custo médio de IA por entrega** via apuração call-level; card renomeado para "**Custo Médio IA**"; USD→BRL passa a usar `economic_parameters.usd_brl_rate` (fonte única, D2); `admin_get_metrics` (F28) **inalterado**
- **UI preparada para F38.3** — exibe "Custo estimado Vendeo" / "Custo reconciliado provider: ainda indisponível" / "Diferença: pendente" sem quebrar a arquitetura quando a reconciliação OpenAI entrar (D7)
- `npx vitest run`, `npm run typecheck`, `npm run lint`, `npm run build` — zero erros

**Entrega verificável:** migrations `economic_parameters` + audit + RPC `admin_set_economic_parameter` (padrão F38) + `EconomicParameterService` (fail-open/fail-closed) + `GET/PUT /api/admin/economic-parameters`; página `/admin/operation-costs` renomeada visualmente com seção de parâmetros; página `/admin/ai-operation-costs` com filtros/KPIs/tabela/drilldown; migration de confiança + tracker persistindo; endpoints/RPCs de operation runs; segmentação econômica D9; correção do `/admin/metrics`; ~40+ testes novos + verificação SQL/integrada I1–I6 + regressão completa.

## Capabilities

### New Capabilities

- `economic-parameters`: Tabela `economic_parameters` (1 linha por chave) + `economic_parameter_audit` (append-only, idempotência por `operation_id`) + seeds idempotentes (1.00/1.00) + RPC `admin_set_economic_parameter` (SECURITY DEFINER, transacional, motivo obrigatório) + `EconomicParameterService` (server-only, fail-open para linha inexistente / fail-closed para erro real de leitura) + `GET`/`PUT /api/admin/economic-parameters` (requireAdmin + zod). **Sem endpoint público.** (D1/D2)
- `ai-operation-runs-api`: Endpoints `GET /api/admin/ai-operation-runs` (lista por entrega com filtros + paginação + P95) e `GET /api/admin/ai-operation-runs/[operationRunId]` (detalhe call-level) servidos por RPCs `admin_get_ai_operation_runs` / `admin_get_ai_operation_run_events` (SECURITY DEFINER); derivação de `estimated_cost_brl`, receita/resultado/margem BRL e badges no service layer (D1/D4/D5)
- `ai-operation-costs`: Página admin `/admin/ai-operation-costs` ("Custos de Operação") com filtros, KPIs, tabela por entrega com badges de confiança e drilldown call-level por etapa; `force-dynamic` + `requireAdmin` + service layer; estado 503 fail-closed; segmentação econômica D9 com agregados por segmento (D3/D9)

### Modified Capabilities

- `ai-cost-tracker`: `AiCostTracker.record` passa a persistir `cost_formula_version`, `cost_estimation_note`, `text_component_usd`, `image_tool_component_usd` a partir do `CostResolution` — daqui para frente, sem reclassificar histórico (D5)
- `ai-cost-accounting`: `admin_get_ai_costs` (F38.1) permanece **inalterado e compatível** para agregado; os RPCs novos `admin_get_ai_operation_runs`/`admin_get_ai_operation_run_events` são especificados na capability nova `ai-operation-runs-api` (D4)
- `admin-operation-costs`: Página `/admin/operation-costs` muda o **título visual** para "Configurações Econômicas" (rota mantida) e ganha a seção de Parâmetros Econômicos (`ParamsForm`) com `usd_brl_rate`/`credit_value_brl`, motivo obrigatório e badge de `source` (tabela/fallback) (D2)
- `pipeline-metrics`: `getAvgCost` deixa de ler o delivery marker `campaign_pipeline.estimated_cost_usd` (NULL desde F38.1) e passa a apurar custo médio de IA **por entrega** a partir da apuração call-level (D6)
- `admin-metrics-dashboard`: Card "Custo Médio" renomeado para "**Custo Médio IA**"; conversão USD→BRL passa a usar `economic_parameters.usd_brl_rate` (fonte única D2), não o env `VENDEO_USD_BRL_RATE` (default 5.50)
